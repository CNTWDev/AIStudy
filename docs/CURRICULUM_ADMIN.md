# 教材与知识点管理

管理员登录后进入 **管理 → 教材与知识点**（`/admin/curricula`）。原有后台只展示教材库存；现在可以维护教材与知识点，保存草稿、校验和发布。

## 内容之间的关系

- **教材版本**：出版社、适用地区、学制、覆盖范围、核实来源与状态。没有知识点的版本也可先登记库存。
- **教材包**：学习端可选的课程，包含学科、课程体系、学段、板块和知识点。
- **册次 → 单元 → 知识点**：决定学校进度中显示的章节。一个知识点可以在多个册次出现；每个册次内只映射到一个单元。未映射部分继续显示原课程分组，不会隐藏。
- **知识点**：教材中的具体教学内容，包括说明、方法、诊断思路、术语与前置关系。知识点页面可以查看后续知识、共通知识及最近 30 道关联题目。
- **共通知识**：不同教材中底层等价的知识。合并前应核对范围与难度，不能仅凭名称相同或前置关系认定等价。移动映射后，学习状态按保留的作答事件重新计算。

目前管理现有学科与学段；新增学科、学制、学校默认选课模板或新的学段定义仍需修改仓库元数据。教材目录录入和题目核对是两项工作，创建知识点不会自动生成已核实题目。

## 日常操作

1. 在版本核实库存中登记版本、来源和覆盖边界。`pending` 表示待核实，不关联已上线教材包；`partial` / `verified` 必须提供来源。
2. 新增教材，设置学科、体系和覆盖学段。系统会创建基础板块及一条部分核实的版本记录，可继续编辑出版社等资料。
3. 从教材目录进入「新增知识点」，填写内容与前置知识点 ID。先创建被依赖的知识点，再引用它；必须前置不能成环或指向更晚学段。
4. 新增册次，在知识点编辑页选择同教材、同学段的册次，填写单元 ID、名称和顺序。相同单元使用同一个 ID；保存会替换该知识点在此册次的映射。
5. 根据需要建立共通知识映射。一个教材知识点只属于一个共通知识组；移入新组会自动从原组移出。
6. 用搜索、学段、册次和题目缺口筛选检查内容。题目编辑与上下架仍在「题库 / 卷库」操作。
7. 到「发布与历史」填写发布说明，点击「检查并发布草稿」。保存草稿不会改变孩子正在使用的课程。

所有管理员共用一份草稿。页面带修订号，其他管理员先保存时，旧页面会返回冲突而不会覆盖；刷新后重新编辑即可。

已有教材和知识点 ID 用于关联学习记录，编辑时保留。已有知识点不能移动到其他教材，导入也不允许删除原有知识点；创建新版本时使用新的教材 ID。第一版不提供硬删除操作。

## 发布、恢复与导入导出

每次发布新增一条不可变的数据库修订，记录发布人、说明与时间。Web 在后续请求中检查发布号（每个进程最多每秒查询一次）；worker 每个维护循环检查（空闲时约 30 秒，正在执行的维护任务结束后加载）。无需重启服务。

发布知识说明变化后，旧的 AI 讲解和知识背景缓存会停用，后续按新内容生成；题目、作答事件、错题及复习记录保留。共通知识映射变化由既有事件投影机制处理。

「恢复到草稿」不会立即改变线上内容，需要核对后再次发布。恢复较早版本时，保留后来上线的知识点 ID 和必要的教材、板块、学段，避免学习记录失去对应内容；这是一份可继续编辑的恢复草稿，不是删除新增知识点的精确回滚。「放弃草稿修改」则用当前线上内容覆盖草稿。

可导出完整草稿、完整已发布内容或单个教材 JSON。当前批量导入接受单教材格式（`pack`、`strands`、`kps`），上限 2 MB；完整导出还包括版本、册次和共通知识，供备份检查与程序化迁移使用，不能直接作为单教材导入文件。导出不包含学生数据。

## 存储、升级与运维

仓库 `curricula/` 是基础数据；后台编辑是数据库覆盖层（`curriculum_workspace` 与 `curriculum_revisions`）。后台发布不会写 Git 文件或自动推送 GitHub。数据库备份包含草稿和全部发布历史，换服务器时应恢复数据库，而不只是复制代码。

未编辑的教材继续接收仓库更新。编辑某个教材包后，覆盖层保存该包的完整内容；后续仓库对同一教材包的修改不会自动混入。升级有此类数据变更时，应对照新基础数据与后台导出，在草稿中合并并校验。版本、册次、概念按各自 ID 覆盖；册次映射按知识点覆盖。

安装和升级沿用 `install.sh`，自动执行 `0030_curriculum_admin.sql`，并启动 / 重启 Web 与 worker，无需增加服务。

```bash
sudo /opt/aistudy/install.sh upgrade
# 若服务器上的旧脚本尚未包含 worker 支持，直接使用 GitHub 最新脚本：
curl -fsSL https://raw.githubusercontent.com/CNTWDev/AIStudy/main/install.sh | sudo bash -s -- upgrade
```

检查仓库基础数据与线上有效数据分别使用：

```bash
python -m app.cli check-curricula
python -m app.cli curricula-report --published
```

`--published` 使用配置中的实际数据库；排查线上问题应以服务用户和线上配置运行。教材导入或发布若出现引用错误，会拒绝整个操作，保留原草稿与线上版本。
