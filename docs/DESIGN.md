# AIStudy 设计文档

## 1. 目标

一套能陪孩子从小学一直学到高中的网页系统：

- **同一套系统，不同教材**：教材是可插拔的数据，不写死在代码里。
- **向后补、向前学**：知识点之间有前置关系，诊断时沿前置往回追找断点，学会后沿后续往前预习。
- **门槛低**：每件事都拆成小步骤；先做最简单的一步；卡住了有提示、有「退一步」。
- **完整记录**：每道题、每次复习、每个查过的词、每天的反思都留下来，家长随时能看。
- **简单稳定**：一个 Python 应用 + 一个 PostgreSQL 数据库，一台 1 核 1G 的云服务器就能跑；一键安装/升级；AI 只在服务器端调用。

## 2. 架构

```
浏览器（孩子 / 家长，手机优先）
   │  服务端渲染页面 + 少量原生 JS 调 /api/*
   ▼
FastAPI 应用（app/main.py）
   ├─ catalog.py   教材目录：加载 curricula/*.json，提供知识图谱查询（前置、后续、祖先）
   ├─ engine.py    学习引擎：掌握度、诊断回溯、每日计划、间隔复习、错题本、统计
   ├─ llm/         AI 抽象层（见第 6 节）
   │   ├─ base.py       Provider 接口、ChatRequest、LLMError
   │   ├─ providers.py  anthropic（Claude）/ openai_compat（DeepSeek、通义…）/ mock
   │   ├─ settings.py   读取 config/llm.toml
   │   ├─ service.py    选提供方、缓存、每日限额、解析 JSON
   │   └─ tasks.py      具体任务的提示词：查词、讲解、出题、造句点评、写短文
   ├─ auth.py      账号系统（见第 3 节）
   ├─ db.py        数据库访问：PostgreSQL（生产）/ SQLite（本地试用、测试），统一 ? 占位符
   ├─ migrate.py   数据库迁移：按编号执行 migrations/*.sql，记录在 schema_migrations
   └─ cli.py       命令行：migrate / check / backup / create-admin / reset-password / invite …
数据：curricula/（教材知识图谱） seed/（人工核对过的题库、术语卡） PostgreSQL（全部账号和学习记录）
配置：.env（服务器、数据库、账号策略） config/llm.toml（AI 提供方、模型、密钥、按任务路由）
运维：install.sh（一键安装/升级：环境检测 → 装依赖 → 拉代码 → 建库 → 备份 → 迁移 → systemd → Caddy HTTPS → 健康检查）
```

为什么这样选：

- **服务端渲染 + 原生 JS**：没有前端构建步骤，部署就是复制文件；手机浏览器打开即可用。
- **PostgreSQL**：单机就能装，稳定、并发好，多个家庭一起用也没问题；`pg_dump` 备份。本地试用和自动测试仍可用 SQLite（改 `DATABASE_URL` 即可），两种数据库跑同一套测试。
- **迁移脚本**：表结构只通过 `migrations/NNNN_xxx.sql` 改动，升级时自动执行，已执行的不会重复。新增字段就加一个编号更大的文件，不改旧文件。
- **AI 在服务器端**：密钥不会出现在孩子的浏览器里；所有调用有缓存和每日上限。

## 3. 账号

- **角色**：家长（parent）和孩子（kid，属于某个家长）。家长里 `is_admin=1` 的是管理员；系统里第一个注册的账号自动成为管理员。
- **家长注册**由 `.env` 的 `REGISTRATION` 决定：`approval`（默认：有邀请码直接开通，没有的提交申请等管理员审批）/ `invite`（必须邀请码）/ `closed`（只能管理员创建）/ `open`。管理员和家长都能生成邀请码，`users.invited_by` 记录邀请关系。
- **孩子账号**由家长在网页上创建：名字、登录邮箱、密码、年级、每天学习分钟数、学校，以及要学的教材包和当前学段；家长可以改孩子密码、暂停孩子账号。
- **密码**：PBKDF2-SHA256，20 万次迭代，每个密码独立随机盐。
- **会话**：登录后生成随机令牌，cookie 里放令牌（已签名），数据库 `sessions` 表只存它的 sha256。退出、改密码（其他设备自动下线）、停用账号、在「我的账号」里踢掉某个设备，都立即生效。
- **防暴力破解**：同一账号连续输错 `LOGIN_MAX_FAILS` 次锁定 `LOGIN_LOCK_MINUTES` 分钟；`python -m app.cli unlock 邮箱` 可手动解锁。
- **忘记密码**：孩子找家长改；家长找管理员在「管理」页生成一次性重设链接（48 小时有效）；管理员自己用命令行 `reset-password`。暂不发邮件（`password_resets` 表已为以后接入邮件预留）。
- **安全日志**：登录成功/失败、锁定、改密码、停用、生成重设链接等都记在 `auth_events`，管理页可看最近 100 条。
- 孩子只能看到自己的数据；家长能看自己孩子的总览和报告，也可以「以孩子视角打开」陪着做。

## 4. 教材数据模型（可插拔）

每个文件 `curricula/<pack_id>.json` 是一个**教材包** = 一个学科的一个版本：

```json
{
  "pack": {"id": "eng-shanghai", "subject": "english", "subject_name": "英语",
           "edition": "上海牛津版（小学·初中）+ 上海高中英语新教材", "region": "上海公办",
           "stages": ["G1", "...", "G12"], "version": 1, "sources": ["..."], "notes": "..."},
  "strands": [{"id": "GRA", "name": "语法"}],
  "kps": [{
    "id": "ESH-GRA-07", "strand": "GRA", "stage": "G3", "term": "上", "unit": "3A Module 2",
    "name": "一般现在时（第三人称单数）", "name_en": "Present simple (3rd person)",
    "desc": "掌握是什么样子", "prereqs": [{"id": "ESH-GRA-03", "strength": "必须"}],
    "hot": true, "method": "低门槛学习方法 + 常见错误", "probe": "诊断题思路", "terms": ["..."]
  }]
}
```

要点：

- **知识点 id 全局唯一**，前置关系可以跨包（例如上海物理引用数学基础知识点）。
- **stage** 用统一学段：`G1`–`G12`，另有 `IGCSE`、`A-Level`，内部按顺序比较（IGCSE≈9.5）。孩子每个教材包有自己的「当前进度学段」，不一定等于年级（国际学校初二就在学 IGCSE 物理）。
- **prereqs 强度**：「必须」用于诊断回溯和补漏；「有帮助」只做展示。
- **加新教材**：往 `curricula/` 放一个新 JSON 文件，重启即可在「编辑孩子」里勾选。例如人教版数学、新概念英语、AP 物理都按这个格式写。
- 题库 `seed/items_*.json`、术语卡 `seed/vocab_*.json` 按知识点 id 挂靠，人工核对过的题优先使用；没有题的知识点由 AI 现场出题并存入题库复用。

当前内置 6 个包，共 741 个知识点（统编语文 168、上海英语 134、沪教数学 150、上海物理 121、Cambridge 英语 75、Cambridge 物理 93）。这些知识图谱依据课程标准、考纲和教材目录整理，**没有复制教材原文**；各版教材可能修订，发现与孩子课本不一致时直接改 JSON 即可。

## 5. 学习引擎

### 5.1 掌握度

每个孩子 × 每个知识点一条记录：分数 0–1、做题数、正确数、状态（未测 / 薄弱 / 学习中 / 已掌握）。

- 练习答对：`score += (1-score)×0.35`；答错：`score -= score×0.45`。
- 分数 ≥0.8 且至少答对 2 次 → 已掌握；<0.4 → 薄弱；之间 → 学习中。
- 诊断题答对直接记为已掌握（0.8）；复习卡片的结果以一半权重计入。

### 5.2 诊断（向后回溯）

1. 取当前学段和上一学段的知识点，每个板块至少挑一个，优先高频点和有现成题的点，共约 8 个起点。
2. 每个点出 1 道题（有现成题用现成题，否则 AI 出题；AI 不可用时让孩子自评「会 / 不太会」）。
3. **做错 → 把它的「必须」前置插到队首继续测，最多追 3 层**；最多 18 题。
4. 报告里区分「断点」（做错、但前置都没问题的点——最该先补）和「需要加强」；答对的点，其前置推断为大概率已掌握。

### 5.3 每日任务清单

每天第一次打开时生成（可点「重新安排」；已经做完的任务即使新计划里没有了也保留打勾）。分两部分：

**固定项**（每天都有，不截断——坚持比做对更重要）

| 顺序 | 任务 | 来源 |
|---|---|---|
| 0 | 更新学校进度 | 有学科超过 14 天没更新进度时出现 |
| 1 | 单词 | 到期的生词/短语/术语卡片，含当天按词表加入的新词（`tracks.kind=words`） |
| 2 | 错题回顾 | 到期的错题卡片，最多 8 道 |
| 3 | 英语阅读 | 家长安排的英文读物（`read_en` track，今天读哪一段），否则 AI 短文 15 分钟 |
| 4 | 名著接着读 | 家长安排的中文书（`read_zh` track，按回目/章节接着读），否则中文阅读 15 分钟 |

**学习项**（按每天可用分钟截断，至少保留一项）

| 类型 | 来源 |
|---|---|
| 跟上学校 `sync` | 孩子/家长设置的「正在学」知识点，还没掌握就练（每天最多 2 个） |
| 试卷订正 `paper` | 导入了还没订正完的试卷 |
| 诊断 `diagnose` | 还没诊断过的学科，一次一科 |
| 补弱 `weak` / 补前置 `backfill` | 薄弱/低分学习中的知识点；它的必须前置没掌握就先补前置；两者交替 |
| 回顾小检查 `check` | 学校学过（勾选的 + 以前学段）但系统里还没检测过的知识点，每天轮换一个，限当前学段往前两段 |
| 预习 `preview` | 设置了进度：同一板块里「正在学」之后、前置已学过的下一个；没设置进度：前置已具备的当前/下一学段知识点 |
| 知识点回顾 `review` | 到期的知识点总结卡片 |

完成练习、复习、阅读、诊断、试卷订正时，对应的任务自动打勾并 +1 ⭐。

### 5.3.1 课程进度（个性化推进）

学校进度对不齐是每日计划最大的难点，系统不去猜，而是让孩子/家长自己维护（`/progress`，1 分钟）：

- 每个教材包：当前学段、「现在学校正在学」的知识点（`enrollments.progress_kp`）、本学段已经学过的知识点（`kp_taught`）。
- 「学过」= 以前学段的全部 + 本学段勾选的。系统据此：跟上「正在学」、在学过的范围里往回抽查、顺着前置关系补漏、在同一板块往前预习一步。
- 掌握度（`mastery`）和「学过」是两回事：学过但没检测的会被「回顾小检查」轮到；检测出薄弱的进入补弱和补前置。这样形成一张网：往回巩固、相互补漏、往前推进。

### 5.3.2 试卷

`/papers`：拍照（浏览器先压缩到长边 1800px）或粘贴文字 → `llm.parse_paper`（任务名 `paper`，需要能看图的模型）一次完成拆题、作答、讲解、从候选知识点（当前学段往前两段、往后一段）中选 `kp_id`、读出卷面答案和批改痕迹。

- 题目存入 `items`（`source='paper'`），卷子和每题的原卷对错、在线作答存 `papers` / `paper_items`。
- 原卷判错/扣分的题：记一次 `exam` 作答（计入掌握度）并进错题本。
- 在线重做：自动判分或自评，可点「还不会」；觉得 AI 答案不对可以标记，这题不计入诊断；知识点对得不准可以手动改。
- 诊断：按知识点汇总原卷丢分和重做结果；重做还错/还不会的是「要补的」，并列出没掌握的前置；原卷错但重做对的列为「可能粗心」。

### 5.3.3 划词查词插件

`extension/` 是 Chrome MV3 插件。孩子账号在「查词工具」页生成连接码（`api_tokens`，只存 sha256），插件用 `Authorization: Bearer` 调 `/ext/me`、`/ext/lookup`、`/ext/save`。加入的词成为 `word`/`phrase` 卡片，进入每天的「单词」任务。下载的 zip 会自动写好服务器地址。

### 5.4 一个知识点的学习步骤

看懂（说明 + 关键词 + 可选「AI 一步步讲」）→ 记方法 → 做 3 题（从易到难，每题有提示；连错两题提示退一步补前置）→ 一句话总结（变成复习卡片）。页面下方同时列出「往回：前置知识」和「往前：后续知识」。

### 5.5 间隔复习

卡片类型：生词、术语、错题（做错自动加入）、知识点总结。盒子间隔 1/2/4/7/15/30/60 天；「忘了」回到第 0 盒当天再来，「模糊」明天再来，「记得」进下一盒。

### 5.6 阅读

- 来源：AI 按年级写略高一点的短文（i+1），自动嵌入孩子最近要复习的生词，附 3 道理解题；或者粘贴自己的书/课文。
- 英文：每个单词可点；中文：选中字词查询，点句子可问「这句什么意思」。
- 查词结果贴合原句意思；可一键收藏（带原句进入复习）、用它造句（AI 先表扬再指出一个最重要的问题，给改正句和示范句）。
- 读完打卡记录时长和理解题结果。

### 5.7 问一问小助手（引导式提问，默认名「小艾」，`.env` 里 `ASSISTANT_NAME` 可改）

孩子页面右下角常驻按钮（诊断页除外）。前端带上当前上下文：孩子最近点过 / 屏幕上的那道题（`renderItem` 给题目框标 `askable` 和题目 id）、是否已作答、选中的文字、页面标题、知识点。
服务器取出题目的正确答案和讲解，作为「只给小艾参考、绝不能说出」的内容放进提示词（`llm.ask_tutor`，任务名 `ask`）。
回复要求：苏格拉底式，一次只推进一小步、以问题结尾；连续卡住就退回更基础的知识；模型自报 `reveals_answer` 为真时重新生成一次。
对话存 `ask_threads` / `ask_messages`，同一道题接着问，换题自动开新对话；家长在学习报告里能看到。计入每个孩子每天的 AI 次数上限。

## 6. AI 抽象层与使用原则

- **配置和代码分离**：提供方、模型、密钥、每日上限、按任务路由都在 `config/llm.toml`（模板 `config/llm.example.toml`），改完重启服务生效，不用改代码。值可以写成 `"${环境变量}"`。
- **抽象**：业务代码只调用 `app.llm` 里的任务函数；任务函数把请求包装成 `ChatRequest` 交给 `service.ask_json`；`service` 按配置选出 `Provider` 调用。新增一个模型厂商 = 写一个 `Provider` 子类并 `@register("类型名")`，配置里写 `type = "类型名"`。
- **按任务路由**：`[tasks.lookup]` 这样的段落可以给某个任务单独指定提供方、模型、effort、max_tokens（比如查词用更便宜的模型，出题用更强的模型）。
- 所有调用在服务器端，结果按输入做缓存（同一个词在同一句里只查一次；讲解按知识点缓存）。
- 生成的题存入题库复用，不重复花钱；题目要求「答案正确且唯一」，人工核对过的题标为 seed 优先使用。
- 每个孩子每天调用上限 `daily_limit_per_kid`。
- 面向国际学校的学科：题干英文 + 中文翻译，讲解用中文并标出英文术语。
- Claude 默认启用服务端 fallback（`server_fallback = true`），模型过载时自动切换备用模型。
- `install.sh check --llm` 会真实调用一次，确认密钥和网络都通。

## 7. 数据表

`users`（家长/孩子）· `enrollments`（孩子选的教材包和当前学段）· `mastery`（掌握度）· `items`（题库）· `attempts`（每次作答）· `cards`（复习卡片：生词/错题/术语/总结）· `diag_sessions`（诊断过程和结果）· `days`（每日计划、分钟数、打卡、反思）· `readings` · `lookups`（查词记录）· `tracks`（阅读/新词进度）· `reading_logs` · `kp_taught`（学校学过的知识点）· `papers` / `paper_items`（试卷）· `api_tokens`（插件连接码）· `ask_threads` / `ask_messages`（问小艾）· `sentences`（造句与点评）· `llm_cache` · `llm_usage` · 账号：`sessions` · `invites` · `password_resets` · `auth_events` · 迁移记录：`schema_migrations`。完整定义见 `migrations/`。

## 8. 后续路线

1. **作业拍照**：和试卷一样，但只挑错题。
2. **听说**：英文朗读（TTS）、跟读录音、听写。
3. **按课本单元走**：给知识点补全 `unit`，进度页按单元勾选更快。
4. **家长周报**：每周自动汇总发到邮箱或微信。
5. **奖励机制**：连续打卡、完成计划兑换积分。
6. **更多教材包**：人教版数学、新概念英语、IGCSE 数学/化学、A-Level 等，按第 4 节格式添加即可。
