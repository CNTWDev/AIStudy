# AIStudy 设计文档

> 2026-10 更新：入口已拆为 `routes/` 与 `web.py`，新增概念投影、教材库存与独立 worker。当前实现以 [学习基础架构](LEARNING_FOUNDATION.md) 为准；以下保留既有功能说明。

## 1. 目标

一套能陪孩子从小学一直学到高中的网页系统：

- **同一套系统，不同教材**：教材是可插拔的数据，不写死在代码里。
- **向后补、向前学**：知识点之间有前置关系，诊断时沿前置往回追找断点，学会后沿后续往前预习。
- **门槛低**：每件事都拆成小步骤；先做最简单的一步；卡住了有提示、有「退一步」。
- **完整记录**：每道题、每次复习、每个查过的词、每天的反思都留下来，家长随时能看。
- **简单稳定**：一个 Python 应用 + 一个 PostgreSQL 数据库，一台 1 核 1G 的云服务器就能跑；一键安装/升级；AI 只在服务器端调用。

## 2. 架构

```
浏览器（孩子 / 家长，手机优先）
   │  服务端渲染页面 + 少量原生 JS 调 /api/*
   ▼
FastAPI 应用（app/main.py）
   ├─ catalog.py   教材目录：加载 curricula/*.json，提供知识图谱查询（前置、后续、祖先）
   ├─ engine.py    学习引擎：诊断回溯、间隔复习、错题本、统计
   ├─ evidence.py  学习证据：事件表 → 当前学习方式的模型 → 掌握状态；换方式时按事件重放（见 5.0）
   ├─ methods/     学习方法：掌握模型（mastery.py）、记忆模型（memory.py）、学习方式配置（profiles.toml）
   ├─ plan.py      每日计划：任务来源 + 按学习方式的策略排
   ├─ itemtypes.py 题型注册表：判分、显示、证据题型、蒙对概率、AI 题整理、前端控件
   ├─ llm/         AI 抽象层（见第 6 节）
   │   ├─ base.py       Provider 接口、ChatRequest、LLMError
   │   ├─ providers.py  anthropic（Claude）/ openai_compat（DeepSeek、通义…）/ mock
   │   ├─ settings.py   读取 config/llm.toml
   │   ├─ service.py    选提供方、缓存、每日限额、解析 JSON
   │   └─ tasks.py      具体任务的提示词：查词、讲解、出题、造句点评、写短文
   ├─ auth.py      账号系统（见第 3 节）
   ├─ db.py        数据库访问：PostgreSQL（生产）/ SQLite（本地试用、测试），统一 ? 占位符
   ├─ migrate.py   数据库迁移：按编号执行 migrations/*.sql，记录在 schema_migrations
   └─ cli.py       命令行：migrate / check / backup / create-admin / reset-password / invite …
数据：curricula/（教材知识图谱） seed/（人工核对过的题库、术语卡） PostgreSQL（全部账号和学习记录）
配置：.env（服务器、数据库、账号策略） config/llm.toml（AI 提供方、模型、密钥、按任务路由）
      config/methods.toml（可选：覆盖 / 新增学习方式，默认配置在 app/methods/profiles.toml）
运维：install.sh（一键安装/升级：环境检测 → 装依赖 → 拉代码 → 建库 → 备份 → 迁移 → systemd → Caddy HTTPS → 健康检查）
```

为什么这样选：

- **服务端渲染 + 原生 JS**：没有前端构建步骤，部署就是复制文件；手机浏览器打开即可用。
- **PostgreSQL**：单机就能装，稳定、并发好，多个家庭一起用也没问题；`pg_dump` 备份。本地试用和自动测试仍可用 SQLite（改 `DATABASE_URL` 即可），两种数据库跑同一套测试。
- **迁移脚本**：表结构只通过 `migrations/NNNN_xxx.sql` 改动，升级时自动执行，已执行的不会重复。新增字段就加一个编号更大的文件，不改旧文件。
- **AI 在服务器端**：密钥不会出现在孩子的浏览器里；所有调用有缓存和每日上限。

## 3. 账号

- **角色**：网站管理员（admin，第一个注册的账号；只用管理后台）、家长（parent：添加孩子、查看和管理）、孩子（kid，属于某个家长；只有孩子账号能做题学习）。
  `is_admin=1` 表示有管理后台权限；旧版本里「第一个家长」账号保留家长 + 管理员两种身份。
- **家长只读**：家长在家长页选中孩子后，可以看今天的清单、学科、知识地图、记录、单词本，可以更新学校进度、导入试卷、改试卷的知识点；
  做题、阅读、复习、打卡、提问这些「学习」接口都要求孩子本人登录（`kid_or_redirect(manage=False)` 默认拒绝家长）。
- **家长注册**由站点设置里的注册方式决定（管理后台「站点设置」，默认取 `.env` 的 `REGISTRATION`）：`approval`（默认：有邀请码直接开通，没有的提交申请等管理员审批）/ `invite`（必须邀请码）/ `closed`（只能管理员创建）/ `open`。管理员和家长都能生成邀请码，`users.invited_by` 记录邀请关系。
- **自学者**：注册时选「自己学」的账号，在库里是没有家长的学习账号（`role='kid'`、`parent_id` 为空，`auth.is_self_learner`），默认年级「成人」。
  学习功能和孩子完全一样；孩子由家长管的那些（课程、每天时长、考试日期、名字邮箱）由自己管：「我的课程」（`/me/courses`）和家长的「编辑孩子」共用一张表单（`kid_form.html` 的 `self_mode`，保存都走 `web._save_learning`），不显示学校、隐私模式和城市，乐园（每天玩多久、昵称）自己定。
- **家庭里的成人成员**：家庭只是把一家人放在一起（家里的房间、一起打卡），家长管的只是未成年的孩子。谁安排学习只看一条规则 `auth.self_managed`：
  没有家长（自学者），或年级在大学及以上（`catalog.is_adult`），就自己管。成人成员用「我的课程」自己选课，年级只能选大学或成人；
  家长页上显示 TA 的坚持（连续天数、这一周学了几天）、正确率小曲线和上周进步，能点开 TA 的学习报告（只看不改，`auth.kid_of(..., report=True)`），每周报告邮件里也有 TA；
  只能改账号（名字、邮箱、密码、暂停、年级），今天清单、安排学习都进不去（`auth.kid_of` 默认拒绝，`account_only=True` 才放行）。
  孩子年级升到大学，自动改成自己管，原来的课程留着。成人不上排行榜、不进全站的公开房间（`auth.with_other_kids`），家里的和用密码约好的房间照样能进。
  考试日期由学习者自己定，不由管理员维护场次：各地、各场次不同，自己定的才准，也省掉运营成本。管理后台「家庭与孩子」里单独列出自学者。
- **孩子账号**由家长在网页上创建：名字、登录邮箱、密码、年级、每天学习分钟数、学校，以及要学的教材包和当前学段；家长可以改孩子密码、暂停孩子账号。
- **密码**：PBKDF2-SHA256，20 万次迭代，每个密码独立随机盐。
- **会话**：登录后生成随机令牌，cookie 里放令牌（已签名），数据库 `sessions` 表只存它的 sha256。退出、改密码（其他设备自动下线）、停用账号、在「我的账号」里踢掉某个设备，都立即生效。
- **防暴力破解**：同一账号连续输错 `LOGIN_MAX_FAILS` 次锁定 `LOGIN_LOCK_MINUTES` 分钟；`python -m app.cli unlock 邮箱` 可手动解锁。
- **账号管理**：家长在「资料与密码」里管自己的孩子，管理员在「账号管理」（`/admin/users/<id>`）管任何其他账号。两处共用同一套操作（`main.account_action`）：改名字和邮箱、重置密码、解除锁定、退出所有设备。
  - 重置密码时可以直接输入新密码，留空则生成一个好读的临时密码（只在页面上显示一次）。
  - 勾选「下次登录要求改密码」会设 `users.must_change_pw=1`，对方登录后除了「我的账号」页哪里都进不去，改完密码自动清除。管理员重置家长时默认勾选，家长重置孩子时默认不勾。
  - 管理员也可以改发一次性重设链接（48 小时有效）。管理员自己忘记密码用命令行 `reset-password`。暂不发邮件。
- **孩子的教材**：每门课只选一个教材版本，学段按孩子年级自动对应（`catalog.default_stage`）；年级没变、教材没换时保留原学段（「学校进度」里可能已经往后调过）。
- **安全日志**：登录成功/失败、锁定、改密码、停用、生成重设链接等都记在 `auth_events`，管理页可看最近 100 条。
- 孩子只能看到自己的数据；家长能看自己孩子的总览和报告；管理员能看所有家庭和孩子的情况。

## 4. 教材数据模型：四层，各自独立、各自扩展

不同年级、学科、学校类型的孩子用的教材都不一样，还会不断增加，所以教材数据分成四层。
每一层只依赖它下面的层，每层都可以单独扩充。孩子自己的选择存在数据库里，不进教材文件。

```
孩子的选择（数据库）    年级 · 学校类型/模板 · 每科选哪套教材、哪个方向 · 学到哪 · 掌握情况
        │
学校模板 _meta/presets.json   上海公办小学/初中/高中、民办双语、国际学校剑桥路线……（预填，可逐科改）
        │
关联层   _links/*.json         concepts（同一概念跨教材互认）· links（uses / language / context）
        │
教材包   curricula/*.json      一套教材 = 板块 + 知识点（+ 方向 tracks）；包与包互不依赖
         国内公办：课标主干（知识点）+ 目录包（这套书哪一册哪一单元教哪些点），见 4.2.1
        │
学段     _meta/stages.json     所有学制放在同一根「学年」轴上（G1–G12、IGCSE、A-Level、IB MYP/DP、AP）
```

### 4.1 学段（`curricula/_meta/stages.json`）

每个学段有 `id`、`system`（cn / cambridge / alevel / ib / us / uni）、`label` 和 `year`。`year` 是「相当于中国几年级」，例如 IGCSE = 9.5，MYP3 = 8，DP1 = 11，大一 U1 = 13。

- 不同学制的知识点靠 `year` 比先后，诊断回溯和跨教材推断都用它。
- 学制（`systems`）带 `international` 和 `lang`：这个学制的课默认用什么语言授课和出题。代码不再按教材 id 猜。
- 没有统一学制的课程（少儿编程、某个技术栈、兴趣课）用 `course` 学制，级别在教材包里自己定义（见 4.2 的 `levels`）。
- 职业资格考试（基金从业、证券从业、会计……）用 `cert` 学制，`kind` 写 `syllabus`，级别同样在包里用 `levels` 定义（如 `FUND-1` 基金从业·科目一，year 18）。
- **成人学习者**：年级选「成人」（`ADULT`，year 18）；年级在 U1 及以上都算成人（`catalog.is_adult`）。成人的 AI 提示词换成成人口吻（`llm/tasks.py` 的 `TUTOR_ADULT`、`ASK_TUTOR_ADULT`），乐园默认关闭、不显示入口；`cert` 学制的课不自动安排摸底诊断，也不提醒更新学校进度。
- 加学制或年级只改这个文件。孩子的「年级」从 `grades` 里选，`default_grade` 是新建孩子时的默认值。

学科表 `curricula/_meta/subjects.json`：学科 id、名字、图标、颜色、领域（language / math / science / humanities / social / computing / finance），语言类学科还有 `lang`（它教的是哪种语言）。加学科只改这个文件，页面上的图标、语言课的判断都从这里来。

### 4.2 教材包（`curricula/<pack_id>.json`）

```json
{
  "pack": {"id": "eng-cambridge", "subject": "english", "subject_name": "英语", "edition": "剑桥英语（…）",
           "region": "国际学校", "system": "cambridge", "school_types": ["international", "private"],
           "tracks": [{"id": "0511", "name": "IGCSE ESL 0511（口语计入总分 25%）"}, {"id": "0510", "name": "…"}, {"id": "0500", "name": "…"}],
           "default_track": "0511", "stages": ["G3", "…", "IGCSE"], "version": 2, "verified": "2026-10-06",
           "sources": ["官方大纲 / 教学用书目录 URL"], "notes": "版本说明、学段对应、考试结构"},
  "strands": [{"id": "REA", "name": "阅读"}],
  "kps": [{"id": "ENG-REA-12", "strand": "REA", "stage": "IGCSE", "syllabus": "0510/0511 Paper 1 Ex3",
           "tracks": ["0510", "0511"], "name": "笔记补全", "name_en": "Note completion", "desc": "…",
           "prereqs": [{"id": "…", "strength": "必须"}], "hot": true, "method": "…", "probe": "…", "terms": ["…"],
           "source": "这个点的依据"}]
}
```

- **知识点 id 全局唯一，而且永不修改**，因为学生数据按 id 记录。内容变了就改字段；要删除先评估影响。
- **方向（tracks）**：同一套教材里不同考试或难度的分支，例如剑桥英语 0511 / 0510 / 0500、IGCSE Core / Extended。
  - 知识点带 `tracks` 字段，表示只属于这些方向；不带，表示所有方向都要学。
  - 孩子在每套教材上选一个方向（存在 `enrollments.track`），没选就用 `default_track`。
  - 诊断、计划、地图、进度、统计都只看所选方向的知识点：`catalog.ids_for(pack, track)`、`engine.my_ids(user, pack)`。
- **prereqs**：「必须」用于诊断回溯和补漏，「有帮助」只做展示。前置的学段不能晚于本点，否则自动降为「有帮助」。
- **school_types / system**：「编辑孩子」时把适合这类学校的教材排在前面。其它教材仍然可选，用于转学或提前学。
- **kind**：`textbook`（审定教材，如统编、沪教）/ `syllabus`（考试局大纲，如剑桥 IGCSE）/ `course`（没有统一教材的课程：少儿 Python、大学线性代数、某个技术栈）。不写时按学制推断：cn → textbook，国际学制 → syllabus，其它 → course。
- **teach_lang / item_lang**：授课语言、出题语言。不写时：语言课的题目用它教的语言（语文课讲解也用中文）；其他学科按学制（国际学制英文，否则中文）。题库按 `item_lang` 分语言，AI 出题和讲解的说明也按它生成。
- **levels**：`course` 没有年级时自己定义级别，例如 `[{"id": "PY-L1", "label": "入门", "year": 3}]`。级别挂到学段轴上，和年级比先后，知识点的 `stage` 引用它。大学课程直接用 U1–U4。
- **prompt_note**：给 AI 出题、讲解时的额外说明，比如「代码用 Python 3，不用第三方库」。不用为某门课改代码。
- 编程类题目用现有题型加 `code` 字段（一段代码，页面按代码块显示）：读代码写输出用填空，选哪段代码对用选择。
- **加一套教材**：往 `curricula/` 放一个 JSON 文件，跑 `python -m app.cli check-curricula` 通过即可。CI 也会跑这一步。
- 题库 `seed/items_*.json`、术语卡 `seed/vocab_*.json` 按知识点 id 挂靠。

### 4.2.1 课标主干 + 目录包：国内公办的不同教材

全国公办学校都按国家课程标准（义务教育 2022 版、高中 2017/2020 版）编书，教材不同，知识点大同小异。
所以国内公办的一门课分两层：**知识点属于课标主干，一套教材只是一份目录**。

```
math-cn（kind: standard，主干）     知识点、前置、题、讲解、掌握度、能力模型都挂在这里；孩子不直接选
   ├── math-shanghai（目录包）      沪教版：册次 → 单元 → 知识点
   ├── math-sujiao（目录包）        苏教版小学
   └── math-suke（目录包）          苏科版初中
```

- 目录包 = `pack.base` 指向主干 + `books`（`[{stage, term, name, status, sources, units: [{name, kps}]}]`）+ 可选的本书独有知识点 `kps`。
  学科、学制、语言、方向这些从主干继承。孩子报名的是目录包（`enrollments.pack_id`），学生数据仍然按知识点 id 记。
- **同一个点，不同的教学时间**：知识点在某套书里的学段、学期、单元取它在目录里第一次出现的位置（`catalog.kp_in(pack, kp)`、
  `catalog.stage_in`）。周长：上海三年级教，苏教新版四上教。主干里的学段只用来排先后、往回找。
  学校进度、章节、「以前学过」「今年的」「预习」都按孩子那套书算；同一个点可以在几个单元里出现（螺旋上升）。
- **目录还没核实全**：每册写 `status`（verified / partial / legacy）和来源。没列出的册由系统补一本「目录待核实」：
  目录里还没出现的主干知识点放进后面第一本没列的册，按板块分章；上下册都列全了还没出现的点、比这套书开始年级还早的点（那是地基，见 5.23），不算这套书的。
  拿到课本目录后把那一册补进 `books` 就行，学生记录不受影响。
- **贯穿各单元的板块**：主干的板块可标 `throughout`（英语的语音、阅读、写作、听说）。这类点每个单元都在练，不归哪一个单元：
  目录列了这个年级的册，就记在这一学年第一册的 `throughout` 里，算这一年的内容，但不占章，不参与按章推演学校进度。
- 换教材、转学（上海 ↔ 江苏）：同一个知识点，证据直接用，不用概念互认；题和讲解只有一份，AI 不重复生成。
- 主干里没有、课标里有的内容（比如苏教一下的「数据分类」）加进主干（id 前缀 `MCN-`），不加进某一套书。真正只有这套书有的（某套英语的单元词表）才放目录包自己的 `kps`。
- 知识点合并（比如以前的苏州试点主题点并进主干）记在数据库 `kp_renames` 表，迁移把学习记录挪到新 id 上；知识点 id 本身仍然永不修改。
- 现在拆了主干的：数学（`math-cn`）、英语（`eng-cn`）、语文（`chn-cn`），知识点来自上海包（id 不变），目录包有上海、苏教小学数学、苏科初中数学、译林英语、统编语文五四学制（`chn-tongbian`，上海）和六三学制（`chn-tongbian-63`，江苏等）。语文的板块都标 `throughout`，没挂到具体单元的点记在这一学年。
  其它学科（物理、化学……）等有第二套国内教材时再拆。国际课程（剑桥、IB）依据各自考纲，仍是独立的包，和主干之间用 4.3 的 concepts 互认。
- `textbooks.json` 仍是全国教材的库存（哪些版本在用、核实到哪一步、对应哪个包）；管理后台的册次映射目前只用于独立的包，目录包的 `books` 在文件里改。

### 4.3 关联层（`curricula/_links/*.json`）：学科独立，课上融合

教材包之间互不引用（基础前置点除外），跨学科的融合单独放在关联文件里。加关联不动教材，删掉一个关联文件也不影响教材。

现有关联文件按领域分：`core.json`（第一批）、`math.json`（沪教 ↔ 剑桥 ↔ 前置，理科用到的数学）、`science.json`（理科同一概念、理科互用、中英术语）、`language.json`（语文 ↔ IGCSE 中文、上海英语 ↔ 剑桥英语，英语和语文、地理的融合）、`history.json`（历史和语文、地理、英语、理科）、`economics.json`（经济和数学、地理）。同一个知识点只能属于一个概念，`check-curricula` 会检查。

- **concepts**：同一个概念在不同教材里的知识点。例如「密度」在沪科版物理、剑桥物理、Lower Secondary Science 里各有一个点。
  - 孩子学会其中一个，其它几个如果还没测过，就推断为「学习中」（`engine.infer_equivalents`）。
  - 这样转学、换教材、公办转国际，都不用从零开始。
- **links**：有方向的关联。
  - `uses`：from 用到 to。例如物理「速度」用到数学「速度、路程、时间的数量关系」和一次函数。
  - `language`：同一内容的另一种语言说法。例如物理术语和英语词汇。
  - `context`：背景知识。例如英语阅读话题和语文、历史、道法里学过的内容。
- 融合在上层应用里的落点：
  1. **学习页「🔗 和别的学科连起来」**（`engine.bridges`）：列出同一概念、要用到、会用在、相关背景，孩子已经会的排前面。
  2. **AI 讲解**：把孩子在别的学科已经学过的相关内容写进提示，让讲解从已知的东西引入，比如「你在数学里学过……」「英语里叫……」。
  3. **语言阅读选题**（`engine.cross_topics`）：英语阅读用最近在物理、科学、历史里学过的内容（用英语学内容）；中文阅读用历史、道法、科学的内容。
  4. **掌握度互认**：见上面的 concepts。

### 4.4 学校模板（`curricula/_meta/presets.json`）

模板是常见的「学校类型 → 各科教材 + 方向」组合，比如上海公办小学、上海公办初中、民办双语、国际学校剑桥路线。

### 4.4.1 课程按人群分开：中小学的课给中小学生，成人的课给成人（`catalog.visible`）

- 课有一个 `audience`：`school` / `adult` / `all`。默认从学段推：学段（或 levels 的 year）都在大学及以上 → adult，都在高三及以下 → school，两边都有 → all；包里写 `"audience"` 可覆盖。
- 学习者属于哪一群看年级（`app/catalog.py` 的 `audience(grade)`，和 `is_adult` 同一条线），不看账号类型：家长、孩子、自学者只决定谁管谁。家长自己学成人课，就在家里加一个自己的成人成员。自学者都是成人，年级只能选大学或「成人」。
- 一个函数管所有地方：选课表单只列能学的课（`course_choices`），保存时不收别的（`_kid_form_packs`），知识地图、学习页、讲解、练习、诊断打不开别的（`learner_pack` / `learner_kp`），登录页「这里能学什么」按它分组。
- 年级跨线（孩子升大一、成人成员改回孩子年级）：另一边的课暂停、记录留着（`engine.fit_courses`，改年级后和启动时做，同 5.33）。
- 知识点：成人的课可以把中小学的点当前置（补基础，`catalog.foundations`，成人也能打开）；中小学的课不能用到成人课的点，关联和概念也不能把两边连起来，`check-curricula` 校验。
- 每天的学习和学习页同一条规则（`catalog.kp_visible`）：打不开的点（`catalog.closed_to`）算在 `engine.Paused` 里，自动发现、热身、复习、思辨题都不碰；`plan.build_plan` 最后再过一遍，任何来源漏了都排不进计划；排好以后才变的（改年级、升级前排的），`engine.today_plan` 发现还没做的任务里有打不开的点就重排。以前在另一边的课里留下的作答记录照样留着，只是不再拿来排任务。
- 讨论稿：项目文件 `docs/课程按人群分开-方案.md`。

### 4.6 自编教材（第一门：CEO 专项课 `curricula/ceo-core.json`）

没有官方教材或大纲的课，由我们自己编教材，版权归 BeeJoy（beejoy.ai）。教材分三层，都按知识点 id 挂靠：

| 层 | 文件 | 说明 |
|---|---|---|
| 骨架 | `curricula/<pack>.json`，`kind: "course"` | 模块（strands，可带 `dimension`）、知识点、前置、学法、诊断思路、术语 |
| 正文 | `seed/teach_<pack>.json` | 每个知识点一篇人工写的讲义，格式同 AI 讲义（`steps` / `example` / `remember`），可多一条 `action`（本周试一试） |
| 题 | `seed/items_<pack>.json` | 人工写的预置题；不够时 AI 按 `prompt_note` 现场出，存下复用 |

- 启动时 `engine.load_seed_lessons` 把讲义导入为 `contents` 里 `origin='author'` 的讲义，同一个知识点的 AI 讲义和旧版作者讲义换下（`status='retired'`），所以作者版一直优先，AI 不再重写。改讲义就改文件，重启后新版自动替换旧版；管理员在后台下架的那一版不会被自动重新上架。
- 自编课的知识点多三个字段：`evidence`（证据牌）、`evidence_note`（一句话说重复情况和边界）和 `sources`（出处，只记出处不抄原文），学习页上显示。包里的 `copyright` 显示在学习页底部。
- 证据牌所有课共用一套（`catalog.EVIDENCE`）：🟢 稳（多次独立重复、有元分析或大样本）、🟡 要小心（方向成立但效应小、条件多或有争论）、🔴 站不住（大规模重复失败，讲它是为了知道为什么倒）、📐 基本原理（定义或推理得出，如会计、概率、研究方法）、📖 经典案例、💬 经验之谈。前三档是研究结论，必须写 `sources`（`check-curricula` 会查）。
- 讲义里可以带 `context`（「为什么学」的导入：`story`、`question`），一样导入为作者版导入，没配置 AI 时也显示。
- 人性和管理容易混进站不住的说法，所以每条规律标证据等级，`prompt_note` 里写明不编造研究和数据、不用已被推翻的说法。
- 仓库是公开的：只放通用的骨架、讲义和题。CEO 本人的批注、公司真实案例放在网站数据库里，不进 Git。
- 学员的「年级」在成人（U1 及以上）时，选课页把成人课程排在前面。
- 讨论稿：项目共享文件夹 `docs/CEO专项课与自编教材-讨论稿.md`。
- 难题课（`think`）先让学员写下自己一开始的判断，再看几种都有道理的看法；总结时对照一开始的判断写现在的想法。
- **开放题由 AI 点评和追问**（`app/coach.py`，包里写 `"open_review": "ai"`）：学员写下判断和理由 → AI 按题目的 `points` 逐条判断做到没有，点评两到四句（先说想得好的，再说最关键的缺口，不说答案），并追问一句 → 学员接着答，最多追问两次，最后一轮收尾，再给参考思路。每一轮记在 `open_reviews` 表里（迁移 0037），追问中的那几轮不写作答回执。结论决定这次算不算答对：第一轮就 `good` 记一条完整的「答对」，追问后才 `good` 记 0.6 条，`partial` / `miss` 记「还没答对」（进错题本，过几天再练）。AI 点评过的开放题不受自评证据 0.3 的分量上限（`item["judge"]="ai"`）。没配置 AI，或 AI 第一轮就出错时，退回对照参考答案自评；追问那一轮出错按上一轮的结论收尾。

### 4.7 题型怎么判：三种判定方式，思辨题

题型注册表（`app/itemtypes.py`）里每种题型说明自己怎么判（`judge`），各处按判定方式决定能不能拿这道题，不按学科写特例：

| judge | 题型 | 怎么判 | 用在哪 |
|---|---|---|---|
| `auto` | 选择、填空、计算 | 程序判对错 | 所有地方；摸底、找根源、热身、游戏只用这种（`itemtypes.auto`） |
| `self` | 简答 | 对照参考答案判：自评，课程包写了 `"open_review": "ai"` 时由 AI 对照要点点评追问（`app/coach.py`） | 练习、复习 |
| `open` | 思辨题 `discuss` | 不判对错 | 练习；想完以后换条件再想 |

**思辨题**用于没有标准答案的问题（经营决策、历史评价、伦理、议论文立意……），哪门学科都能用：
- 题里不写答案，写 `perspectives`（3-4 种都有道理、彼此有张力的看法，每种带成立条件 `holds_when` 和风险 `risk`）、`moves`（用得上的思考方式）、`twists`（换一个关键条件再问的问题）。
- 课程包列出这门课看重的思考方式 `thinking_moves`（可以直接写本包知识点的 id，CEO 专项课就是 T 模块的九种方法）。只有列了 `thinking_moves` 的课，AI 出题时才会出思辨题。
- 作答（`app/discuss.py`，迁移 0038 `discussions`）：学员写判断和理由 → AI 先把学员的观点说得更有力、回答学员的反问，再提一个挑战（反例、换条件、站到另一方），不说对错 → 学员接着想，最多 4 轮，随时可以收尾 → 学员写结论和一个动作 → AI 对照第一段话说想法变了什么，标出结论接近哪几种看法、有没有几种看法之外的东西、在什么情况下会出问题。
- 不写 `attempts`、不进错题本、不算掌握度的对错证据。记下的是用到了哪些思考方式：第一段话里就用到的算「自己想到」，被挑战以后才用到的算「追问后想到」，在 `/thinking` 页汇成思考画像。想过的题不再当新题出。
- 错题本里不放思辨题：以前按简答题判错、后来改成思辨题的题，启动时拿掉错题卡、删掉当时的对错证据并重算掌握状态（`engine.retire_open_mistakes`）；万一重做时碰到，照思辨题的方式想一遍，想完卡就拿掉。
- 想完以后按 3 / 7 / 14 天依次拿 `twists` 换条件再问（`/thinking` 页和今天页提醒）。没配置 AI 时跳过对话，直接写结论、看几种看法。
- 收尾时「落到自己身上」那一栏问什么，由课程包的 `discuss_action` 定（默认「接下来我会做的一件事」，CEO 课是「回到公司，我会做的一件事」，心理学课是「这周我想试的一件事」）。

#### 4.7.1 学员写的话里有危险信号：先关心人（`app/safety.py`）

学员自由书写、AI 接着回应的地方（思辨题），先用一份短词表看学员的话（只认说自己的话，比如「我不想活了」，讨论题目本身的词不算），AI 回应时也会判断，觉得学员本人可能有危险就只返回 `{"care": true}`。
命中以后这道题停下，显示求助渠道（全国心理援助热线 12356、120 / 110、告诉一个信任的人）；这段话不存、不算一次学习、不进思考画像。只做「停下、指路」，不做诊断，也不做心理辅导。

### 4.8 决策日志（`app/journal.py`）；第二门自编课：散户美股实战课（`curricula/us-stock.json`）

**决策日志**是一个通用模块，哪门课用、写哪几栏由课程包的 `journal` 声明，不按学科写特例：
`{name, intro, subject_label, subject_hint, fields: [{id, label, hint}], review_days: [天数], traps: [本包知识点 id]}`。
- 学员做一个决定之前写一条：决定什么、各栏（美股课是仓位、理由、优势、认错条件；CEO 课是为什么这样定、在赌什么、认错信号）、几成把握、多久以后回看（迁移 0044 `journal`）。
- 到了回看日期，今天页提醒「N 个决定到了回看的时候」。复盘先看当时写的，再选：当时的判断站不站得住、结果好不好、踩了哪些坑（`traps`，连到那一课）。
- 四个格子：判断对结果好、判断对运气差、判断错运气好（最危险，专门提醒）、判断错结果差。复盘多了自己找规律（`patterns`）：判断错却结果好的有几个；说有七成以上把握的，结果好的实际占多少；哪个坑反复踩。
- 只给本人看：家长、管理员、排行榜都看不到（路由用 `kid_or_redirect` 不带 `manage`）。不判对错、不进掌握度。

**散户美股实战课**（讨论稿：项目共享文件夹 `docs/美股实战课-讨论稿.md`）：不教「买什么」，教「怎么下注」。写法同 CEO 专项课（§4.6）：
开篇（先和指数比、优势、能投的钱、决策日志）、下注的数学、人性陷阱、真处境（`think` 难题课），22 课作者讲义，选择题考算账和事实，判断题全是思辨题。
- 投资者教育，不是投资咨询：`prompt_note` 写明 AI 不推荐、不点评、不预测任何具体股票，不承诺收益，学员问能不能买就把问题转回他的理由、优势、仓位和认错条件；案例只用历史行情。
- 规则和账户（换汇额度、W-8BEN、境外所得税、美国遗产税）法规变化快，核实后再加，每条标核实日期。

### 4.9 第三门自编课：心理学（`curricula/psy-core.json`）

讨论稿：项目共享文件夹 `docs/成人心理学课-讨论稿.md`。面向所有成人：看清自己、读懂别人、改掉一个习惯，并学会分辨心理学说法靠不靠谱。写法同 CEO 专项课（§4.6），试点 24 课：
- 开篇「心理学怎么知道」（后见之明、相关不等于因果、证据五问、重复危机、个体差异）是这门课的思考方式（`thinking_moves`），思辨题里记的就是这五种。
- 每课：一个生活困惑（作者写的 `context`）→ 先猜一个经典实验的结果（第一道选择题，学完做题时揭晓）→ 研究和证据牌 → 怎么用 → 一周小实验（讲义的 `action`；难题课思辨题的最后一个 `twists` 回来问「试了吗」）。
- 🔴 站不住的结论单独成课（试点里是自我损耗），讲它为什么火、为什么倒。
- 判断与决策模块的规律和 CEO 课、美股课重叠，用 `_links/psychology.json` 的概念连起来，各课不重复写：心理学课讲是什么、证据多硬，另两门讲在公司、交易里怎么用。判断与决策模块配了一个「生活决定日志」（决策日志模块，§4.8），陷阱就是这八课。
- 不做心理治疗、不做诊断；心理健康只讲素养（以后的模块），思辨题受 §4.7.1 的安全规则保护。

## 5. 学习引擎

### 5.0 学习方式（教学理念）和扩展点

学习方法会不断研究、引入，所以「方法」和「记录」分开：

- **学习事件表 `events` 是唯一的原始记录**：做题、复习卡片、单词摸底、推断、自评、导入，每条证据一行（`target` = kp / word / card）。
- **一种学习方式 = 掌握模型 + 记忆模型 + 每日计划策略 + 参数**，写在 `app/methods/profiles.toml`。现在有三种：
  - 均衡（默认）：检索练习 + 间隔复习 + 交错练习 + 掌握学习。
  - 先学牢再往前：掌握学习，标准更严（90%、3 天），先补前置，不预习。
  - 考前冲刺：高频考点和薄弱点优先，复习更勤（保持率 90%），不预习、不摸底。
  家长在孩子资料页给每个孩子选，管理员在后台设全站默认。
- **掌握状态是算出来的**：`mastery.model` 记着算它的模型指纹（模型 + 版本 + 参数）。换方式、调参数、升级算法后指纹变了，就按事件重放（启动时自动做，换方式时立即做），新方法马上用上全部历史，旧记录一条不丢。
- **扩展的地方都只有一处**：
  - 调参数、加一种学习方式：写 `config/methods.toml`（同名覆盖，新名新增），不改代码。
  - 换一种算法：在 `app/methods/` 写一个实现同样接口的类（掌握模型：`step / judge / missing / needs_work / now_p`；记忆模型：`recall / interval / review`），登记到 `app/methods/__init__.py` 的注册表，在配置里用 `model = "名字"` 引用。
  - 加一类每日任务：在 `app/plan.py` 写一个来源函数，登记到 `SOURCES`，在学习方式的 `plan` 里排上。
  - 加一种题型：在 `app/itemtypes.py` 写一个子类（判分、显示、证据题型、蒙对概率、AI 题整理、前端控件）。
- 单元测试 `tests/test_units.py` 覆盖模型、配置、题型、教材元数据，改算法时先跑它。

### 5.1 掌握度

每个孩子 × 每个知识点一条记录：真懂的概率、记忆稳定性、做题数、正确数、证据、状态（未测 / 薄弱 / 学习中 / 已掌握）、模型指纹。下面是默认学习方式「均衡」的掌握模型（`app/methods/mastery.py` 的 BKT）；实时更新和按事件重放都走同一个纯函数 `step`。

- **真懂的概率**用贝叶斯知识追踪（BKT）估算：按题目的蒙对概率（四选一 25%，填空 / 计算约 5%）和粗心概率（10%）更新，所以选择题答对只加一点，粗心错一次也不会掉到底。题库里大家几乎都对的题，答对算的证据弱一些；大家都错的题，做错算的证据弱一些。点「还不会」是很可靠的证据。
- **遗忘模型**用 FSRS 的记忆公式：记忆稳定性 S（天），隔 t 天还记得的概率 R = (1 + t/9S)^-1。隔得久、R 低时答对，S 涨得多；当天反复答对几乎不涨。现在真懂的概率 = 上次的估计 × R。
- **掌握要交叉验证**：概率 ≥85%，答对过 ≥2 道不同的题，在 ≥2 天里答对过，并且 ≥2 种题型（只有一种题型时换 ≥3 道题）。诊断、摸底答对也只是一条证据，不会直接算掌握。
- **薄弱也要证据**：概率 <35%，并且不同的题错过 ≥2 次或自己点过「还不会」。
- 每日计划里会安排「确认一下」（昨天以前答对过、还差隔天 / 换题型证据的）和「该复查了」（记得的概率掉到 85% 以下的）。取题时优先没用过的题型。
- 推断出来的（同一概念、前置、自评、导入）只给一个概率，不算证据。学习页会显示概率、记得多少、已有的证据和还差什么。

### 5.2 诊断（向后回溯）

1. 取当前学段和上一学段的知识点，每个板块至少挑一个，优先高频点和有现成题的点，共约 8 个起点。
2. 每个点出 1 道题（有现成题用现成题，否则 AI 出题；AI 不可用时让孩子自评「会 / 不太会」）。
3. **做错 → 把它的「必须」前置插到队首继续测，最多追 3 层**；最多 18 题。
4. 报告里区分「断点」（做错、但前置都没问题的点——最该先补）和「需要加强」；答对的点，其前置推断为大概率已掌握。

### 5.3 每日任务清单

每天第一次打开时生成（可点「重新安排」；已经做完的任务即使新计划里没有了也保留打勾）。代码在 `app/plan.py`：每类任务一个来源函数，排哪些、什么顺序、每类几个由学习方式的 `plan` 决定（`fixed` / `flex` / `limits` / `prefer_hot`，`"weak+backfill"` 表示交替）。下面是默认「均衡」的排法，分两部分：

**固定项**（每天都有，不截断——坚持比做对更重要）

| 顺序 | 任务 | 来源 |
|---|---|---|
| 1 | 单词 | 到期的生词/短语/术语卡片，含当天按词表加入的新词（`tracks.kind=words`） |
| 2 | 错题重做 | 到期的错题卡片，最多 8 道 |
| 3 | 英语阅读 | 家长安排的英文读物（`read_en` track，今天读哪一段），否则 AI 短文 15 分钟 |
| 4 | 名著接着读 | 家长安排的中文书（`read_zh` track，按回目/章节接着读），否则中文阅读 15 分钟 |

**学习项**（按每天可用分钟截断，至少保留一项）

| 类型 | 来源 |
|---|---|
| 跟上学校 `sync` | 孩子/家长设置的「正在学」知识点，还没掌握就练（每天最多 2 个） |
| 试卷订正 `paper` | 导入了还没订正完的试卷 |
| 诊断 `diagnose` | 还没诊断过的学科，一次一科 |
| 补弱 `weak` / 补前置 `backfill` | 薄弱/低分学习中的知识点；它的必须前置没掌握就先补前置；两者交替 |
| 回顾小检查 `check` | 学校学过（勾选的 + 以前学段）但系统里还没检测过的知识点，每天轮换一个，限当前学段往前两段 |
| 预习 `preview` | 设置了进度：同一板块里「正在学」之后、前置已学过的下一个；没设置进度：前置已具备的当前/下一学段知识点 |
| 知识点回顾 `review` | 到期的知识点总结卡片 |

完成练习、复习、阅读、诊断、试卷订正时，对应的任务自动打勾并 +1 ⭐。

### 5.3.1 课程进度（个性化推进）

定位：系统的主线是**诊断过去 + 个性化**（补弱、补前置、间隔复习），学校进度只是参考，用来把预习和「跟上学校」对准。没报进度时计划照样按诊断排。

- **按章报，不按知识点**：孩子记得的是「学到第几章」。`catalog.chapters(pack, stage, track)` 把本学段的知识点按 `unit` 分章（整个学段没标 `unit` 的按板块；大纲编号很细的归到大题），上册在前、下册在后。
  `/progress` 上点「正在学」的章，前面的章自动勾「学过」。正在学的知识点 = 这一章里第一个还没掌握的（`engine.set_progress_chapters`）。
  按能力分的课（剑桥英语、IGCSE 中文、统编语文）在包里写 `"progress": "none"`，不问进度。
- **不是每天的任务**：今天页上方一周最多提示一次「这周学校学了啥？」（`engine.progress_prompt`，超过 7 天没更新的课），可以「这周跳过」（`users.settings.progress_snooze`）。
- **自动往前走**（`engine.advance_progress`，排计划时调用）：正在学的知识点掌握了 → 换成这一章下一个；导入的考试卷考到的知识点记为学校教过（`papers` → `engine.mark_taught`），后面的章里有教过的内容 → 正在学的章挪到那一章。
- 每个教材包：当前学段、「现在学校正在学」的知识点（`enrollments.progress_kp`）、本学段已经学过的知识点（`kp_taught`）。
- 「学过」= 以前学段的全部 + 本学段勾选的。系统据此：跟上「正在学」、在学过的范围里往回抽查、顺着前置关系补漏、在同一板块往前预习一步。
- 掌握度（`mastery`）和「学过」是两回事：学过但没检测的会被「回顾小检查」轮到；检测出薄弱的进入补弱和补前置。这样形成一张网：往回巩固、相互补漏、往前推进。

考试日期（`enrollments.exam_date`，在 `/progress` 设置）：设了日期的课由 `plan.src_exam` 安排新内容。离考试超过两周（`engine.SPRINT_DAYS`）时，
把还没学的考点（不在「学习中 / 已掌握」、也没勾过「学过」）按大纲顺序平均分到剩下的天数里，每天几个（上限 `limits.exam`，默认 4）；
最后两周不学新内容，改成把还没掌握的高频考点（`hot`）过一遍。`cert` 学制的课没设日期时，清单第一项提醒设定考试日期（`src_exam_date`）。

### 5.3.2 试卷

`/papers`：拍照（浏览器先压缩到长边 1800px）或粘贴文字 → `llm.parse_paper`（任务名 `paper`，需要能看图的模型）一次完成拆题、作答、讲解、从候选知识点（当前学段往前两段、往后一段）中选 `kp_id`、读出卷面答案和批改痕迹。

- 题目存入 `items`（`source='paper'`），卷子和每题的原卷对错、在线作答存 `papers` / `paper_items`。
- 原卷判错/扣分的题：记一次 `exam` 作答（计入掌握度）并进错题本。
- 在线重做：自动判分或自评，可点「还不会」；觉得 AI 答案不对可以标记，这题不计入诊断；知识点对得不准可以手动改。
- 诊断：按知识点汇总原卷丢分和重做结果；重做还错/还不会的是「要补的」，并列出没掌握的前置；原卷错但重做对的列为「可能粗心」。

### 5.3.3 划词查词插件

`extension/` 是 Chrome MV3 插件。孩子账号在「查词工具」页生成连接码（`api_tokens`，只存 sha256），插件用 `Authorization: Bearer` 调 `/ext/me`、`/ext/lookup`、`/ext/save`。加入的词成为 `word`/`phrase` 卡片，进入每天的「单词」任务。下载的 zip 会自动写好服务器地址。

### 5.4 一个知识点的学习步骤

看懂（说明 + 关键词 + 可选「AI 一步步讲」）→ 记方法 → 做 3 题（从易到难，每题有提示；连错两题提示退一步补前置）→ 一句话总结（变成复习卡片）。页面下方同时列出「往回：前置知识」和「往前：后续知识」。

### 5.5 间隔复习

卡片类型：生词、术语、错题（做错自动加入）、知识点总结。**复习要作答、由系统判对错**，不靠孩子自评「记得 / 模糊」（`app/recall.py`）：

- 错题：原题原样重做（选项齐全，标出上次选的）。做错 → 明天再做；隔天连续做对 2 次 → 换一道同知识点的变式题（不同组），也做对了才过关（`extra.passed`，不再到期）；找不到变式题的隔天连续做对 3 次过关。
- 生词 / 短语 / 术语：刚学的看意思四选一（干扰项来自自己的生词本，不够从词表补），复习过 2 轮以上看意思写单词（拼写）。
- 知识点卡：从题库取这个知识点的一道题来做（不现场让 AI 出题）。
- 出不了题的（意思还没查到的词、找不到原题的旧错题、题库没题的知识点）才退回翻面自评。

按学习方式的记忆模型排期（默认：下一次复习排在「记得的概率」降到 85% 的那天，「考前冲刺」是 90%）；「忘了」当天再来，稳定性回落。单词摸底四选一认出来的词，三天后会换成「看中文写英文」复查，写不出来就不算认识。

### 5.6 阅读

- 来源：AI 按年级写略高一点的短文（i+1），自动嵌入孩子最近要复习的生词，附 3 道理解题；或者粘贴自己的书/课文。
- 英文：每个单词可点；中文：选中字词查询，点句子可问「这句什么意思」。
- 查词结果贴合原句意思；可一键收藏（带原句进入复习）、用它造句（AI 先表扬再指出一个最重要的问题，给改正句和示范句）。
- 读完打卡记录时长和理解题结果。

### 5.8 自动发现问题（`app/insights.py`）

每次生成计划时检测一遍，结果存 `insights` 表（新出现的插入，还在的更新，消失的标记为已解决）：

| 类型 | 信号 | 变成的任务 |
|---|---|---|
| root 根源前置 | 两个以上没掌握 / 最近做错的知识点，共用同一个没掌握的必须前置（往回 3 层） | 补根源 |
| dont_know | 14 天内同一知识点点了 2 次以上「还不会」 | 再练练 |
| asked | 同一知识点问了小助手 2 次以上 | 再练练 |
| slow 做对但慢 | 做对的题平均用时超过 60 秒且超过孩子自己中位数的 2 倍（`attempts.ms`） | 再练练 |
| forget_words / forget_kp | 卡片复习「忘了」2 次以上 | 单词任务里重点复习 / 再练练 |
| lookup_repeat | 同一个词查了 2 次以上还没收藏 | 自动加入单词本 |
| decay 久未复习 | 已掌握但 30 天没练、在学过的范围内 | 回顾小检查 |
| careless | 试卷原卷错、在线重做对 | 提醒考试检查 |
| habit / reading_gap（只给家长） | 近 7 天学习天数 ≤ 4；某本书 4 天没读 | — |

计划里，最重要的一条排在「跟上学校」后面且不会被时间截掉；其余的排在补弱 / 补前置 / 回顾小检查各自的最前面，任务说明带 🔍 和发现的原因。孩子在「今天」页看到对自己有用的几条，家长页和学习报告里能看到全部。

### 5.9 摸底探索：解决冷启动（`app/explore.py`）

孩子不管几年级进来，过去几年的知识点掌握情况系统都不知道。不靠一次长考试，而是每天穿插少量「以前学过的」小题，让个性化快速收敛：

- **范围**：每个教材包里当前学段之前的知识点，加上本学段学校已经教过的（`past_range`）。
- **选题**（`candidates`）：在范围里的未测知识点中，按信息量打分：`2 × 未测的必须前置数 + 被范围内未测知识点依赖的次数 + 4（和学校正在学的有关）+ 2（高频）`。答对一题能推断一串前置，所以优先测「高处」的点；各学科轮流；一周内测过的不再抽。
- **作答**（`after_probe`，attempts.mode = `probe`）：答对记为掌握，2 层以内未测的必须前置记为「推断掌握」（source = inferred，score 0.65）；答错 / 还不会记为薄弱并进错题本，它没掌握的必须前置进入 `probes` 队列（最多往回 3 层），之后优先测。
- **投放**：每日清单最前面的「热身」（`/warmup`，3 道知识点题 + 2 个旧单词，约 4 分钟）；知识点练习的第 2 题穿插一道这个知识点没测过的前置（`/api/practice`）。
- **英语旧单词**：从孩子年级及以下的核心词表抽词四选一（干扰项来自同一词表），优先测得少、离当前年级近的词表；不认识的自动加入单词复习；按词表认识率（拉普拉斯平滑）估算词汇量，测满 10 个后显示。
- **可见**：「今天」页「我的学习地图」（每科摸清百分比、今天点亮的知识点、词汇量估计）；家长页同样显示。
- **前方**（`ahead`）：每科的下一站（进度之后的下一个，否则当前学段第一个未学的）、必须前置准备了几个、还差哪个、学会后能学什么。
- **点亮**（`lights` 表）：一个知识点第一次变成「已掌握」时记一笔，答题结果里返回 `lit`，前端放礼花。

### 5.10 网站内划词（`app/static/app.js` 的 `SelMenu` / `QuickLook`）

孩子账号在网站任何页面选中文字（输入框、阅读器除外，阅读器有自己的点词查询）弹出菜单：查词（短词）/ 翻译（句子，`/api/translate`）/ 加入复习（`/api/collect`，AI 查好意思再存）/ 问小助手。
自动记录规则（`_auto_collect`）：同一个词或句子查第二次，或在题目上划词查的，直接加入复习卡片，extra 里记 `why`。
「阅读 → 打开一篇网页文章」：服务器只抓公网 http/https（每次跳转都重新检查 IP，拒绝内网 / 本机 / 保留地址），限 3 MB、12 秒，只取正文段落（`app/webpage.py`）。

### 5.7 问一问小助手（引导式提问，默认名「小艾」，`.env` 里 `ASSISTANT_NAME` 可改）

孩子页面右下角常驻按钮（诊断页除外）。前端带上当前上下文：孩子最近点过 / 屏幕上的那道题（`renderItem` 给题目框标 `askable` 和题目 id）、是否已作答、选中的文字、页面标题、知识点。
服务器取出题目的正确答案和讲解，作为「只给小艾参考、绝不能说出」的内容放进提示词（`llm.ask_tutor`，任务名 `ask`）。
回复要求：苏格拉底式，一次只推进一小步、以问题结尾；连续卡住就退回更基础的知识；模型自报 `reveals_answer` 为真时重新生成一次。
对话存 `ask_threads` / `ask_messages`，同一道题接着问，换题自动开新对话；家长在学习报告里能看到。计入每个孩子每天的 AI 次数上限。

### 5.11 跟自己比（`app/records.py`，前端 `Run`）

目标是让孩子越学越想学，而不是堆功能：只跟自己比，没有排行榜、积分商城、抽奖。

- **一组（run）**：热身、单词复习、错题重做、知识点回顾、知识点练习、阅读，每做完一组 `POST /api/run` 记一笔（`runs` 表：题数、答对、专注毫秒、总毫秒、最长连对、破了哪些纪录）。服务端会把数字收在合理范围内。
- **专注计时**：只在页面可见、而且最近 60 秒内有点击、打字或滚动时才计时。
- **个人最好（PB）**：每类任务比答对最多、最长连对、每道答对的题平均用时（只在热身和三种复习上比，因为这些是学过的内容）；最长专注跨所有任务比。正确率低于 80% 的一组不算答对和速度纪录。每类任务的第一组只立纪录，不算破纪录。
- **上周的我**：过去 7 天（不含今天）这类任务每道答对的题平均用时。进度条上的 👻 按这个速度前进，🏃 是答对的题数。
- **每周进步卡**：上周（周一到周日）和再上一周比，只列进步的地方（更快、正确率更高、点亮几个、破几次纪录、专注多少分钟），最后总是写学了几天、做了几道。上周没学就不出卡。周一在「今天」页默认展开，家长页一行显示。

### 5.12 乐园：按个人水平出题的游戏（`app/arena/`、`app/quickgen.py`，前端 `app/static/play/`）

**第一原则：PK 比的不是知识，也不是谁做同样难的题，而是当下学习的专注和投入。** 每个孩子拿到的题难度不同、答对的概率相同；在这个前提下谁更投入，谁赢的机会更大，学习效果也更好。战报、贴纸、胜负都围绕这一点设计。其次：游戏本身要好玩、可爱，学习是游戏的燃料；只奖励真实发生的事（专注、答对、坚持、点亮知识点），不做排行榜、抽奖、积分商城。

**专注指数**（战报里最显眼的数，`matches.focus`）：实际答对题数 ÷ 预期答对题数（每题出题时预测的答对概率之和）× 100。100 是正常发挥，高于 100 是比平时的自己更投入；3 秒内答错算「猜」，单独提醒；一局答题少于 3 道不算。乐园首页显示本周专注指数，家长页也能看到。

**在产品里的位置**：孩子底部导航五项「今天 · 学科 · 🎮乐园 · 阅读 · 记录」，乐园在正中间凸起，是学完以后的奖励。复习和单词本从「今天」进（今天页顶部有复习、单词本、乐园三个快捷入口；复习本来也是今天任务的一部分），乐园入口直接显示「再完成 N 项任务就能玩 / 今天还能玩 N 分钟」。乐园首页：我的角色和乐园等级、三款游戏、角色墙、贴纸墙、为什么公平。

**后端分层**（`app/arena/`，从下往上，每层只做一件事）：
- `fair.py`：能力值 θ、难度 b、答对概率 p = 1 / (1 + e^-(θ − b))，Elo 式在线校准，按目标答对率选级别。只管数学。
- `sources.py`：题从哪来。每种题源回答「能不能用、占多少」「出一道答对概率接近目标的题」「答完怎么记」。现有三种：
  - `math`：沪教版一到六年级口算、短计算，按题族现场生成（`quickgen.py`），答案由程序算出，题目 id 是 `gen-<题族>-<指纹>`，不进 `items` 表；
  - `words`：英语核心词（`content/words_en.json`，按年级分 1–5 级）、教材术语词表，加上孩子自己生词本里的词（三成），四选一认词义，题目带朗读文本；答错的词进生词本；
  - `bank`：题库里孩子学过的知识点上的短选择题（题干 ≤ 90 字、选项 ≤ 36 字），任何学科都能用，级别按这道题全体的答对率定。
  - 题不让孩子选：`sources.pick(kid, target, rng)` 按这个孩子在学的科目和每个知识点的掌握度挑题源和知识点（学数学的孩子数学多，高年级少出口算；学习中、薄弱的多出），难度按他自己的 θ 定。一起玩的孩子各开各的对局、各答各的题，水平差得再远也各自答得上。加题源只要写一个 `Source` 子类登记到 `SOURCES`。
- `rules.py`：每天能玩多久、什么时候解锁、学习换时间、能量（局内经验值）、冷冻。
- `awards.py`：贴纸、角色、乐园等级。
- `matches.py`：每个孩子自己的答题对局（开局 → 出题 / 作答 → 结束个人战报）。
- `games/`、`progress.py`、`sessions.py`、`rooms.py`、`bus.py`：游戏平台（游戏登记、队伍进度、对局记录、房间和设备、实时转发），见 5.26。
- `board.py`：管理后台的公平看板。

**公平的出题**（IRT / Elo）：θ 按「孩子 × 能力维度」存（`arena_ability`，维度是知识点 id 或 `vocab:en`、`terms:<词表>`），b 按（题族, 级别）存（`arena_calib`）。θ 起点取自掌握度（没做过的按学段估），每答一题更新，新孩子步子大；b 由全体孩子的作答校准，步子小。选级别时在答对概率刚好高于、刚好低于目标的两级之间按比例混着出，平均正好是目标（火柴人 75%、赛跑 80%、守城 72%；选择题再加 5%，抵消蒙对）。`tests/test_smoke_arena.py` 用模拟验证：真实水平差很多的孩子答对率都在目标附近。

**学习和游戏的关系**：
- 解锁：家长在「编辑孩子」里选什么时候可以玩：随时 / 做完今天一半的任务后（默认）/ 做完全部任务后（`users.settings.game_unlock`）。今天没有任务时直接能玩。
- 时长：基础每天 0–60 分钟或「不限时」（默认 20，`settings.game_minutes`，不限时存 -1：不封顶、不倒计时、不算奖励时间，解锁规则照常）；今天任务全部做完 +10 分钟，今天每点亮一个知识点 +2 分钟（最多 +6），冲刺每 20 分 +1 分钟（最多 +10，见 5.14）。按每局开始到结束的时间算。
- 证据：游戏里每次作答照常进 `attempts` / `events`（mode = `game`），作为掌握度证据**打对折**（限时作答，手快手慢不该误判）；不计入学习打卡和学习分钟，不参与「做得慢」的自动发现，也不进题目的用时统计；做错的题不进错题本（单词例外，进生词本）。
- 战报：每局结束告诉孩子这局练了哪些内容（每个知识点 / 词表答对几道）、能改进的地方（能量长时间是 0、瞎猜太多等）、乐园等级进度。

**奖励**（都是确定的，不靠运气）：
- 能量：局内答对得 70–150（8% 暴击翻倍），只在这一局里用来出招、换武器，局结束清零，不跨局积累、不能买东西。
- 贴纸（`arena_awards`）：19 张，每张对应一件真做到的事：一局专注指数 120 以上（超级专注）、第一次进乐园、第一场胜利、一局连对 5 / 10 题、答对率 90%、一局不瞎猜、累计答对 50 / 200 / 500 题、赛跑赢了「上次的我」、守住第 5 波、打败大怪兽、先做完全部任务再来玩、连续学习 7 / 30 天、真正掌握 3 / 10 / 30 个知识点。后几张来自学习本身，进乐园首页时补发。
- 角色：4 个一开始就有，8 个要某张贴纸解锁（比如「坚持一周」解锁猫猫，「点亮 10 个」解锁魔法师），存在 `settings.avatar`，所有游戏里都用这个角色。
- 乐园等级：累计在游戏里答对的题数，第 n 级要 5·n·(n−1) 题，越往后越慢。

**三款游戏**（前端只写玩法）：
- 🥋 火柴人大战（目标 75%，30 关闯关，见 5.15）：走、跳、出拳都耗能量，能量只靠答题补；点「答题」时整个游戏暂停；3 连击、必杀（每连对 3 题攒一次）、用能量换木棍 / 护盾 / 剑 / 激光；电脑也按 75% 的答对率「答题」，答错同样被冷冻。
- ⚡ 闪电赛跑（目标 80%）：答题面板常驻下方，答对冲刺一段、连对加速，答错原地冷冻；跟「上次的我」（上一局的完成时间，半透明影子）赛跑，只跟自己比。
- 🏰 星星守卫（目标 72%）：小怪兽一波波走向城堡，答对放星星魔法打怪，连对放大招，第 5 波后出大怪兽。

**前端**（`app/static/play/`）：`engine.js`（舞台适配高清屏、主循环、粒子特效、合成音效和背景音乐、场景、输入、倒计时和提示）· `art.js`（矢量画的角色、怪兽、城堡，12 个角色同一套骨架，姿势和表情可换）· `quiz.js`（答题面板 `ArenaQuiz`：弹出或常驻两种，大号彩色选项、数字键盘、朗读、答对彩带、冷冻倒计时）· `shell.js`（所有游戏共用的外壳，见 5.26）· `<游戏>.js/.css`。加一款游戏见 5.26。

**公平看板**（管理后台「游戏公平」）：按孩子已掌握的比例分 4 组，对比各组的预测答对率、实际答对率、每分钟能量、打赢电脑的比例；下面列出每个（题族, 级别）校准后的难度。

### 5.14 坚持和冲刺：小节、保底、补签卡、冲刺倍数（`app/streak.py`、`app/sprint.py`）

要解决两个问题：一小时坚持不下来怎么办；学有余力的孩子想继续往前冲怎么办。仍然只跟自己比，不做排行榜、积分商城、抽奖。

- **小节**：今天的任务按顺序切成 10–15 分钟一节（凑满 12 分钟或 3 项成一节，最后剩得太少并进上一节）。今天页顶部一节一格，任务清单按节分组；学完一节弹出「第 N 节完成！」，可以选「☕ 休息 3 分钟」（倒计时 + 伸懒腰、看远处的小提示）或直接继续。
- **保底**：做完第 1 节就保住今天的连续天数（今天没有任务时学满 10 分钟）。连续天数从 2026-10-08 起按保底算，只打卡、开着页面不再算；以前的日子沿用老规则，已有的连续天数不受影响。
- **补签卡**（`streak_freezes`）：连续天数每满 7 天得一张，手里最多 2 张。哪天没达到保底，第二天打开「今天」时自动用卡补上（缺几天就要几张，不够就不用），补上的那天不加天数、日历上标 🧊。只有孩子自己打开时结算，家长查看不结算。
- **每日目标**（`users.settings.goal`）：孩子自己选 轻松（保底）/ 认真（全部任务，默认）/ 冲刺（全部任务 + 冲刺 50 分）/ 超神（+150 分），今天页显示进度条，达成撒花。
- **冲刺**（`/sprint`，`sprint_runs`）：今天的任务全做完后开放（没有任务直接开），题目不限量。出题和乐园共用 `app/arena/sources.py`（目标答对率 80%，θ 共用，所以越冲越难）。
  - 倍数 ×1 → ×2 → ×3：连对 5 题到 ×2，再连对 7 题到 ×3；答错降一档不清零；3 秒内答错（像在猜）回到 ×1；一题拖了 1 分钟以上降一档；「这题不会」不降档也不加分。
  - 每答对一题得「答题时的倍数」分。冲刺分只用在三处：每天每 10 分换 1 颗 ⭐（算进累计星星）、每 20 分乐园多玩 1 分钟（每天最多 +10）、每日目标。个人纪录是冲刺分最多的一天；周一进步卡写「冲刺了多少分，比再上周多多少」；家长页显示本周冲刺分。
  - 作答记进学习记录（mode = `sprint`），掌握度证据记 0.75；和游戏一样不进题目用时统计、不参与「做得慢」的发现。
  - 休息：连续冲 20 分钟、或今天一共学满 90 分钟，各提醒一次休息；今天页学满 90 分钟时也提示。冲多少都不影响第二天的任务量。
- 答题面板沿用乐园的 `ArenaQuiz`（`base` 换成冲刺接口，`dontKnow` 加「这题不会」，服务器回 `freeze_ms: 0` 时答错不冷冻，看懂答案再点下一题）。

### 5.15 火柴人闯关（`app/arena/games/stickman.py`，前端 `stickman.js`、`shell.js`）

家长试玩后的反馈：只有一局没有关卡，没理由明天再来；电脑太好打，根本用不着答题；弹出答题时游戏没停，怪还在打。

- **地图**：5 个世界 × 6 关（草地擂台、黄昏山谷、糖果城堡、星空屋顶、火山之巅），每个世界第 6 关是大怪兽。过关才开下一关，进度存在 `game_runs`（一个人一队；每关最好的星星数、打了几次、第一次过关的时间，见 5.26）。游戏页的开始面板就是地图，一个世界一页；战报里有「下一关」。
- **星星**：每关最多 3 颗：过关、专注指数 ≥ 90、血量剩一半以上。输了不扣，只记最好的一次。乐园首页显示打到第几关、一共几颗星。
- **越往后越难的是游戏，不是题目**：电脑的血量、伤害、速度、出手、躲闪、格挡、答题快慢都按关卡从第 1 关到第 30 关线性变强（参数在 `Stickman.params`，按关数和已打通的世界现算，开局时发给前端）。题目难度不跟关卡涨，一直按孩子自己的水平出，公平不变。
- **不答题赢不了**：能量只从答题来，开局只给一点（第 1、2 关 260 / 200，之后 120），不会自己回；出拳一次 15。第 1、2 关能量会慢慢回到 100，让孩子先学会玩；从第 3 关起，不答题打不过。
- **大怪兽护盾**：没破盾时只吃 1/4 伤害；答对 3–5 题（越往后越多）碎完护盾，接下来 8 秒伤害 ×1.5，然后护盾长回来。
- **暂停按钮**（所有游戏，外壳 shell.js 管）：右上角 ⏸ 谁都能按，大家屏幕上都显示「XX 暂停了」；谁都能点继续（不怕暂停的人走开或掉线），所有人一起倒数 3-2-1 再开始。暂停时游戏循环停住（`Play.frozen`）、这一关的用时停住，也不算今天玩游戏的时间（`/api/arena/{match}/pause`，各自的对局记 `paused_s`）。
- **答题暂停**：弹出答题时整个游戏停住（画面蒙一层淡蓝，写「时间停止」），怪不动、不掉血、不计时；答错的冷冻照旧。闪电赛跑和星星守卫的答题面板一直在下方，答题本身就是操作，不需要暂停。
- **世界奖励**：打通第 1、2、3 个世界分别解锁装备店里的护盾、剑、激光；打通第 4 个世界解锁超级必杀；30 关全通得「火柴人大师」。贴纸：闯过第一个世界、一共 30 颗星、30 关全通。
- 难度目前只按推算设定，等孩子真玩一段时间后，按各关的通过率和星星数调参数；先在火柴人上验证，再推到另外两款。

### 5.16 一路做下去：每天的主线和统一的题目展示（`engine.flow_state`、前端 `Flow`、`itemtypes.view`）

- **主线**：每天的清单按「先易后难再放松」排（`profiles.toml` 的 fixed → flex → tail）：热身（几道小题进入状态）→ 错题重做（旧账先清）→ 单词 → 学新的、补弱的、回顾检查 → 阅读收尾（大量输入）。做完以后才是冲刺和乐园。第 1 节（保底）正好是热身 + 错题 + 单词这类「保持记忆」的小任务。
- **统一入口**：今天页只有一个大按钮「开始今天的学习」，指向 `/go`：直接进第一项没做的。任务页面顶上有一条「今天 3/8 · 第 n 项：…」，可以回清单，也可以「先做下一项」（`/go?after=tN`，只换顺序、不打勾，后面做完了会回头找它）。
- **做完接下一项**：每一项做完，接口都返回 `flow`（今天做到哪、下一项、是否刚学完一节、是否全部完成），页面底部弹出小卡「✓ 完成一项 · 下一项：…  [继续 →]」。刚做的题和讲解留在页面上：做错了先看清楚再走。学完一节可以休息 3 分钟；全部完成给冲刺、乐园和一日记录的入口。新的任务类型只要做完时调 `finishTask` 或在接口里返回 `engine.flow_state`，就自动串进来；以后在两项之间插一个小步骤（比如卡住时的溯源小测），也是在这里接。
- **每日阅读**：任务入口是 `/reading/today?lang=`：今天读过、生成过的那篇直接打开（没读完的优先）；还没有才进写文章的工具。今天写的那篇没读完时再点生成，会回到那篇（可以「换一篇」）。交卷的答案存在 `readings.answers`，再进来直接看到自己的答案、对错和解析。
- **错题回来**：正式练习、诊断、摸底、试卷、知识点回顾做错的进错题本；游戏和冲刺里题库的题，认真想了（超过 3 秒）还错或点了不会的，也进。过关后 21 天再回头做一次原题，还会才算真正掌握。
- **题目的统一展示**：一道题只有两种样子，数据都来自 `itemtypes.view(item, mine, with_answer)`：
  不带答案（出题）：题干、选项 A B C…/输入框；带答案（判完、错题本、订正过的卷子、读完的阅读小题）：选项上标「✓ 正确答案」「我选的」，下面分栏写 答案 / 我的答案 / 解析 / 要点。
  服务端用 `_ui.html` 的 `question` 宏，前端用 `app.js` 的 `renderItem`（作答）和 `qView`（带答案），样式同一套（`.qc*`）。判题接口都用 `itemtypes.reveal(item)` 返回答案部分。

### 5.17 追根：卡住了当场找「为什么不会」（`app/trace.py`，页面 `trace.html`）

一个知识点不会，常常是因为过去某个点没懂。以前的做法是错一次就把前置排进摸底队列，隔天才在热身里出现，孩子感觉不到因果；现在改成卡住时当场几道小题找到根。

- **触发**：同一个知识点今天在练习 / 诊断 / 考试 / 试卷里错第二次，或者点了「这道题还不会」（错一次可能是粗心，不触发）。一天最多两次，同一天同一个点只追一次。答题结果里返回 `trace`，学习页显示「🔍 找找根在哪」。
- **最多 4 道小题**（`MAX_STEPS`），像二分查找一样往回走：
  1. **错项指向**：出题时 AI 给选择题的错误选项标「选它说明哪个前置没懂」（`items.data.traps`，`{"错项下标": 前置 id}`，不发给前端）。孩子选的错项直接把那个前置排到最可疑。
  2. **中文再问一次**：英文授课的非英语学科（IGCSE 物理等），卡住的那道题没有中文翻译时，先找一道带中文的同知识点题用中文问。中文会、英文不会 → 根在术语：这个点的术语卡今天复习（没有就从讲解里取英文 = 中文加卡片）。
  3. **嫌疑打分**（`suspects`）：必须前置（往回 3 层）、直接前置、跨学科「要用到」的知识（物理用到的数学）。薄弱 5 > 没测过 3 > 只是推断会 2.5 > 学习中 2 > 学会了但按遗忘规律快忘了 1.5（记得牢的不怀疑）；必须 +1.5、每深一层 −0.8、错项指向 +6、好几个正卡住的点共用它最多 +3。
  4. **测最可疑的**：答对就排除它和它下面整支（并推断它的前置会）；答错就把它当新的卡点，下一题从它的前置里挑。
- **结论**（`finish`）：最后一个答错的就是最深的根 → 今天清单里没做的任务最前面插「追根：先补 X」和「再战：原来的点」；前置都没问题 → 「换个讲法再学：原来的点」（是这个点本身没学会，不往前甩锅）；中文会 → 「术语过关」。这些任务每天排计划时也从 `trace.today_tasks` 来，重排不会丢；根掌握了就不再出现。
- **可见**：追根页是一条链（卡住的点 → 测过的前置，✓ 绿 / ✗ 橙，根加粗）；「系统发现」里有「X 卡住，根在 Y」和整条链，家长页能看到，根没补上之前会一直排「补根源」。
- 追根的题按摸底记（`attempts.mode = probe`），答错不再排进摸底队列（这里已经自己往下追了）。每次追根的结果存在 `traces`，以后用户多了可以拿来校正前置关系（哪条边真的有影响）。

### 5.18 边学边校正过去的知识（`explore.candidates`）

孩子不管几年级进来，过去的知识点不是「测一次就完」：没测过的要摸底，只是推断会的要确认，学会很久的会忘。热身（每天 3 道）和每组练习 / 预习的第 2 题都从这里挑：

- **相关性优先**：正在学的知识点要用到的旧知识（必须前置 3 层 + 跨学科「要用到」）、今天清单里要学的知识点用到的（「今天要学的 X 要用到它」，只读已排好的清单）、学校正在教的内容附近的。
- **覆盖面**：每个学科按知识线（strand）和学段算「摸清了多少」，摸得少的地方加分，慢慢把过去各年级、各板块都过一遍，而不是一直在一处打转。
- **推断的要确认**：答对一题会推断它的前置「大概会」（source = inferred）。这些推断的点和正在学的有关、或所在的板块摸得少时，也会被抽出来测一次，确认真的会。
- **快忘了的**：学会过、按遗忘规律现在记得的概率掉到目标保持率以下的，也会穿插进来（今天要学的内容用到的排更前）。
- 预习新内容时也穿插一道它的前置（地基不稳先知道）。
- **家长页**「按年级看摸清了多少」：每科每个学段已测 / 共多少、其中推断的、薄弱的。

### 5.19 题目配图（`app/figures/`）

图是题的一部分：存在题目的 `fig` 字段里（items.data），和文字一起存一次、反复用；去重哈希也算上图（文字一样、图不一样是两道题）。两种来源，显示方式一样：

- **画出来的图**：AI 不直接画图，而是写「画图说明」（点的坐标、连哪些线、电路里有哪些元件……）。`figures.normalize` 检查说明，几何图里题目给的长度、角度、平行、垂直写在 `checks` 里由程序核对；画不出来或对不上，`itemtypes.normalize` 返回 None，这道题直接不要（图文不符的题宁可没有）。页面上按说明现场画成 SVG（线条用 currentColor，深色模式自动变色），结果按说明缓存。给前端的只有画好的图，说明本身（可能含答案）不下发。
- **原卷上的图**：试卷 / 卷库导入时 AI 报告图在第几张照片、框的位置（千分比），`figures/photo.py` 裁下来按内容哈希存在 `data/figs/`（几道小问共用一张图只存一份）。上传的照片先按拍照方向摆正、太大的缩小，AI 看到的和裁图用的是同一张。裁歪了在试卷页「✂️ 调整图」重新框或去掉（家长、孩子都能改；卷库由管理员改）。孩子卷子上的图只给本人、家长和管理员看（`/fig/<题目>/<文件>`）。
- **种类**（各自一个文件，`@register` 登记，只给 `subjects` 里的学科的出题提示词带上写法）：plane 平面图（几何、方格、受力、光路）、solid 立体图形（斜二测，看不见的棱自动虚线）、graph 坐标图像 / 函数 / 数轴、chart 条形 / 折线统计图、clock 钟面、scale 刻度读数（尺、量筒、温度计）、circuit 电路图（按电流顺序写元件和并联支路，自动排版）、lab 化学实验装置图（固定几套课本装置：加热 / 固液制气体配三种收集方法、过滤、蒸发、蒸馏、滴定、电解、纸层析；AI 只选装置和给部位标字母，不自己摆仪器，免得画得不像）、photo 原卷裁图。加一种图 = 加一个文件，出题、校对、显示都不用改。
- **哪些知识点要多配图**：每种图有 `cues`（关键词），`figures.wanted_for` 拿它对知识点的名称、说明、关键词；对上的知识点出题时要求一组题至少一半带图，题库里一道带图的都没有时 `engine.items_for` 补一批（只补一次，见 `FIG_PROMPT_V`）。配图本身仍是可选的：不需要图的知识点照常出纯文字题。
- **AI 校对 / 改编**：校对时把画图说明（或原卷图的文字描述）一起给 AI；家里卷子改编进公共题库时，原题有图的必须按描述重新画，画不出来就不改编，原卷照片不进公共题库。
- 游戏（乐园）里不出带图的题。图做选项（「哪个图像表示匀速」）还没做：选项目前只有文字。

### 5.20 听力：题目录音（`app/audio/`）和先听后读

和配图并列的一类「题目素材」，接口一样（normalize / present / describe / prompt_for）：

- **录音存的是稿子，不是音频**：题目的 `audio` 字段 = `{lang, lines: [{who, text}], plays}`，who 是角色（N 旁白 / F 女 / M 男 / C 孩子）。播放时前端一句一句交给朗读服务，按角色用 `config/tts.toml` 里 `[roles.<语言>]` 配的声音（没配用默认声音；浏览器自带朗读时用音高区分），第一次读完的音频缓存复用。稿子不合格（空、太长、太多句）这道题就不要；去重哈希算上录音。
- **作答前只听不看**：页面上只有「🔊 听录音」，最多听 `plays` 遍（默认 2，和 IGCSE 一样）；答完 `itemtypes.reveal` 带上 `transcript`，「带答案」的几栏里显示听力原文，录音不再限次数。稿子随题目下发给前端（浏览器自带朗读要用），只是不显示。
- **哪些题带录音**：教材包里板块标 `"audio": true` 的知识点（英语「听说」板块），出题提示词才带录音写法；校对、改编时稿子一起给 AI，听力题改编后也必须是听力题。游戏里不出带录音的题。
- **一段录音配几道题**（IGCSE 听力第 3、5 部分）还没做：现在一道题一段录音（第 1、2 部分的短录音）。长一点的听力先用阅读页的「先听后读」：英文短文、每日新闻可以盖住原文只听、做小题，交卷后再看原文，交卷时原文没打开过记 `readings.mode = listen`。
- **单词听写**：单词复习熟到第 3 轮以后，拼写和听写（只给读音）轮换（`recall.DICTATE_FROM_BOX`）。

### 5.21 页面的视觉重心：每页一个主角

孩子打开页面应该一眼知道「点哪里」。规则：每页只有一个实心主按钮，其余入口降成浅色按钮或文字链接；内容分三层。

- 今天页：第一层是「下一项」主卡（下一项的名字、为什么做、一颗大按钮 → `/go`；全部做完时换成「去打卡」或「来冲刺」）。第二层是任务清单（不再在行里重复「开始」按钮）。第三层是复习 / 单词本 / 乐园 / 冲刺入口和一日记录（心情打卡），电脑上也是整行往下排（见 5.35）。地图、前方、纪录、目标、这一周放到最下面的「看看我的进步」安静区（无阴影、标题小一号）。最近四周日历去掉，看「记录」页的热力图。
- 学科页：学科卡片整张可点（去知识地图），按钮都降成浅色；「学校学到哪了 / 模拟考 / 导入试卷」挪到下面的「工具」一层。
- 乐园页：游戏卡片是主角，贴纸墙收起来点开再看。
- 记录页：心情列表只显示最近 7 天，更早的点开看。
- 家长页：每个孩子先看今天（完成项数、分钟、连续天数，整块点进清单），再看系统发现；入口一排小链接，只有「学习报告」是实心按钮；「添加孩子」降为次要按钮。
- 答题卡：「提交」是唯一主按钮；「💡 提示」是浅色按钮，跟在提交后面；「🤔 这道题还不会」是文字按钮，放在同一行最右边（`renderItem` 的 `dontKnow`，小测页叫「不会，跳过」，点了直接下一题）。不在题卡外面另加描边按钮；「先到这里，看结果」这类离开的入口也用文字按钮。

### 5.22 孩子看到的文案：用孩子的话

界面上的字是在跟孩子说话，不是在描述孩子。孩子能看到的页面、任务标题、「发现」、战报和 AI 讲解都按这几条写：

- 说这件事对孩子意味着什么、下一步做什么，不说系统怎么判断他。不出现「系统」，由陪伴角色（小艾）来说。
- 不用家长和老师的术语：诊断→小测，前置→要先会的 / 基础，薄弱→还不稳，掌握度→不显示或叫「把握」，保底→第 1 节，专注指数→专注值。
- 描述状态，不打分：任务说明里不写百分比，状态标签后面也不跟分数。
- 一种口吻照顾两个年龄：平实、短句、像学长学姐，不用「小朋友」、叠词和一串感叹号。AI 生成的内容按年龄换口吻（`app/llm/tasks.py` 里的 `VOICE_PRIMARY` 和 `VOICE_TEEN`）。
- 家长页和管理后台用准确的成人用语。家长和孩子共用的页面（比如记录页）用 `report_for` 区分。
- 管理后台导航（`_admin.html`，组在 `app/web.py` 的 `ADMIN_NAV`）是一张整齐的表：每组一行，左边是组名，菜单项放进等宽格子（电脑每行 5 格，手机 3 格），上下对齐，不按字数长短排成大小不一的胶囊。当前页是填满格子的品牌色块。

### 5.23 学校进度按校历推演 + 每门课一组混合练习 + 跟着新知识往回找

家长的反馈：孩子从来不主动报学到哪了；每天做的题差不多，总围着「正在学的 + 做错的」。原因在代码里：学新知识的任务每个只有 3 题、被每天时长截到两三个；进度不报就停在原地；以前的知识测对一次就不再出；往回只在报名的那几本教材里找。讨论稿：项目文件 `aistudy/docs/进度推演与每日练习-讨论稿.md`。

**学校进度按校历推演**（`app/schoolyear.py`，校历 `curricula/_meta/calendar.json`）
- 校历写「月-日」每年通用：上海两学期（9/1–1/20、2/16–6/30，国庆等不上新课，每学期最后两周复习），国际学校三学期。学制决定用哪份。
- 这一学段的章按上新课的天数铺开、每个知识点占一样的天数：分上下册的第一学期铺上册、第二学期铺下册；不分册的整学年铺；两年的课程（学段 year 是 x.5，如 IGCSE）按孩子的年级算第几年。大章里也按日期往前走到具体知识点。
- 推演到的位置之前的内容写进 `kp_taught`（`source = inferred`，每天排计划前重算）；孩子 / 家长报的、试卷考到的是 `manual`，考到了后面的内容，进度至少到那里。
- 家长在「学校学到哪了」点「对 / 学校快一章 / 慢一章」或直接点章：存成偏移量（`enrollments.progress_shift`，只在这一学期有效），以后照样按日期往前走。一个月没核对，家长页提示一次。孩子端不再问「这周学校学了啥」。
- 寒暑假、复习周不推新课。

**每门课一组混合练习**（`app/mix.py`，任务类型 `mix`，页面 `/practice/<pack>`）
- 今天页每门课一张「XX 练习 N 题」，取代原来一个知识点一张卡的「跟上学校 / 回顾 / 预习」。题量 = 排完其它任务后剩下的时间平分（每题约 1 分钟，三年级以下 0.8 分钟），每门课至少 10 分钟；时间不够时排在后面的课被截掉，所以每天换一门打头。
- 一组的成分（比例在学习方式 `profiles.toml` 的 `mix` 里调，默认 新 30 / 近期 20 / 往回 30 / 换问法 10 / 预习 10）：
  - 新：推演到的正在学的知识点，分散着出 3～5 次，最后一次是**融合题**；
  - 近期：最近 3 周练过还不稳的，和按遗忘规律到期的；
  - 往回：先是新内容要用到的旧知识，再在最近两个学年里铺开，会了的按遗忘规律长间隔回来；
  - 换问法：答对过但只用过一种题型的、从别的教材推断来的（掌握标准本来就要两种题型，见 `methods/mastery.py`）；
  - 预习：学校下一步要学的，两道入门题。
- 往回最多占一半；往回的比例跟着最近两周摸底题的正确率调（≥85% 少出，<60% 多出，`past_factor`）。
- 一组里做错的（摸底题除外）过几题换一道同类的再来，同一个点最多两次（连续重学，Rawson & Dunlosky 2011）。
- 新内容第一次出现时可以点「先看看怎么做」看讲解（和知识点页同一份讲解）。

**跟着新知识往回找，不一刀切**（`app/ladder.py`，规则 `curricula/_meta/ladder.json`；`explore.candidates`）
- 地基 = 能往回找到哪里的边界：报名教材里更低的学段，加上 `base_packs`（教材从中途开始时，用基础教材补齐更低的学段）和 `builds_on`（物理用到科学、数学）找到的别的教材，到孩子的年级为止。对所有孩子同一套规则。
- 但不是要全部摸一遍：铺开摸底只在最近两个学年里铺；更早的、地基里的，只有是正在学的 / 今天要学的知识点的前置或要用到的，或者答错以后沿前置一层层往回追到的，才出题。一组里这类更早的题最多 3 道。
- 依据：学新知识前先激活要用到的旧知识（Ausubel 1968：影响学习最重要的是学生已经知道什么）；知识空间理论（Doignon & Falmagne，ALEKS 的做法）——先测高层的，答对就推断它的前置也会，答错才往下追，用最少的题摸清；认知负荷（Sweller 1988）——一道题里旧知识太多、一组里补洞太多都会挤掉新知识，所以设上限。

**融合题**（`engine.items_for(purpose="combine")`、`llm.generate_items(purpose="combine")`）：一道题同时要用到新知识点和一两个旧知识点（AI 出、标 `kp_ids`，存进题库复用）。做对：旧知识点各记半条「会」的证据；做错：说不清是哪块没会，不扣旧知识点，把它们排进往回追的队列。

**快练进主线**（`src_drill`、`sprint.start(drill=True)`）：每天固定的「⚡ 快练 5 分钟」，用冲刺的玩法（连对加倍），不用等任务做完；答满 5 分钟且至少 8 题这一项就完成。题源：口算（沪教版一到六年级）、单词和术语、学过的知识点短选择题，以及报了剑桥物理的孩子的单位换算和代公式（`quickgen` 的 si / speed / density / weight / pressure，题干英文）。每种题按孩子的水平出（目标答对率约 80%），练的是又快又准（流畅性）。

**一次里的出题顺序**（`arena/sources.py` 的 `next_item` / `settle`，快练、冲刺和所有游戏共用）：一次快练、一局游戏里出过的题不再出（单词按词算，换个考法也算同一个词）；答错或点「不会」的题隔 4 道再考一次、只考一次，之后交给隔天的复习。理由：刚看完答案几分钟内反复答对只是短时记忆（集中练习的「熟悉错觉」），真记住要隔开时间、换题再答对，这正是掌握模型判「掌握」的条件；所以再考的这一道证据只记一半，也不拿来估能力值。单词换着考法：认意思、看中文选英文、听音选意思（只在快练 / 冲刺里，游戏可能关着声音）、拼写（给一盘字母，蒙对的机会很小，最能说明真记住了），各考法的难度各自校准、能力值共用。题库题除了短选择题也出短计算题。比孩子低 3 个年级以上的口算不再出，除非那个知识点查出薄弱。

**一个水平**（`app/ability.py`）：整个系统只有一个能力值 θ（每个知识点、每个词汇维度一个），和掌握模型读同一份学习记录。`engine.record_attempt` 记证据时同时更新 θ 和这道题所在（题族, 级别）的难度：现场生成的题按题族和级别，题库题按题型分族（bank、bank:num……），级别看大家的正确率；自己判的简答题、刚看过答案再答的那一道不算。所以每日练习里学会了，游戏和快练的题也跟着变难。快练和游戏多出该复习的内容：快忘了的知识点（`evidence.due_checks`）权重 ×2.5；今天该复习的生词卡先出，答了就按记忆模型排下次（算一次复习）。

**一个取题入口、铺开知识面**（`engine.items_for`，练习、热身、学新、游戏、快练、冲刺都用）：同一个孩子尽量不见做过的题——没做过的新题先出；不够就请 AI 出新题存进题库（页面上不等：交给后台 `prefetch`，这次先出别的）；换了数字的同型题、做错过的、做对过的老题只在出不了新题时凑数。用新题反复考同一个知识点，才分得清是真会了还是记住了这道题。游戏和快练的题库题（`BankSource`）铺到所有在学科目、所有知识点（英语语法、语文、历史……；写作、听说、长阅读、实验探究这种答不快的不出），分四类按比例混着出：正在学 / 薄弱 30%、快忘了该复习 25%、这学期学的 25%、以前学过的（最近两个学年，越久没碰越先出）20%；一次里出过的知识点少出。抽中的知识点没有新的快答题（`purpose="quick"`：20 秒内答完的短选择题、短计算题），后台请 AI 出一批 5 道（`prefetch.quick`，每个孩子每天最多 12 个知识点），这次换个知识点或题源。单词：最近 3 天在任何地方答对过的词先不出。

### 5.24 提前备题：孩子做题时不等 AI

以前题库里题不够就当场请 AI 出，孩子盯着「正在准备题目」等十几秒到一两分钟（混合练习一次取 4 道、缺几道就串行等几次），等过 10 秒注意力基本就离开了（Nielsen 的响应时间三档），孩子一等就切走。现在（`app/prefetch.py`）：

- **做到上一项时备下一项**：做完一项（`flow_state` 算出下一项）、打开今天页（第一项没做的）时，后台只给下一项备题：混合练习建好题单、备前 3 道；学新 / 补弱 / 预习的知识点备练习题（学新连讲解）；热身备几道摸底题。不在早上一次把一整天的题备好：孩子今天不一定来（白花钱），而且后面的题要跟着前面的对错调（同一天的个性化）。
- **一项里面也只往前看几步**：`engine.items_for(ai=False)` 只看题库里现成的。混合练习每次取题后，后台备后面 3 道；答错要「再来一道」的那个点马上备；某一道没有现成题，不停下来等，往后挪 3 位、后台去出，先给后面有题的；挪过一次又轮到它还没好，手上有题就先给这些，一道都没有才现场出（先等后台那一份，不重复出）。学习页一打开就在后台出练习题和讲解；学习页穿插的「以前学过的」那道没有现成题就不穿插；热身先挑有现成题的候选；找根时孩子做这一步，后台备下一步可能要问的。
- **真要等**（`waitWith`）：超过 1 秒还没好，放一张今天到期的单词（看意思四选一，答了照常算复习，`/api/filler`），没有就放这个知识点「记住」那一句；题好了下面出「题来了 →」，孩子点了才换。等待时做一次小回想本身就是有效练习（提取练习），放笑话、动画反而把注意力带离学习。
- 做题用时扣掉页面在后台的时间（`Away`），「会做但很慢」不再把切出去的时间算成慢。

### 5.25 联网游戏：两个孩子在各自的设备上一起玩（`app/arena/`，平台见 5.26）

乐园里的「联网合作」游戏：**双人闯关**（森林冰火人式，火苗和水滴各走各的机关）、**泡泡堂**（炸开砖块和怪兽，困住了等队友来救）、**贪吃蛇**（两条蛇一起长到目标长度）。泡泡堂、贪吃蛇各 1000 关，双人闯关也是 1000 关，一个世界 4 关，世界的场景一轮一轮用下去（第二轮起叫「糖果小镇 2」）；一关一关解锁，下次进来接着玩，每天来都能往下走。

**关卡**：双人闯关每关都是手做的谜题，出发点、门和路线各不一样，越往后越要两个人轮流按机关；`tests/duo_solver.py` 模拟两个人轮流走、跳、踩按钮、推拉杆、坐升降台，测试保证每关都能一起走到门口、每颗宝石都拿得到、地图不重复，最后一个世界比第一个世界步数多、换人多。泡泡堂、贪吃蛇前 8 关手做，后面由 `make(n, rng)` 按关数生成（种子按游戏和关数固定，每次一样；用到哪关才生成哪关，`title(n)` 不生成整关就能给地图上的名字）。难度一直往上走、越往后涨得越慢，每个世界的第 1 关比上一个世界的最后一关松一点：泡泡堂砖块更密、怪兽更多更快（蝙蝠、穿墙的幽灵、要炸两次的铁甲小龙越来越多）、地图从 17×11 变大到 21×13，隔几关有「找星星」任务（带 ⭐ 的砖块，星星全捡到才过关）；贪吃蛇场地更大、目标更长、电脑蛇更多更快更爱拦路，越往后场上石头越多（撞上就倒下），隔几关有「收集金星」任务。双人闯关前 16 关手做，第 17～1000 关由 `tools/gen_duo_levels.py` 离线生成好放在 `levels/duo_more.json`（网站上不现算）：用几种布局（之字形往上爬 / 往下走、两条路、双塔）拼按钮门、拉杆、毒水桥、岩浆 / 水池桥、气闸、升降台这些要两个人配合的机关，左右镜像让出发点和门在四个角都有；每关都用更严的解题器（跳跃留出头顶空间、不会走进死路）验证能一起过关、宝石都拿得到，最少步数从 15 步左右涨到 23 步左右，换人次数也跟着涨，每个世界第 1 关松一点（`tests/test_duo_more.py` 抽查）。

关卡多了以后，闯关地图一页一个世界：`progress.progress(game, team, world)` 只算那一个世界的关，`room_info` 带 `preview`（选中的这一关的整关数据），翻页时 `GET /api/rooms/{id}?world=k`。

**一路上的激励**（`awards.after_run`，所有联网游戏共用，全队一起得，只和自己比）：每过一关告诉「再过 N 关打通这个世界」，打通时庆祝；贴纸：🫶 好搭档（第一次一起过关）、🛟 一次都没倒下、🤜 默契三连（连着 3 关没人倒下）、🧠 答题零失误（这一局倒下答的题全答对，至少 3 题）、🗺️ 一起闯过一个世界、🧭 十个世界的旅伴、🌠 默契之星（和同一个搭档攒够 50 颗星）、🧗🏔️🚀 一起闯过 50 / 200 / 500 关（和同一个搭档在联网游戏里一共打通的关）、🏯 默契大师（一款游戏全部打通）。

**规则**：同一个家庭的兄弟姐妹才能进同一个房间。倒下的人要答题才能复活：**所有游戏都是答对一题就起来**，不管倒下几次、答错几次（答错、「不会」都只是换一道，不加题；规矩只写在外壳 `shell.js` 的 `REVIVE_NEED` 一处，游戏只能改说法 `def.revive = {verb, done}`，改不了要答几道。以前答错多欠一道、最多欠 3 道，一直答错的孩子越欠越多，挫败感太强）。答题不冷冻（游戏登记里 `freeze = False`），题目和单人游戏一样按孩子自己的水平出，所以姐姐和弟弟各答各的难度。两个人是队友，**比的是这一队和自己上次**：每关记队伍最好成绩和三颗星（过关 + 两个各游戏自己定的条件，比如宝石全拿、在时间内、倒下不超过 2 次），没有家庭之间的排行榜。

**分层**：和单机游戏共用一个平台（5.26）。联网特有的只有实时转发（`bus.py`、`/ws/room/{room}`：服务器只转发、不模拟，盖上发送人 `from`，每秒最多 60 条、每条最多 6000 字节；多进程用 PostgreSQL LISTEN/NOTIFY，SQLite 进程内转发；进出房间发 hello / bye）和前端的 `net.js`（连接重连、`MpNet.Track` 插值、`MpNet.rng` 大家同一个随机种子）。玩法里调 `ctx.die()` / `ctx.rescue()` / `ctx.finish(result, report)`。

**谁说了算**：每个孩子的设备算自己的角色（手感不受网络延迟影响），开房间的那台算共享的东西（怪兽、炸弹、食物、电脑蛇），然后发给对方。家里两台设备之间这样足够；不防作弊（只是家里兄弟姐妹）。服务器只校验过关数据的范围（太快不算、宝石不能比地图上多）。

**断线、刷新、换设备**（家长的要求：刷新后自动回到游戏、进度不丢）：
- 以还在玩的那个人为准：重连的人先按存档放好自己和世界，再向队友要一份实时状态（`need_world` → `world`：共享的世界 + 队友看到的我），换上去接着玩。两个人在一个画面里，进度就是还在线那个人的进度。
- 服务器存档兜底（5.26）：每台设备每 2 秒存一次（`/api/rooms/{id}/save`，挂在这一局 `game_sessions.state` 上）：玩了多久、我自己的状态、是不是还在答题、倒下几次、答题对局；开房间的那台再加上世界。两个人都掉线（或队友已经走了）时从这里接着玩；还在不在答题、泡泡堂的道具这种只有自己知道的，也从这里来。10 分钟没人更新就作废；这一局结束就清掉。
- 对方掉线时这一关不结束：等 30 秒，回来了就接着玩。
- 同一个账号两台设备：服务器说了算（5.26）。另一台正在玩就问「在这台设备上接着玩吗？」，点了才换过来；不点就不动原来那台。另一台只是开着房间、没在玩，就直接换过来。
- 倒下答题的题目盖在游戏画面上（`ArenaQuiz` 的 `mount`），答对之前关不掉；万一没弹出来，每秒检查一次再弹。贪吃蛇复活保留原来的长度，泡泡堂保留道具，双人闯关回到最后站稳的地方。

**部署**：用 Nginx 反向代理时要转发 WebSocket，见 `docs/DEPLOY.md` 和 `deploy/nginx-websocket.conf`。

### 5.26 乐园游戏平台：单机、联网、多人是同一套（`app/arena/`，前端 `shell.js`）

家长的要求：以后的游戏要么单机、要么联网（两个人或很多孩子一起），要有一个自己的小引擎支撑记录、设备管理、多账号同步、账号在各个游戏里的档案；优雅、不过度设计、不打补丁。做法：**游戏只写玩法，其余都由平台提供；单机就是一个人的房间**。方案和取舍的讨论记在项目文件夹的「乐园游戏平台引擎-架构方案」。

| 层 | 文件 / 表 | 管什么 |
|---|---|---|
| 游戏登记 | `games/<id>.py`（`Game` 子类）+ `games/levels/<id>/NN.json` | 名字、几个人（`players`）、目标答对率、冷不冷冻、角色、三颗星的条件、世界和解锁、纪录比什么（用时 / 分数 / 只比星星）、贴纸。关卡默认是文件；后面的关可以写 `count` + `make(n, rng)` 生成；要按进度算的改写 `stage`（火柴人） |
| 账号档案 | `progress.py`、`game_runs` | 每支队伍（孩子 id 排好序；一个人就是自己）每关最好的星星、纪录、玩了几次、第一次过关。开到第几关、打通几个世界、解锁了什么都从这里算 |
| 对局记录 | `sessions.py`、`game_sessions` | 每一局一行：游戏、关、队伍、随机种子、开始结束、结果、用时、星星、游戏报的数据。玩的时候的存档也挂在这一局上（`state`），结束就清空。每个人的答题对局（`arena_matches`）用 `session_id` 指回来 |
| 房间和设备 | `rooms.py`、`game_rooms` / `room_members` | 房间放 1～N 人，房主开局、报结果，房主走了由最早进来的人接任。单机每人每款游戏一个房间，一直留着。每个账号在一个房间里同时只有一台设备在玩（`room_members.device`） |
| 实时转发 | `bus.py`、`/ws/room/{id}` | 只有联网游戏用，见 5.25 |
| 外壳 | `static/play/shell.js`（`PlayShell.init`） | 大厅、房间（成员、角色、闯关地图）、倒计时、答题面板（弹出 / 常驻 / 倒下才弹）、倒下复活、存档和接着玩、状态条和表情、结算（星星、纪录、解锁、个人战报、贴纸） |

**一局的流程**（单机、联网一样）：房主 `POST /api/rooms/{id}/start` → 服务器检查人到齐、都还能玩、这一关解锁了，开一局（定随机种子）→ 每个人 `POST /api/arena/start {session}` 开自己的答题对局 → 玩，写了 `save` 的游戏每 2 秒存档 → 房主 `POST /api/rooms/{id}/finish {result, report}`：服务器按 `Game.clean` 收数据、按 `Game.checks` 算星星（火柴人的专注星用这一局所有人的答题算）、记进这一局和队伍进度、开下一关、发贴纸 → 每个人结束自己的答题对局，拿个人战报。

**设备**：每个页面一个设备号（`sessionStorage`，刷新不变）。改房间的请求都带它，不是这个账号现在那台设备的一律 409（`moved`），那台就停下来，显示「已经换到另一台设备上玩了」。另一台设备进来（`enter`）时，原来那台最近 8 秒内存过档（正在玩）就先问（`elsewhere`），点了才换（`take`）；没在玩就直接换。刷新是同一台设备，直接回到刚才那一局。不靠两台设备自己商量，服务器说了算，多进程也一样。

**记录不会越来越臃肿**：页面只读汇总表 `game_runs`（每队每关一行，只更新不增长）；`game_sessions` 一局只写开始和结束（一个家庭一年约 2 万行）；存档每 2 秒覆盖同一行、最多 16 KB、结束就清空；位置、动作只在设备之间转发，不进数据库。

**加一款游戏**：`games/<id>.py` 写一个 `Game` 子类（`@register`，在 `games/__init__.py` 里 import、排进 `ORDER`）→ 有关卡就放关卡文件 → `static/play/<id>.js` 用 `PlayShell.init({...})` 只写玩法（`begin(ctx)`、`ctx.finish(result, report)`；要接着玩就写 `save`，联网再写 `saveWorld` / `loadWorld` / `peerView` / `loadMe`）。单机还是联网只差 `players` 那一行。

**还没做**（下一步）：每个孩子的颜色和喜欢的场景；第一款 3 人以上的游戏和它的大厅；家长页的「玩了什么」改从 `game_sessions` 出。

### 5.27 对战游戏：乒乓球对战（`games/pingpong.py`、`play/pingpong.js`）

家里两个人各用一台设备打乒乓球：每局 7 分（6 平以后要多赢 2 分，最多打到 10 分），三局两胜；**输了一局答对一道题，就接着打下一局**（和所有游戏的倒下答题一样；答错换一道）。选乒乓球而不选网球、羽毛球：从上往下看一张球台，只要上下拖手指，回合短、得分清楚，平板和手机上最好上手。

- **对战用平台原有的东西**：`players = (2, 2)` 的联网房间；输一局 = 外壳的「倒下答题」（答对一道，`def.revive = {verb: '接着打'}` 只改说法）；题目照旧按每个人自己的学习情况出（5.12、5.26）。一场打完由开房间的人报结果（`winner`、局分），外壳用 `def.verdict` 给每个人各自显示赢还是输。没有关卡、星星和排名，只和家里人比。
- **让球**（`Game.team_setup`：开局时按队伍现算、并进 `stage`）：差 5 个年级以上的小的那个让球 0.8（球拍大 48%、飞向他的球慢 22%），差得少按比例；之后看两人最近 6 场，谁多输一场让球 +0.1、多赢一场 −0.1（0～1），目标是两个人各赢一半左右。答对了题，下一局球拍再大 20%。
- **网络**：球归接球的那台设备管（判断接没接到没有延迟），接到了把球的位置和速度发给对方（`hit`），没接到告诉对方得分（`pt`，按顺序编号）；球飞到对方那边时本机把球停在对方球拍处等结果。比分两边各算一份，刷新 / 换设备时从对方或存档拿回来，这一分重新发球。

### 5.28 联网房间：全站的孩子都能一起玩，2～4 个人一起打怪（`rooms.py`、`shell.js`）

- **两种模式**（2026-10-19 定）：开房间只选「🌏 公开」（默认）或「🏠 家里」。公开房间全站的孩子在大厅里都能看到，可以勾「🔒 设个密码」：不设就点一下就进（`game_rooms.kind`=public），设了就带 🔒、点了输 4 位密码才能进（kind=code，密码房主自己定，不填就随机；不用报房间号；10 分钟内输错 8 次就先不让试）。家里的房间只有同一个家里的孩子能看到、能进。一局开始以后不能再进人，满了也不能进。
- **大厅**（2026-10-19 改）：进游戏就列出我能进的所有房间（满了的、正在打的不列），点一下就进，不用搜房间号。房间名自动起：「房主的房间」（家里的用名字，公开和密码的用昵称）。
- **只显示昵称**：公开和密码房间里所有人只看到昵称（`users.nickname`，`auth.public_name`），真名、学校、年级都不出现；没有打字聊天，只有现成的表情。昵称 1～10 个字，不能含自己的名字、电话、邮箱。孩子在游戏大厅里起，家长在孩子资料里也能改。
- **家长开关**：孩子资料里的「隐私模式」（默认关，`settings.private`，见 5.29）。打开以后大厅里看不到不带密码的公开房间，开公开房间一定要设密码；家里的和带密码的房间照常（密码是约好的熟人），也不上排行榜。
- **人数**：泡泡堂、贪吃蛇 2～4 人（`players = (2, 4)`），双人闯关还是 2 人（机关是两个角色配合设计的），乒乓球是对战。`Game.for_team(lv, k)` 按人数调关卡：泡泡堂在空着的角落加 3、4 号出生点，每多一个人多约 1/3 的怪兽；贪吃蛇目标长度和豆子按人数加；「倒下 / 被困」那颗星每多一个人多放宽 1 次。出生点按角色顺序排（`ctx.slot`），人少时也是连着的。
- **关卡接着往下打**：队伍还是「这几个人」（id 排序）。能选的关 = 这队自己打过的和队里打得最远的人打到的（和谁一起打的都算，`progress.reach`）取大的，再往后一关；所以新凑的队伍不用从第 1 关打起，打得远的带着大家往下打。每个人在哪个房间过的关都算在自己身上，每天来都接着玩。房间里的人一变，选中的关就跳到最远能打的一关（`rooms._frontier`），房主可以往回选。
- 换角色：大家手里的角色轮换一下（两个人就是互换）。

### 5.29 排行榜：比坚持，不比水平（`app/boards.py`、`/boards`）

- 原来的原则是「只和自己比，不做排行榜」，因为按分数、按水平排名会打击年纪小的孩子。这里放开一类榜：**只比每天坚持**。打卡天数和年级、水平无关，三年级和初二站在同一条起跑线上。按分数、正确率、通关数的跨家庭排名仍然不做。
- **学习榜**四个：连续打卡、最长连续（补签卡补上的日子不断也不加）、本月打卡（每月 1 号重新数，新来的、断过的孩子也有机会）、累计打卡。打卡规则同 5.14（做完第 1 节算；补签卡保住连续但不加天数）。天数一样名次一样。
- 范围：全站、我的城市。城市存在家长账号上（`users.city`，「省·市」，市去掉结尾的「市」统一写法；直辖市、港澳、海外只有省），一家填一次。一个城市上榜的孩子不满 5 个就不开城市榜。
- 隐私：孩子默认在榜上。家长在孩子资料里可以打开**隐私模式**（`settings.private`，`auth.is_private`，默认关）：不上任何排行榜，也不进全站公开房间（家里的、密码房间照样能进）。以前单独关过「公开房间」的算打开了隐私模式。榜上只显示游戏昵称（5.28），不显示名字、学校、年级。没上榜的孩子也能看榜；家长、管理员也能打开 `/boards` 看（同样只看到昵称）。
- 孩子看到：前 10 名、自己的名次、「再坚持 N 天就超过前面一位」。连续断了不说名次掉了多少，只说「这个月你已经打卡 N 天」。入口：「今天」页顶上的「🏆 学习榜」、「记录」页的学习榜卡片。榜上没人时写明白为什么。
- **乐园榜「本周答对」**（`/boards?metric=game`，入口是乐园首页游戏上面的乐园榜卡片）：这周（周一起）在乐园所有游戏里答对几道题，每周一重新数；还有「一共答对」。只数答对的、不数答了几道，乱点刷不上去。每个人的题都按自己的水平出、预期答对的比例一样（5.12），比的是肯不肯答题。同一个「上排行榜」开关、同样只显示昵称。**每款游戏自己的榜**放在那款游戏的页面里（开房间、选关的下面）：这款游戏本周答对几道，前 5 名和我，点开是 `/boards?metric=game&game=<id>`。单款游戏的分数、存活时间、通关数仍然不做跨家庭排名（主要比手快和年龄）。
- **还没起昵称**：榜上叫「小玩家 + 编号」，不显示名字（家长 2026-10-18 选的）；孩子打开排行榜时先请他起一个昵称，起好马上换上。
- **呈现**（设计稿 /mnt/project-files/aistudy/docs/排行榜呈现设计.md，样式 `play.css` 的 `.bd-*`、动画 `play/boards.js`）：总榜只列前 10 名，前 3 名站领奖台（自己的角色在欢呼）；「我的名次」卡：比上周前进几名（掉了不提）、再多少超过前面一位、再多少进前 10；「这周 VS 上周这时候」只和上周同一天的自己比；「🚀 本周进步」榜按比上周同一时间多出来的排，坚持得少的孩子也能拿金牌。今天页、乐园页各一句离下一个目标最近的话（`boards.nudge`）。
- 榜单在每个进程里缓存 1 分钟（玩一局回来就能看到名次变了），日期变了马上重算。

### 5.30 孩子风格：整站和乐园答题卡一个样子（`app.css` 末尾 `[data-skin=kid]`）

- 产品首先是给孩子用的。孩子（`ui_tone` 是 `kid`）的每一页 `body` 上有 `data-skin="kid"`，CSS 在共用组件上加一层，页面模板不用改；成人学习者、家长、管理员没有这一层，还是原来的简洁样子。家长替孩子看页面时看到的就是孩子的样子。游戏页（`arena_game.html`）用 `{% block skin %}` 关掉这一层，游戏的样子在 `play.css` 里单独管。
- 样子照乐园里的答题卡：**能按的东西**（主按钮、选项、选中的标签、底部导航、提问按钮）有一圈深色描边、底下一道实心「厚度」，按下去会沉一下，孩子一看就知道哪里能点；**装东西的卡片**只有浅色厚边，不抢眼；**正在做的那一件事**（今天页的「下一项」、正在答的题、做完弹出的小卡）用深色描边，一页只有它最醒目。标题、数字、按钮用圆体。
- 主次（5.21）照旧：一页只有一个蜂蜜色实心、深色描边的主按钮；`soft` 按钮白底浅边，`ghost` 不描边。
- 为什么这样做：三年级的孩子靠「看得见、摸得着」理解界面，大块、有厚度的按钮和即时的反应让他们愿意点、点得准；初二的孩子不喜欢幼稚，所以不用卡通字、叠词和满屏贴图，而是游戏界面那种干净、有分量的样子，两个年龄都接受。
- 守住学习：动画只出现在孩子做了什么之后（按下、答对蹦一下、答错轻轻摇一下、做完弹小卡），读题、想题的时候页面不动，不加会动的装饰（唯一的例外是等 AI 写内容时小伙伴「翻书」，那时没有要读要想的东西，内容一出来就停，见 5.34）；答错的反馈是「这里不对，看看为什么」，不是惩罚。答完以后没选的选项变浅、压平，眼睛落在对错和解析上。系统设置了「减少动态效果」的，动画都关掉。
- 新页面、新组件：用现有的 `.card`、`.btn`、`.opt`、`.chip`、`.tabset` 就自动是孩子风格；自己写的可点元素，用 `--k-ink`、`--k-drop`、`--k-card-edge`、`--k-card-drop` 这几个变量。

### 5.31 登录页：所有人的入口，用中性的成人口吻（`login.html`，`accounts._showcase`）

- 孩子、家长、成人自学者、管理员都从同一个登录页进，所以这里不用孩子风格，也不放大的小伙伴和童趣口号；上面写清楚这是一个学习平台、怎么学（每天一份清单、按遗忘规律复习、错题追到根），右边（手机上紧跟介绍）是登录 / 注册。
- 登录和注册是同一张卡片里的两个标签；注册第一步选「给孩子用」（家长账号）还是「自己学」（成人自学），下面的说明和例子跟着变（纯 CSS `:has`，不靠 JS）。孩子不自己注册，选家长时说一句。邀请码按注册方式写成「选填」或必填，规则只写一次。
- 下面「这里能学什么」只展示、不选课不付费（小范围使用的内部平台，不做课程门户）：从课程目录直接生成，分中小学和成人，每门课一张卡片，点开看板块和知识点数，加一个教材包这里自动多一门；知识点少于 20 个的试点包不展示。

### 5.32 知识点学习页：先导入，再一步一张卡（`learn.html`）

- 以前一页摊开「看懂它 / 它从哪来 / 记住方法 / 做 3 题 / 总结 / 前后知识点」，不知道先干什么、几个按钮抢眼。现在一次只看一张卡：顶部 5 格进度条，每张卡第一行写「这一步：要做什么」，底下一个主按钮去下一步，随时能回上一步。
- 顺序：**为什么学**（导入：当时遇到了什么麻烦才有了这个知识、生活里哪用得上，落到一个引子问题上；`bank.context` 的 `story` + `question`，没有引子问题的老版本换新一次；AI 没有内容就跳过这一步）→ **看懂**（先猜一题再揭晓核心）→ **方法**（方法 + 讲解里的例题「看我做一遍」）→ **练 3 题**（一题一屏，卡住可以「回看方法」，连错给退一步和追根）→ **总结**（给三个开头接着写，变复习卡）。
- **先猜一题**：用这次练习的第 1 道题（打开页面就去取，孩子的题后台已备好），只记下猜的选项，不判对错、不记作答；学完做第 1 题时再揭晓「开头你猜的是 B」。只用选择题，题一时出不来就不等，直接看内容。依据：先猜后学（pretesting）、例题效应、由扶到放、自己说出来（生成效应）。
- **导入怎么写**（`llm.kp_context`）：按知识点挑一种角度讲成小故事：来历（当年谁、什么时代、被什么麻烦逼着想出来）/ 卡住的难题（没有它某件想做的事做不成，抽象工具类）/ 身边的怪现象（天天见却说不清）/ 真实场合（语言、管理类：不会它办不成什么事）。有人物、处境、难处和转折，最后接到今天的生活；不编考试和作业场景，口吻贴合年龄。配一张「故事条」（`figures/story.py`：几格「什么时候 · 图标 · 一句话」）。
- **图文结合**：讲解的步骤和例题可以带配图，用出题的同一套画图说明（`app/figures`，这个学科能画的那几种），画不出来的图丢掉、文字照用。
- **一次生成、大家共用**：导入和讲解是教材的一部分，按知识点存在 `contents` 里，谁来学都用这一份，不按人、不按次生成；存的是画图说明，显示时画成 SVG。`bank.KP_CONTENT_V` 升版本时，AI 写的老版本在下一次有人打开时换新一次（人写的、教材作者的不换）。
- 孩子按顺序走，只能回看走过的；成人进度条每一格都能点。今天内离开再回来，从上次那一步接着走（浏览器本地记）。
- 难题课（`kp.think`）同一套：难题（先写判断，再看不同的想法）→ 拆题方法 → 练题 → 对照开头写现在的想法。
- 前后知识点收进页面最下面的「🧭 前后的知识点」，不在学习主线上；每边超过 6 个收进「还有 N 个」。

### 5.33 退掉的课：暂停，不删（`engine.Paused`）

- 以前退课只改 `enrollments.active`：按选课出的（每科练习、快练和游戏里的「我的科目」、热身铺开摸底、词表）马上停了，按卡片 / 记录出的照样每天到期：错题重做、术语和复习卡、游戏里的单词题、系统发现的问题、到期复查和排着的往回追、CEO 课的「换个条件再想一次」。
- 规则只写一处：`engine.Paused(user_id)`。暂停的知识点 = 报过名的教材（包括已退的、换掉的方向）里、现在不在学的；同一概念在在学的教材里也有的、给在学的课打地基的（`ladder.foundations`），照常出。暂停的单词卡 = 来自不再给这个人用的词表（不是在学科目的，也不是家长安排的单词任务）；阅读时自己收藏的词一直留着。
- 用到的地方：`engine.due_cards`、`WordSource._my_cards`、`insights.detect`、`explore.candidates`、`discuss.due / upcoming`。掌握度、错题、卡片都不删；本子里收在最下面的「已经不学的课」，标「暂停」。重新选回这门课就接着复习。不改数据库。

### 5.34 等 AI 写内容：小伙伴去「翻书」（`app.js` 的 `seek`）

- 以前学习页一打开，导入还在写的时候只有一行灰色小字「正在准备…」，大人都找不到，孩子看到底下的「带着这个问题，往下学」就直接点过去了，故事没看到。
- 现在等的地方是小伙伴（问{小伙伴名} 的那个形象：`.env` 的 `ASSISTANT_NAME` / `ASSISTANT_ICON`，没设图标就用孩子选的形象）出来干活：一句「{名字}正在帮你翻几千年的书」，下面一串它在做的事，一步步打勾，最后一步一直等到内容好了才打勾。步骤照写这份内容的真实步骤写（导入：去哪翻 → 找当年是谁、卡在什么难题 → 看生活里哪用得上 → 挑故事画故事条），第一步按学科换说法（数学「翻古代的算书和数学家的手稿」，物理化学「翻科学家几百年来的实验笔记」，语文「翻古人的诗文和老字典」……）。故事出来时上面一行「{名字}找到了一个故事 👇」，内容淡入。
- 不让孩子跳过：孩子在「为什么学」这一步，故事出来之前主按钮锁着，写「等{名字}找到故事…」；等了 30 秒还没好就放行（「先往下学 →」），故事好了照样放回这张卡。成人不锁。
- 用在：学习页的导入、讲解（讲给我听）、例题、先猜一题、练题；混合练习、小测、热身的取题和「先看看怎么做」；写阅读短文（半分钟，`passage`，英文多一步「把要复习的生词放进去」）；追根、阅读里「AI 正在看」改成小伙伴的名字。题这种通常很快、或者后面有等题小卡（5.24）接着的，用一行的小版本（`compact`）。
- 不闪：库里现成的内容 350 毫秒内就到，什么都不显示。
- 动：等的时候没有要读要想的东西，小伙伴上下飞、放大镜来回找，当前那一步的图标弹一下；内容一出来就停（和 5.30「想题的时候页面不动」不冲突）。成人只留文字的「…」；系统设了减少动态效果的全部不动。
- 少等：学习页打开时后台（`prefetch.kick(teach=True)`）连导入一起写，今天清单里的下一项也提前一步把导入写好；`/api/context` 先等后台那一份，不重复写。

### 5.35 今天页：一块一块往下排，小伙伴站在主卡旁边（`today.html`）

- 以前电脑上左栏任务清单、右栏入口 + 一日记录，两栏都跟着内容变高：今天学到的知识点一多，右栏拉得很长，左边任务清单下面空出一大片。
- 现在每块整行、从上往下排，高度只跟自己的内容走：主卡 → 任务清单 → 复习 / 单词本 / 乐园 / 冲刺一排（电脑上一行排开，手机两列）→ 一日记录 → 「看看我的进步」。没有并排的块，就没有对不齐。
- 一日记录：标题旁边一行用时和做题数；「今天学到的 · {名字}帮你整理」是一段话，下面分「✅ 练会了 N」「🔁 再练练 N」两组知识点，整行铺开往右排，不再一个一行；心情和留言在同一行。
- 小伙伴（和 5.34 同一个：`ASSISTANT_NAME` / `ASSISTANT_ICON`，没设图标用孩子选的形象）站在主卡右边（手机上在主卡顶上），气泡里按进度说一句：还没开始「准备好了吗？我陪你一起开始！」、做了几项「已经做完 N 项，接着来！」、第 1 节做完「真稳！后面每项都多一颗 ⭐」、全做完「我就知道你行 💪」。一日记录里整理的那段话也由它出面（手机上收掉头像，只留名字）。点它去换形象。
- 动：进页面时招一下手（全做完时蹦两下），然后不动；以前那只一直上下飞的小伙伴去掉了（5.30：想事情的时候页面不动）。成人、家长查看都不出现小伙伴。

### 5.36 一口气：学习切成一段一段，长度一点点加长（`app/focus.py`、`app.js` 的 `Focus`）

讨论稿：`docs/心流专注与单词概念-讨论稿.md`（在共享文件夹）。专注不靠专门的「专注力小游戏」练（练什么只涨什么），而是在真实学习里一点点延长。

- **哪里有**：今天清单里的页面、做一组题的页面（`Run.start`）自动开始；换页面接着算（`sessionStorage` 记着这口气的 id，30 分钟没消息算走了）。今天页、乐园、诊断不算。所有学习者都有，成人用成人口吻、休息时不叫名字。
- **多长**：按学段起步和封顶（小学 5→20 分钟，初中 10→25，高中 15→40，成人 15→45；`focus.profile`）。第一周只量不加；第一周大多撑不住就起步短一档。之后连续撑住 3 口加一档（小学 1 分钟，其他 2 分钟），连续 2 口没撑住退一档（最短 3 分钟）；掉线后提前收尾的那口不加不减。档位不单独存，每次从 `focus_blocks` 重放（`focus.level_from`）。
- **撑住**：到了目标时间，中间没有离开超过 15 秒。
- **离开**：切到别的页面 / 应用，或页面开着 2 分钟没动（读书时 3 分钟），每次记一笔（`focus_leaves`：多久、当时在做什么、哪项任务）。离开时标签名变成「⏸ 这口气在等你」。回来按离开多久分档：15 秒内不说；2 分钟内一句「回来啦，接着做」；更久在当前题上方提醒「先把题再读一遍，再答」。
- **走神不让孩子自己记**（自我记录反人性、执行不好），系统从作答里看：反应时比自己平时（`focus.baseline`，最近 300 道的对数用时）忽快忽慢、答得快到读不完题又错、错了以后越点越快、离开。几个信号合成一个分数：有点晃 → 下一题出来时读出来、题卡亮一下；一直掉线、又做了一半以上 → 在下一道答对的题后提前收尾（算完成）。从来不说「你走神了」。「会的题突然错了」用 `attempts.p_exp`（答之前估计的答对概率，`ability.expect`）事后算，给家长看。
- **结束**：到了目标时间，在一道题答完、一项任务做完时收尾（`Focus.gate` 挡在「下一项」卡前面）；读书时不打断，悄悄开始下一口气。结束卡：在线 / 掉线的一条线、一句只说好的话（不打分、不出百分比）、下一口气多长；可以休息（小学「动一动 2 分钟」跟着做动作，其他「休息 5 分钟」），时间到用朗读叫名字（游戏昵称，没有就用名字）回来，最多 3 次、隔 30 秒，点「我回来了」就停。进度条旁的 ☕ 随时能休息，休息不算离开。
- **页面不动**：进度条只按整分钟跳一格，不一秒一秒走（5.30）。有了这条进度条，做一组题的「⏱ 专注」计时不再重复显示。
- **家长页**：现在每口气多长（第一周在量节奏）、今天几口气撑住几口、最长一口气、离开几次共多久、这一周离开多在哪项任务和什么情况（刚答错 / 在等题……），会的题突然错了几次。在等题时离开的算系统的问题。

### 5.37 登录：孩子用登录名 + 4 位数字，设备记住登录过的账号（`app/auth.py`、`login_pick.html`）

孩子没有邮箱，也记不住长密码；共用一台设备的家庭要能很快换人。

- **账号**：大人（家长、自学者、管理员）用邮箱 + 密码。家长添加的家人用**登录名**（`users.login`，孩子自己记得住的小名，比如「果果」；全站不重复，存小写；2～16 个汉字、字母或数字），邮箱选填。登录框只有一个「邮箱或登录名」，带 @ 的当邮箱。
- **4 位数字**：家长管着的孩子（`auth.uses_pin`：有家长、年级在大学以下）的密码就是 4 位数字，1111、1234 这类太好猜的不收。家里的成人成员、长大自己管账号的孩子用普通密码（可以自己加邮箱）。以前用邮箱和长密码的孩子照样能登录，家长重设成数字以后用数字。
- **锁住**：数字连错 5 次一直锁着（不是 15 分钟），家长在孩子的「登录与安全」里点「解除锁定」。大人的密码还是锁 15 分钟。
- **设备记住账号**：登录成功后，这台设备（长期 cookie `bj_dev`，表 `device_logins`）记住这个账号，退出登录也不忘。登录页先列出这些头像，像电脑的切换用户：点头像，孩子用大数字键盘输 4 位（输满自动提交），大人输密码。只认这台设备上登录过的账号，别的设备看不到也试不了。「不在这台设备上显示」能把头像拿掉；「用别的账号登录」进普通登录页。
- **样式**：列表里有孩子就用孩子的样式（5.30），小伙伴说话（「是谁来了？点你的头像」「嗨，果果！输入你的 4 个数字」「数字不对，再想想」）；页面上只有一件事要做。只有大人时用大人的样式。普通登录页仍是中性的大人口吻（5.31）。
- **家长添加孩子**：填完名字自动给一个登录名（就用名字，重名加数字），设 4 位数字；保存后给一张「登录卡」（登录名、数字、三步怎么登录，可以打印），数字只显示这一次。

### 5.38 添加孩子：只问用得上的几项，课按学校模板默认排好（`kid_new.html`、`catalog.default_courses`）

家长要很快把孩子加好；系统用不上的信息不问，能推出来的不问。

- **只问四件事**：名字、年级、在哪上学（地区 + 学校类型）、4 位数字。
- **三个名字各管一件事**：名字＝家里人怎么称呼，只在家里看得到（家长页、孩子自己的页面）；登录名＝只用来登录，不公开，添加时按名字自动起（重名加数字），写在登录卡上，要换在编辑页改；昵称＝排行榜、公开房间里别人看到的，不能带名字，家长不用先填，孩子第一次去那里时自己起（5.29）。添加页只问名字。年级选成人或大学时不问学校，4 位数字换成普通密码。
- **课自动匹配**：地区（来自学校模板的 `region`，现在是上海、江苏，加了模板就自动多一个；另有「其它地区」）+ 学校类型（公办 / 民办双语 / 国际学校）+ 年级 → `catalog.match_preset` 找模板：先找这个地区的，再找各地通用的（国际学校）；这个地区没有这类学校的模板就按同地区公办起步。模板里这个年级用得上的教材列成小清单，每门后面「换」打开逐科调整。没有模板的地区先只排统编语文。保存时服务器重新匹配一遍，不信页面传来的模板。
- **不问的**：学校名称（系统没用到，去掉）；邮箱（编辑页可以补）；昵称（孩子第一次打开排行榜时自己起，5.29）；城市（选了上海、江苏就记上省份，家里还没填过时）。每天学多久按年级给推荐值（`web.default_minutes`：1–2 年级 30 分钟，3–4 年级 40，5–6 年级 45，初中 60，高中 90），乐园、隐私模式、学习方式用默认值，以后在孩子的编辑页改。
- **出错**：填错回到这个表单，在上面提示，填过的（包括选好的课）都保留；所有检查通过才建账号。
- 以后按地区 + 课本封面 + 做题情况校准教材的机制，接在 `default_courses` 后面，表单不用再改。

### 5.39 选课清单：一门课一行，一个开关（`_course_grid.html`、`course-picker.js`）

家长编辑孩子、添加孩子（逐科调整）、自学者「我的课程」三处用同一个清单；选课本质上就是「学 / 不学」，样子要整齐。

- **一门课一行**：学科图标、学科名、一行说明，右边一个开关。行一样高，图标、文字、开关各成一列，整张清单对齐；关着的课图标变灰、字变浅，开着的一眼看出来。手机、电脑都是一列（电脑上最宽 720px，开关不离名字太远）。
- **要再选的才多一小行**：只在开着时、在这一行下面出现，和标题文字左对齐。有几套教材的出「教材」下拉框（不再有「暂不安排」这一项：不学就关开关）；剑桥课出「考试方向」（IGCSE 前的年级先按默认，到 9 年级才露出来）；资格考试（`system=cert`）出「考试日期 选填」。自编的成人课什么都不多，就是一个开关。
- **说明收起来**：核对课本的提示、完整名称、适用范围放进「怎么确认是这一套」，只对有几套教材的科目出现；自编课那一行的说明就是课程一句话介绍。年级超出课程范围、教材还在核实的提醒在这一小行里出现。
- **字段不变**：`subj_<学科>` = 教材 id（只有一套时就是开关本身，有几套时是下拉框，关着时不提交）、`track_<教材>`、`exam_<教材>`，服务器照旧（`_kid_form_packs` 再按年级、人群核一遍）。学校方案预填、添加孩子页的默认课都经 `coursePicker.set` 填进来。
- 孩子风格（5.30）下开关加深色描边；减少动态效果时开关不滑动。

### 5.40 等 AI 回话：按下就锁住，说清在做什么，写出来一段就先看一段（`app.js` 的 `aiWait`、`app/llm/stream.py`）

- 以前思辨题点「说说我的想法」、AI 点评的开放题点「提交，看点评」以后，按钮只是变浅，AI 要想十几秒，整段写完才一次性回来。这十几秒页面上什么都没有，大家以为卡住了，一直点。
- 现在所有「等 AI 回话」的按钮（思辨题的开始、接着说、写结论；开放题的提交、回答追问）用同一个 `aiWait`：
  1. 按下立刻锁住：按钮转圈写「正在想」，写的字也锁住，不会交第二次；出错了按钮和字放回去，可以再点。
  2. 下面马上出现 AI 正在做的几步，按时间一步步打勾，最后一步等到 AI 真开始写才算完。步骤就是提示词里让 AI 做的那几件事：思辨题「读懂你的判断和理由 → 分析：哪里最有力，哪里还没想到 → 写回应，再提一个新挑战」；收尾「对照你开头和现在的想法 → 和几种成熟的看法比一比 → 找出这个结论在什么情况下会出问题」；开放题点评「诊断：逐条对照要点 → 分析：找出最关键的缺口 → 给出建议：写点评和追问」。
  3. 边写边看：AI 写出一段，页面上就先出一段（「正在写…」下面），写完换成正式的卡片。
- 样子跟 5.34 的 `seek` 同一个组件：孩子是小伙伴 +「{名字}正在读你的想法」；成人（`data-tone=adult`）不出小伙伴、不带名字，一个转圈 + 几行字，当前那一步加粗，做完的打勾。成人所有用 `seek` 的地方（导入、讲解、挑题……）也都换成这个样子。
- 边写边看怎么做：页面请求带 `Accept: application/x-ndjson`（`api(url, body, {onPart})`），服务端 `web.streamed` 把业务放到后台线程里照常跑完、提交，一行一个 JSON 回：`{"part": {栏: 目前写到的字}}` 若干行，最后 `{"done": 正式结果}`（出错 `{"error", "status"}`）。学员关了页面，这一轮照样存下。
- 只有学员在等着看的三种回答边写边给（`llm.stream.FIELDS`：discuss、discuss_close、review），也只给给人读的几栏（把观点说得更有力 / 回答 / 挑战；变化 / 自己的东西 / 值得留意；点评 / 追问）；判断、编号、思考方式这些等写完校验过跟着正式结果给。出题这种带答案的不边写边给。
- 提供方：Claude 用 `messages.stream`，OpenAI 兼容的用 `stream: true`；不支持的写完一次给（`Provider.stream` 的默认做法），页面上就是等完几步直接出卡片。
- nginx：回包带 `X-Accel-Buffering: no`，宝塔 nginx 不会攒着一起给；等太久时每 10 秒发一个空行，不会被当成断了。
- 快不快：真正的时间花在 AI 想（这几种用 effort=medium）。边写边看以后，从按下到看见第一句话就是 AI 开始写的时候，不用等整份写完。要再快，可以在 `config/llm.toml` 的 `[tasks.discuss]` / `[tasks.discuss_close]` / `[tasks.review]` 里单独把 effort 调成 low，不用改代码（想得会浅一点）。

### 5.41 单词：单词包 → 每天新词 → 每个词的等级 → 用出来（`app/words.py`）

单词是一个成体系的模块，不只是做题、查词时顺手攒下的卡片。四层，一条线：

- **单词包**：现有词表（`content/words_en.json` 的年级核心词、学科术语）就是包。孩子按年级、教材自动挂（`word_packs.state='auto'`，用的时候才建行）：本年级的包是「主包」，每天加新词；低年级的包只在闪测和游戏里用。家长在「学习安排 → 单词包」里加、停、改每天几个；成人（含家里自管的成人）不自动加新词，在「🗺️ 我的词」页自己选。原来的「每天新词」（`tracks.kind='words'`）迁移进 `word_packs`（迁移 0045）。停掉的包：卡片暂停（`engine.Paused`），记录都在。
- **每天新词**（`words.daily_new`，排今天计划时调用）：每个主包补到当天的量（小学 4、中学 5、成人 6，家长可改；当天调大了当场补齐）。一组 12 个词里隔 3 个挑（同一话题的词不在同一天），已经认得的跳过（热身、闪测里答对过），欠着要复习的太多先少加（40 个减半、80 个停）。新词卡带 `extra.new`。
- **每个词的等级**（`words.ladder`，从 `events` 重放，不另存）：认得（看英文选中文）→ 听得出 → 想得起（看中文选英文）→ 拼得出 → 用得对（句子补洞）。某一级在两天以上答对才算到这一级；最近一次答错的词是「有点晃」。复习卡、闪测、乐园的每一次作答都经 `words.log_answer` 记一条 `target='word'` 的事件，带 `tier`。「我认识的词」只增不减（到过「认得」就算）。
- **用出来**：例句库 `word_examples`，按学段（primary / secondary / adult）一个词两句，AI 写一次、所有人复用（`tasks.word_examples`，词用 `[[ ]]` 标出、句子里有线索）；后台按今天要用的词提前写（`words.prepare`，跟着 `prefetch.MODE`），没写好之前退回别的题型，不让孩子等。

复习页（`/review?group=words`，标题「单词」）：新词第一次是**学习卡**——先猜意思（不算对错，记 `guess` 事件）→ 揭晓中文和例句；不当场考，隔开几个别的词再回来认一次（5.44）。复习过一轮放回句子里选词，等级到「拼得出」后隔一次出补洞拼写。答错的说「差一点，是 …」，隔几张再来一次。

乐园原来的「句子补洞」游戏已经撤掉（只是答选择题、小人跟着走，没有操作，不是游戏）；补句子留在复习和快练里当一种题型。

**单词跑酷**（`games/runner.py`、`static/play/runner.js`，5.42）取代它：词就是玩法本身。

「🔤 单词」（`/words/map`，5.43）：我认识的词有多少、有点晃的词、每个包按组的进度（抓住几个 / 见过几个）。孩子说法：没有「背、考、任务、错」，用「抓住、找回来、差一点」。

还没做（后续游戏）：听音抓泡泡、单词打怪（合作）、找错词侦探。讨论稿：`docs/英语单词游戏与单词系统-讨论稿.md`（项目文件夹）。

### 5.42 单词跑酷：撞字母拼词，按单词等级给提示（`app/arena/games/runner.py`）

- **玩法**：近大远小的三条跑道，← → / 左右滑换道，↑ / 往上滑跳。上面写着要拼的词，按顺序撞上对的字母把它拼出来；同一排里还有长得像的字母（b/d、m/n、词里别的字母），靠自己认。撞错字母只减速、亮出要的那个字母；石头要躲、栏杆（第 3 关起）要跳，撞上就摔倒。一关拼够 4–10 个词冲过终点；越往后词越多、越快、障碍越密。连着拼对加速。三颗星：过关、一次没摔、八成的词一次拼对。
- **选词**：`Game.ask = ("words", "run")`，`WordSource` 和别处一样按单词包、该复习的词、能力值挑词（只挑能拼的单个词）。提示几档跟着这个词的等级（`words.run_hint`）：没见过的新词整个词淡淡地写着照着拼（`copy`，算「认得」），认得了只给中文和首字母（`spell`），拼得出了只给中文和读音（`dictate`）；水平高的人没见过的词也直接从第二档起；最近一次错了退一档，答错隔几个再回来时照着拼。三档各自一个题族校准（`words:run0/1/2`）。
- **记录**：一个词拼完报一次作答：一路没撞错算拼对；撞错过报撞到的那串字母（算错，词进复习）；对的字母错过两次被亮出来算「不会」。和别处一样进 `record_attempt`、单词等级、能力值、专注值。
- **摔倒**：共用规则，答对 1 道就起来（`quiz: 'revive'`）；这道题就是正在拼的那个词（服务器上挂着的那一题），起来后换下一个词。
- **谁能玩**：孩子在乐园里玩（排第一个），和别的游戏一样算游戏时间。成人：学单词的游戏（`Game.study`）不受乐园时长和解锁限制（`rules.free_for`），从「🗺️ 我的词」进，返回也回那里。成人还没自己挑包时先挂上成人场景词包（`shelf: scene`：餐厅、出行、酒店、看病、购物、工作邮件、开会，`en-scene-*`），只在游戏、闪测里用，不每天加新词；自己挑了包就只用挑的。没有任何单词包的人进不去，告诉他去哪加。

### 5.43 单词包书架：一个年级一包，跟着课本和学校进度（`content/words/*.json`、`app/words.py`）

- **书架**（包的 `shelf`）：课本单词包（`grade`：译林 `en-yl-g3…g9`、上海 `en-sh-g1…g6` + `en-sh-junior`，高一到高三 `en-hs-g10…g12`）、核心词（`core`，原来的 `en-core-*`）、考试和课标词汇（`exam`：小学课标 505、中考 1600、高考 3000、剑桥 A1–B2）、成人常用词（`adult`：日常高频 7 级、日常口语、商务、职场）、成人场景词（`scene`）、学科术语（`terms`）。
- **来源**：课标词表照《义务教育英语课程标准（2022年版2025年修订）》附录3、《普通高中英语课程标准（2017年版2025年修订）》附录2（数目对得上官方）；课本单词表从网上整理（一部分是旧版课本的，`source_note` 写明）；成人用 NGSL / NGSL-S / BSL / TSL（CC BY-SA 4.0）；剑桥按 Oxford 3000/5000 的 CEFR 分级。中文：课本单词表自带的优先，没有的取词典最常用的一两个意思。家长的规矩：词表不求一字不差，搜到的都收；同一个词在几册都出现，只在第一次碰到时当新词学（`daily_new` 跳过已学过、答对过的词），后面再出现就是复习。
- **谁挂什么**（`_auto`）：写了 `packs` 的包只给选了这套教材的人（课本包、术语包）；只写了 `subject` 的给学这门课的人（核心词）；考试包、成人包不自动挂。有课本包时课本包当主包，核心词留着（以前的卡照常复习，闪测、游戏照常用）。成人还没挑包时挂上场景词和 `starter` 的高频包（日常高频第 1 级、日常口语）。
- **跟着学校进度**（`school_unit`）：课本包的每组带 `book`（册名）和 `unit`（新版：和课程目录的单元名一样）或 `pos`（旧版：这一册第几单元）；`schoolyear.estimate` 推出学校正在上哪一册哪一单元，每天的新词先出这一组，再补前面落下的，最后往后学。
- **页面**：「今天」页快捷入口「🔤 单词」（`/words/map`，替掉原来的单词本入口，单词本在这页底下；不放底栏，底栏五个格子让「乐园」居中）：我认识的词、今天的单词、单词跑酷、我的单词包、单词包书架（孩子只看自己这套课本的包，家长在学习安排里加；成人在这里加、停）。单词包页（`/words/pack/<id>`）：按册、按单元列出全部词和中文，每个词一个点标出会到哪一级，课本包标出学校正在上的单元。
- **还没有的**：译林三上、八下，上海二至九年级新版的单词表（现在用旧版）；拿到课本单词表照片就换。

### 5.52 阅读页：进来就是为了读（`reading_list.html`、`news.archive`）

以前一进来最上面是「AI 写一篇 / 贴链接 / 贴课文」的工具，新闻和书库各只有一个入口，「我读过的」把新闻、短文混在一起。阅读页按「读」来排，从上到下：

- **今天要读的**（主卡，这一页唯一的实心按钮）：今天计划里的阅读、听书，做完的打勾，按钮去第一项没读完的。没有阅读任务时主卡是今天的新闻。
- **每日新闻**：一天一条，按日期排（今天 / 昨天 / 10月21日），标题用按孩子级别改写后的，标「读完 / 读到一半 / 没读」。点开 `/news/<id>` 就读；往天的新闻这个级别还没写过就现写，写一次大家共用。在新闻里换难度留在同一天。显示 7 天，更早的折起来（最多 14 天）。
- **在读的书**：书架上最近翻过的几本，接着上次那页；没有在读的就是一个去书库的入口。
- **每天的短文**：写给你的、自己贴的、网页的，按日期排，新闻不再混在里面。
- **想读点别的？**（最下面，收起来）：写一篇、贴链接、贴课文。从每日任务进来、今天还没有短文时（`/reading/today`），它就是要做的事，放在最上面并打开。

## 6. AI 抽象层与使用原则

- **配置和代码分离**：提供方、模型、密钥、每日上限、按任务路由都在 `config/llm.toml`（模板 `config/llm.example.toml`），改完重启服务生效，不用改代码。值可以写成 `"${环境变量}"`。
- **抽象**：业务代码只调用 `app.llm` 里的任务函数；任务函数把请求包装成 `ChatRequest` 交给 `service.ask_json`；`service` 按配置选出 `Provider` 调用。新增一个模型厂商 = 写一个 `Provider` 子类并 `@register("类型名")`，配置里写 `type = "类型名"`。
- **按任务路由**：`[tasks.lookup]` 这样的段落可以给某个任务单独指定提供方、模型、effort、max_tokens（比如查词用更便宜的模型，出题用更强的模型）。
- 所有调用在服务器端，查词、句子讲解按输入做缓存（同一个词在同一句里只查一次）。
- **题库沉淀**（`app/bank.py`）：AI 现场生成的东西全部存下来，以后先用库里的，不够才生成。
  - 题目存 `items`，用 `item_kps` 挂到一个或几个知识点上。同一概念在别的教材里、语言相同的知识点的题也能用。每道题记下语言、年级、出题目的、生成记录（模型和提示词版本，见 `tasks.PROMPT_VERSION`）、做题统计（次数、正确、还不会、用时），内容相同的题只存一份（`qhash`）。
  - 分步讲解、背景和用处、阅读短文存 `contents`（kind = teach / context / passage）。和孩子个人有关的部分不存，比如讲解前面的「你在数学里学过……」来自人工写的关联说明，用的时候再拼。阅读短文按语言、年级、话题复用，同一个孩子不会读到重复的。
  - 孩子和家长可以标记「这道题有问题」（`flags`）。标记的人自己不再看到这道题；家长标记一次，或两个不同的孩子标记，就暂停使用，管理员在后台「题库」页恢复或下架。后台也能看各教材的覆盖情况、正确率最低的题，并导出整个题库（不含作答记录和试卷原题）。
  - 试卷导入的原题只给这个孩子自己用。题目要求「答案正确且唯一」，人工核对过的题标为 seed。
- 每个孩子每天调用上限 `daily_limit_per_kid`。
- 题目和讲解用什么语言、要注意什么，按教材包的 `teach_lang` / `item_lang` / `prompt_note` 生成（国际学校的学科：题干英文 + 中文翻译，讲解用中文并标出英文术语）。出题格式里的题型来自题型注册表。
- Claude 默认启用服务端 fallback（`server_fallback = true`），模型过载时自动切换备用模型。
- `install.sh check --llm` 会真实调用一次，确认密钥和网络都通。

## 朗读（TTS）和书库

- **朗读服务** `app/tts/`：独立的包（不依赖网站其他代码，可以复制到别的项目）。文字规整后连同 提供方/模型/声音/语言/语速/格式 算 MD5，
  索引记一条（`tts_clips` 表），音频存 `data/tts/ab/cd/<md5>.mp3`。第一次播放时才调用服务，后台线程边生成边写 `.part`，前端同时边下边播；
  `O_EXCL` 抢占保证多进程也只生成一次。每种语言固定一个声音（不让用户选，命中率才高），语速按用途（单词 / 句子 / 阅读）在 `config/tts.toml` 配。
  没开或某语言没配声音时，前端（`Speak`）退回浏览器自带的朗读。网站这边的胶水在 `app/tts_web.py`。
- **书库** `app/library/`：书单 `content/library.json`（只有公有领域的书放原文，其余只列书名）。服务器从古腾堡 / 维基文库下载原文
  （`python -m app.cli library fetch`，安装升级时自动跑；下载失败记在 `data/library/failed.json`，之后的安装升级先跳过，按 1、2、4…最多 30 天再自动试，`--retry` 或管理后台点下载马上重试；管理后台也能上传 txt），去掉头尾、切章、按字数分页，存 `data/library/<id>.json`。
  孩子按页读（`book_progress`、`book_days`），每章第一页显示 AI 写的导读（上回说到、关键词、带着问题读），章末两道小题 + 一句话，答对得书签；
  导读存在 `contents`（kind=`book_guide`），所有孩子共用。家长在「阅读与单词」里选书库的书（`tracks.ref = lib:<id>`，按页算）和「每天听书」，
  读够页数 / 听够分钟自动打勾。
  整理规则在 `app/library/text.py`：有目录就按目录在正文里找各章标题（最可靠），没有再按 CHAPTER / 罗马数字 / 第X回 的规律；

  规则版本 `FORMAT` 升级后读书时自动重新整理。整理完做质量检查，有严重问题（下载到网页、正文太短）的书孩子那边不显示。


### 5.44 背单词的顺序：隔开再取、一次一个方向、1/2/4/7（`review.html` 的 `later/pick/nextStep`，`app/recall.py`）

讨论稿：`docs/背单词的科学方式-方案.md`（项目文件夹）。三条规矩，都在一个地方：

- **隔开再取**：新词学习卡（猜 → 揭晓）不当场考。隔开至少 3 张别的卡（`LAG`），再回来认一次（`check`：听读音、看英文选意思，换一组干扰项）；到点以后最多再拖 4 张（`SLACK`）。答错的卡也走同一个 `later`：隔几张再来，每张只再来一次。这一轮没有别的卡能隔开它（只剩它）就不出了：学习卡记成「看过」（`mode=seen`，明天第一次考），答错的本来就排在今天、下次打开再来。新词和旧词穿插着排（学一个新词、复习一个旧词）。
- **一次一个方向**：同一个词在一轮里只考一种题。当天只认意思（英 → 中，最容易）；第二天起换方向、一次比一次难：看意思选单词 / 补句子 → 拼写 → 听写 / 拼进句子里（按 `box`）。
- **拼的题先用字母块**：要自己拼的题（拼写、听写、拼进句子）在 `box < TYPE_FROM_BOX`（5）时给一盘字母块：这个词的每个字母各一块（重复的各给一块），再混 3 个容易拼混的（b/d、m/n、e/a…，`words.letter_pad(tiles=True)`），每块用一次。之后自己打，想不起来可以点「给我字母」换成字母块。用字母块拼对记成 `tiles`（等级里算「想得起」），自己打对才算「拼得出」。游戏里的字母键盘也用同一个 `letter_pad`（每个字母一个键）。
- **前几次按 1/2/4/7 天**（`recall.YOUNG_STEPS`）：单词卡答对后，前四次隔 1、2、4、7 天，之后交给记忆模型；答错回到 box 0，今天隔几张再来，答对了又从 1 天开始（连续重学）。
### 5.45 主题：孩子自己挑一整套样子（`app/theme/`，换主题在「我的账号」）

- 家长想要像输入法换皮肤那样的「主题」，不只是换背景。一个主题是一个文件夹：`theme.toml`（名字、介绍、浅色和深色两套颜色、乐园的描边和音色、小伙伴开场的一句话、要连续几天才解锁）+ 可选的 `mascot.svg`（这个主题的小伙伴）。内置的在 `app/theme/<id>/`；不进公开仓库的（比如授权来的 IP 主题）放 `DATA_DIR/themes/<id>/`，格式一样，部署时装进去。
- **插画提前画好**：每个主题带 `pattern.svg`（整页淡淡的底纹）、`horizon.svg`（页面底部的场景：电脑上露在内容两边，手机上在底栏上方；底下多画一截地面给底栏盖）、`mascot-cheer.svg`（小伙伴开心的样子，今天全部做完、做完一节的弹出卡用）。画在 `body::before` 上，固定在最底层，深色模式压暗；卡片是实心的，字不压在画上；游戏页、打印不放。现在的图由 `tools/gen_theme_art.py` 生成，以后换成画师画的，文件名不变就行。底栏五个图标在 `theme.toml` 的 `[nav]`，乐园「白天」场景的颜色在 `[play.day]`（别的世界保持原样，认得出是哪一关）。
- **换什么**：颜色和质感（`--bg`、`--card`、`--brand…`、孩子风格的 `--k-ink`、`--k-card-edge`、热力图，只能改 `theme.TOKENS` 里这些）；小伙伴（换主题时顺便换上它的，之后还能单独换）；今天页小伙伴开场那句话；乐园的描边颜色（`art.js`、`--pl-ink`）和音色（`engine.js`：旋律类的音换成主题的波形、整体按主题升降，打击和爆炸声不变）。
- **不换什么**：一页一个主按钮、能按的东西有描边有厚度、读题时页面不动、对和错的颜色（`--ok`、`--mint`、`--coral` 不在 TOKENS 里）、题目、讲解和 AI 的说话方式（按年龄走，见 5.22）。每个主题浅色、深色都要写全，测试检查正文、说明、主按钮、选中选项、品牌色文字的对比度都到 4.5（WCAG AA），不到就不能上。
- **谁用**：只有孩子（`ui_tone` 是 kid）。`body` 上挂 `data-look="<id>"`，颜色由 `/theme.css`（所有主题的变量，挂在 `[data-look]` 上）给；换主题页的每张预览卡挂自己的 `data-look`，看到的就是那个主题。家长替孩子看页面时看到孩子的主题；成人学习者、家长自己的页面、管理员和登录页不用主题。
- **怎么选**：「我的账号 → 换个主题」点一下全站就换，存在 `users.settings.theme`，换设备也一样。第一批：蜂蜜（默认）、太空站、舞台练习生直接能选；深海探险要连续学习 7 天（`theme.best_streak`：历史上最长的连续天数，补签卡补上的日子不断），解锁了就一直在，之后断了也不收回。不卖、不抽、不用星星换。
- **IP**：真实的卡通 IP、明星的形象和名字要有授权（著作权、商标、肖像权），用户又是孩子。先做原创主题；有授权的 IP 主题放私有目录，不进仓库。讨论稿：`docs/主题皮肤系统-讨论稿.md`（项目文件夹）。

### 5.46 做对过的题不再出、错题换变式、「还不会」的承接、成人课回访（`engine.items_for`、`app/recall.py`、`app.js walkThrough`、`app/lessons.py`）

讨论稿：`docs/重复题与我不会-讨论稿.md`（项目文件夹）。一句话：题是用来取证据的，不是用来背的；同一道题对同一个人做对一次就用完了。

- **做对过的题退役**（`bank.retired`）：做对过的题、它同一组换了数字的题、想完了的思辨题，对这个人哪里都不再出——练习、热身和往回摸底（以前 `purpose="diagnose"` 会把做过的题和新题混着排、有老题就不请 AI，是重复的主要来源）、知识点复习卡、错题的变式题、出不来新题时的凑数。没有新题，这个点今天就少出，交给后台出新题（复习卡返回 `mode=later`，今天先不出这张）；只有没配置 AI 的部署才拿做对过的题凑。AI 出重了（存进去是库里已有的一道）也不算新题。请 AI 出题时附上这个点已有几道题的开头（`avoid`），新题换情境、换问法，不只改数字。
- **错题**：做错的原题只再做一次（第二天，标出上次选的），为的是改掉这一个错；之后都用变式题（同一知识点、不同组、没做对过的，题型和原题不同的优先），出卡时现挑。原题改对 → 隔 2 天第一道变式；变式做对 1 道 → 隔 4 天第二道；不同的日子做对 2 道过关（`VARIANT_GAPS`、`PASS_STREAK`）；做错明天换一道再来。过关 3 周后用一道**新的**变式题回头看（以前是原题）。点了「还不会」进来的卡不做原题，直接从变式开始。没挂知识点的老错题出不了变式，照旧原题隔天做对 3 次。
- **「还不会」分三级**（学习页、每科练习、错题本里打开，`ladder: true`）：① 先点一下路子（题目的提示，没有就用知识点的方法 `nudge`），按钮变成「还是不会」；② 还不会：解析拆成几小步（`itemtypes.walk`，最多 4 步），看懂一步点下一步，最后是答案；③ 趁热试一道一样的（`/api/twin`：同组没做过的 → AI 照着改编一道存进题库 → 这个点的一道新题），记 `mode=helped`，只算 0.3 份证据，做错不另进错题本。小测、试卷、追根里的「不会」照旧（直接下一题或看答案）。
- **一周两次「还不会」**（`insights.DONT_KNOW_DAYS`）：不是题的问题，是这一课没学懂——计划里排「从头学一遍：××」（学习页整课），不再继续出题；家长周报的「系统发现」里也有这一条。
- **成人课回访**（`lessons` 表，迁移 0046）：学习页走完一课记一笔。成人学习者学过的课，按 3 / 7 / 14 / 30 / 60 天才再排进计划（`plan.build_plan` 最后一道关）；再打开学习页是回访：先不看讲解写一两句回想（这一课说什么、什么时候不适用）→ 对照讲义的核心和方法、上次自己的总结，自己说想起来了没有（`/api/learn/recall`，0.3 份证据）→ 一个新案例（练习题照上面的规则只出没做过的）→ 写下这周手上哪件事可以这样做。想从头看讲解点 `?full=1`。孩子的课不变。

### 5.47 只能在这里学的课：先上课再做题（`engine.unlearned`、`plan` 的 `lesson`、`app/testout.py`）
自编课和考证（学制 `course` / `cert`，`engine.SELF_TAUGHT`）没有别的地方会教，学员 100% 没学过；学校的课不一样，按校历推演教到了哪（5.23），孩子不用自己标，这一节不改它。讨论稿：docs/没学就先考-讨论稿.md（v2）。
- **上过** = 学习页走完一课（`lessons` 表，5.46）或「考我一下」通过；同一概念在别的课里上过的也算。`engine.unlearned` 是这类课里还没上过的课，并进 `Paused.kps`：热身、复习卡、错题本、快练和游戏、自动发现的问题都不出它。
- **每天**：每门课排一节「新的一课」（任务类型 `lesson`，按课本顺序、必须先学的都上过了的下一课，第一节不因时间不够被截掉）。混合练习里没上过的课不出题，「新学的」是最近 3 天上过的课，没有预习；一课都没上过的课当天不排练习。
- **不摸底**：这类课不排开头的诊断（以前只有考证不排）。已经懂的，学习页开头「考我一下」：两道能自动判对错的题（思辨题不算），走平常的作答入口，都对就算上过（`/api/testout/done` 核对是这一课的题、今天答对的）。
- **升级**：有 `lessons` 表以前已经上过的课，启动时按总结卡和清单里学完打勾的学习任务补记（`engine.backfill_lessons`，一门课里有记录就不再补）。

### 5.48 向下跳：转柱子往下掉，题门的答案就是洞（`app/arena/games/helix.py`、`static/play/helix.js`）

- 照着 Helix Jump 的手感做：柱子上一层层圆盘，一层 12 格（普通、洞、刺）。球一直原地弹，← → 按住转柱子（点一下转得准，按住半秒越转越快，松手很快停住）、鼠标或手指左右拖（拖多少转多少）、滚轮半格半格转、Shift + ← → 一下转到下一个洞的正中间（键盘按住转很难停准，电脑上靠它不比手机差）。连穿 3 层不落地变火球，砸得碎下一层（连刺一起）。
- **看得见下面两层**：原版是竖屏手机游戏，能看到下面两层，掉下来之前就知道下面是刺还是洞。我们是横屏，所以塔窄一点、层距近一点（`geo()`：层距 0.24 屏高），镜头让球待在上面三分之一，下面两层整层都在画面里。球正下方画一个**落点影子**：跳过对着洞的层，画在真正会落到的那一层上；落到刺上影子变成黄圈 + 「!」，来得及转开。
- **题就是玩法（题门）**：每隔几层一层题门，球落到门上就**停住**、开门：题写在上面，门上按选项个数开 2～4 个洞，答案牌立在洞口外沿（前面的挂在圆盘边下面，不被球挡住）。停下来慢慢选，不催：← → 一下换一个答案（转到它的洞上，牌子变黄），↓ / 空格 / 回车掉下去；鼠标、手指直接点答案牌就转过去掉下去，拖完松手停到最近的答案上。（一开始球在门上一直弹、要靠快速转动挑洞，4 个选项时要越过错的洞很难，键盘也跟不上，所以改成停下来选。）第一次掉进哪个洞就是答案（记一次作答）。对了变火球；错了洞口有盖子把球弹回来、那块牌子变灰，再选；连错两次，对的洞亮起来、题上写出答案，照样掉下去（不变火球）。题门前后一层不放刺。
- 题门要短选项，所以这款游戏 `shape = "choices"`：出题时（`sources.pick`）每道题都过 `sources.as_choices`，选择题留短的选项，答案是数、分数的计算题按容易算错的数配错误选项（差 1、差 2、差 10，小数点挪一位），写不成（题太长、拼写题）就换题源；单词只出认意思、看中文选英文。改成选一个以后容易了，所以换个题族单独校准（`<题族>:pick`），能力值还是同一个。倒下答题也是同一种题。
- 刺：碰到就倒下，和所有游戏一样答对 1 道就起来（`REVIVE_NEED`），起来以后刺软 1.5 秒。
- **路上的奖励**：连穿、火球、洞里的蜂蜜滴、每 1/4 一面旗（和「上次的我」比一比）、右边深度条上的 👻 上次的我（按这一关的纪录匀速往下）、超过它的提示；结算的星星、纪录、「再过 N 关打通这个世界」、贴纸照平台的来。
- **比快**：用时是自己的，球停在题门上想题的前 8 秒不算，比的是转得准、下得快，不是题答得快。三颗星：大家都到底、不倒下、题门一次答对。
- **1～4 人**（`players = (1, 4)`）：一个人就是一个人的房间；几个人同一座塔各跳各的（转动、题都是自己的），每 0.25 秒告诉大家掉到第几层，深度条上画出每个人（颜色跟角色走：太阳、莓果、薄荷、天空）。谁先到底谁第一，到了的人在终点看着、发表情加油；大家都到底了开房间的人报过关：用时是最后一个人的，题门一次答对的加起来；人多每多 1 人「不倒下」「题门」各放宽 1 次（`for_team`）。结算每个人看到自己第几个到底和全员用时。「一起」的贴纸（`awards.after_run`）一个人玩不发。
- 关卡 1000 关，6 关一个世界：晴空塔（白天场景，孩子选的主题换它的颜色）、糖果塔、黄昏塔、星空塔、火山塔，一轮一轮往下。层数 14 → 60，刺越来越多、洞越来越窄；第 2 个世界起有自己转的层，第 3 个世界起有一闪一闪的刺。题的难度不跟关卡涨，一直按自己的水平出。讨论稿：`docs/向下跳-讨论稿.md`（项目文件夹）。

### 5.49 学习报告：在哪儿答的题都算，按来源分开看（`app/records.py` 的 `answers / tally`）

- 每一次作答都记在事件表里（`kind='answer'`）：知识点的题（每日任务、练习、热身、复习、试卷重做、乐园、冲刺）、单词（热身、单词复习、游戏里的单词题）、阅读理解（`target='reading'`，交卷时每题一条，不进掌握度）。学习报告都从这里数：记录页的正确率曲线和「答题 · 正确率」、最近做题、一日记录、家长页、每周报告邮件、管理后台的统计。以前只数 `attempts` 表，单词和阅读理解从来没算进去，正确率曲线还专门排除了乐园和冲刺。
- 不算作答的：原卷上老师批的对错（`exam`）、诊断里的自评、复习卡片的「记得 / 不记得」（`kind='review'`）。术语卡挂了知识点、在游戏里答的，知识点那条证据也记成 `kind='review'`（和单词复习一样），一题只数一次。
- 五个来源：📚 学习和练习、🔤 单词、📖 阅读理解、🎮 乐园游戏、⚡ 冲刺。曲线的「全部」什么都算，另外能按学科、按来源切换着看；下面一行列出最近 7 天每个来源多少题、正确率多少。乐园和冲刺的题跟着水平自动调难度，正确率本来就在七成左右，所以每周进步卡「正确率提高」只比不算乐园和冲刺的正确率，写明「不算乐园和冲刺」；答题总数按来源分开写。


### 5.50 迭代日记：每一次调整背后的那个父亲（`app/diary.py`、管理后台 `/admin/diary`）

- 系统的每一次重要调整，背后是对孩子的一次观察、对学习的一次理解。代码和 PR 只记下改了什么；日记记下为什么，和那天心里在想什么。
- **谁写**：不是管理员填。有「为什么」的改动合并以后，由 Claude 用父亲的口吻写一篇草稿；同一天的几件事合成一篇；只修 bug、调排版的不写。管理员读，然后收下、改一改，或者不要（不要了的还能找回来）。
- **口吻**：第一人称，大白话，短句，留白；事后回头看；在一个小细节上停住；写父亲自己的着急、忍住、后悔、再试一次。只写真的事：没发生过的场景不编。
- **谁能看**：现在只有管理员（`diary.audience` 默认 `admin`，以后可以开放给家里人或所有人）。
- **隐私**：仓库是公开的，这里只有模块，没有日记。一篇日记是一个 Markdown 文件（开头 `day / title / quote / changes / prs / tags / status`，正文空行分段），放在服务器的 `DATA_DIR/diary/`，或在后台上传（也存进这个目录）。打开日记页时读一遍目录：新的进表；后台没改过的跟着文件变；后台改过的（`edited`）和不要了的，文件不再覆盖。
- 页面：时间线按月份一行一篇（日期、标题、最上面那一句、标签），草稿单独排在最上面；读一篇时宽度收窄、行距放大，末尾一行「那天改了什么」链到 PR，上一篇 / 下一篇翻着读。

### 5.51 积少成多：这一项 → 今天 → 一共（`app/growth.py`，表 `gains`）

讨论稿：`docs/积少成多-讨论稿.md`（在共享文件夹）。孩子只看得到今天和这一周，看不到每天一点点加起来有多少；好消息又都在今天页最下面折起来。

- **一共，只增不减**：答过的题（5.49 的作答口径，在哪儿答的都算）、学会过的知识点、认识的单词（答对过一次就算）、学习的天数。知识点第一次变成「学会了」时记进 `gains`（`evidence._save` 里写，以后又不稳了也不删，那个点回到「再练练」）；上线时按掌握表回填。孩子端不出百分比、不出「答对多少道」（基础弱的孩子这个数涨得慢，反而提醒他错得多）。
- **每天第一次打开**：不弹窗（弹窗挡在主按钮前面，孩子很快学会看都不看就关）。今天还一项没做时，主卡里小伙伴的气泡说上次学了什么、一共攒了多少（`growth.hello`）：「昨天你答了 46 道题，学会了『××』！到今天一共 1,284 道啦！」；快到里程碑说「再答 5 道就到 100 道了，今天就能到！」（只在照昨天的量今天够得着时说）；隔了几天说「欢迎回来！你一共学会了 63 个知识点，今天接着来！」，从不说「你没学」「断了」；周一说上周学了几天。做了第一项以后回到平常那几句。初中以上只说事实、不加「啦」和感叹（`growth.teen_of`）。主卡第一行多一个「📚 一共 N 道」，点了去记录页。
- **做完一项**（`flow_state` 带 `grow`，「下一项」卡上）：「这一项 12 道 · 今天 46 道 · 一共 1,284 道」，一共那个数从旧的跳到新的（孩子做完事以后才动；系统设置了减少动画就直接显示）；这一项里第一次学会的知识点带名字和「第几个」。「这一项」从上一项做完数到这一项做完（`done_at`），不算中间去冲刺、乐园答的。
- **里程碑**：答题 100 / 200 / 500 / 1,000 / 2,000 / 3,000 / 5,000 / 7,500 / 10,000，之后每 5,000；知识点 10 / 25 / 50 / 75 / 100 / 150 / 200 / 300，之后每 100；单词 50 ～ 3,000，之后每 1,000。越往后越稀，不天天放烟花。跨过时（做完一项的卡上，或者在冲刺、乐园里跨过的回到今天页时）撒花一次，一句话把第一天拿出来比（「第 1 天是 23 道，是你一天天攒起来的」）。只庆祝，不换 ⭐ 也不加乐园时间（事先说好的奖励会削弱兴趣）。每个只庆祝一次，记在 `gains`；上线那天已经跨过的悄悄记成庆祝过。
- **记录页「我的积累」**（孩子自己看）：四个「一共」；装满的罐子（一罐 100 道，3,000 道以后一罐 1,000 道），罐子和名字跟着主题换（`theme.toml` 的 `[grow]`：蜂蜜 🍯 罐蜜、太空 🪐 颗星球、舞台 💡 盏灯、海洋 🐚 个贝壳），颜色用主题的 `--brand`；最近 12 周每周结束时一共多少，一周叠一周，顶上一截是那周新加的；最近两周学会的知识点；离下一个里程碑还差多少。家长看报告时保持原来的样子，多一句「从第一天到现在」的同一组数，周报邮件也加这一句，家长可以照着夸具体的事。
- 所有的话按规则拼出来，不调 AI。
