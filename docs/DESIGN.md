# AIStudy 设计文档

## 1. 目标

一套能陪孩子从小学一直学到高中的网页系统：

- **同一套系统，不同教材**：教材是可插拔的数据，不写死在代码里。
- **向后补、向前学**：知识点之间有前置关系，诊断时沿前置往回追找断点，学会后沿后续往前预习。
- **门槛低**：每件事都拆成小步骤；先做最简单的一步；卡住了有提示、有「退一步」。
- **完整记录**：每道题、每次复习、每个查过的词、每天的反思都留下来，家长随时能看。
- **简单稳定**：一个 Python 应用 + 一个 PostgreSQL 数据库，一台 1 核 1G 的云服务器就能跑；一键安装/升级；AI 只在服务器端调用。

## 2. 架构

```
浏览器（孩子 / 家长，手机优先）
   │  服务端渲染页面 + 少量原生 JS 调 /api/*
   ▼
FastAPI 应用（app/main.py）
   ├─ catalog.py   教材目录：加载 curricula/*.json，提供知识图谱查询（前置、后续、祖先）
   ├─ engine.py    学习引擎：诊断回溯、间隔复习、错题本、统计
   ├─ evidence.py  学习证据：事件表 → 当前学习方式的模型 → 掌握状态；换方式时按事件重放（见 5.0）
   ├─ methods/     学习方法：掌握模型（mastery.py）、记忆模型（memory.py）、学习方式配置（profiles.toml）
   ├─ plan.py      每日计划：任务来源 + 按学习方式的策略排
   ├─ itemtypes.py 题型注册表：判分、显示、证据题型、蒙对概率、AI 题整理、前端控件
   ├─ llm/         AI 抽象层（见第 6 节）
   │   ├─ base.py       Provider 接口、ChatRequest、LLMError
   │   ├─ providers.py  anthropic（Claude）/ openai_compat（DeepSeek、通义…）/ mock
   │   ├─ settings.py   读取 config/llm.toml
   │   ├─ service.py    选提供方、缓存、每日限额、解析 JSON
   │   └─ tasks.py      具体任务的提示词：查词、讲解、出题、造句点评、写短文
   ├─ auth.py      账号系统（见第 3 节）
   ├─ db.py        数据库访问：PostgreSQL（生产）/ SQLite（本地试用、测试），统一 ? 占位符
   ├─ migrate.py   数据库迁移：按编号执行 migrations/*.sql，记录在 schema_migrations
   └─ cli.py       命令行：migrate / check / backup / create-admin / reset-password / invite …
数据：curricula/（教材知识图谱） seed/（人工核对过的题库、术语卡） PostgreSQL（全部账号和学习记录）
配置：.env（服务器、数据库、账号策略） config/llm.toml（AI 提供方、模型、密钥、按任务路由）
      config/methods.toml（可选：覆盖 / 新增学习方式，默认配置在 app/methods/profiles.toml）
运维：install.sh（一键安装/升级：环境检测 → 装依赖 → 拉代码 → 建库 → 备份 → 迁移 → systemd → Caddy HTTPS → 健康检查）
```

为什么这样选：

- **服务端渲染 + 原生 JS**：没有前端构建步骤，部署就是复制文件；手机浏览器打开即可用。
- **PostgreSQL**：单机就能装，稳定、并发好，多个家庭一起用也没问题；`pg_dump` 备份。本地试用和自动测试仍可用 SQLite（改 `DATABASE_URL` 即可），两种数据库跑同一套测试。
- **迁移脚本**：表结构只通过 `migrations/NNNN_xxx.sql` 改动，升级时自动执行，已执行的不会重复。新增字段就加一个编号更大的文件，不改旧文件。
- **AI 在服务器端**：密钥不会出现在孩子的浏览器里；所有调用有缓存和每日上限。

## 3. 账号

- **角色**：网站管理员（admin，第一个注册的账号；只用管理后台）、家长（parent：添加孩子、查看和管理）、孩子（kid，属于某个家长；只有孩子账号能做题学习）。
  `is_admin=1` 表示有管理后台权限；旧版本里「第一个家长」账号保留家长 + 管理员两种身份。
- **家长只读**：家长在家长页选中孩子后，可以看今天的清单、学科、知识地图、记录、单词本，可以更新学校进度、导入试卷、改试卷的知识点；
  做题、阅读、复习、打卡、提问这些「学习」接口都要求孩子本人登录（`kid_or_redirect(manage=False)` 默认拒绝家长）。
- **家长注册**由站点设置里的注册方式决定（管理后台「站点设置」，默认取 `.env` 的 `REGISTRATION`）：`approval`（默认：有邀请码直接开通，没有的提交申请等管理员审批）/ `invite`（必须邀请码）/ `closed`（只能管理员创建）/ `open`。管理员和家长都能生成邀请码，`users.invited_by` 记录邀请关系。
- **孩子账号**由家长在网页上创建：名字、登录邮箱、密码、年级、每天学习分钟数、学校，以及要学的教材包和当前学段；家长可以改孩子密码、暂停孩子账号。
- **密码**：PBKDF2-SHA256，20 万次迭代，每个密码独立随机盐。
- **会话**：登录后生成随机令牌，cookie 里放令牌（已签名），数据库 `sessions` 表只存它的 sha256。退出、改密码（其他设备自动下线）、停用账号、在「我的账号」里踢掉某个设备，都立即生效。
- **防暴力破解**：同一账号连续输错 `LOGIN_MAX_FAILS` 次锁定 `LOGIN_LOCK_MINUTES` 分钟；`python -m app.cli unlock 邮箱` 可手动解锁。
- **账号管理**：家长在「资料与密码」里管自己的孩子，管理员在「账号管理」（`/admin/users/<id>`）管任何其他账号。两处共用同一套操作（`main.account_action`）：改名字和邮箱、重置密码、解除锁定、退出所有设备。
  - 重置密码时可以直接输入新密码，留空则生成一个好读的临时密码（只在页面上显示一次）。
  - 勾选「下次登录要求改密码」会设 `users.must_change_pw=1`，对方登录后除了「我的账号」页哪里都进不去，改完密码自动清除。管理员重置家长时默认勾选，家长重置孩子时默认不勾。
  - 管理员也可以改发一次性重设链接（48 小时有效）。管理员自己忘记密码用命令行 `reset-password`。暂不发邮件。
- **孩子的教材**：每门课只选一个教材版本，学段按孩子年级自动对应（`catalog.default_stage`）；年级没变、教材没换时保留原学段（「学校进度」里可能已经往后调过）。
- **安全日志**：登录成功/失败、锁定、改密码、停用、生成重设链接等都记在 `auth_events`，管理页可看最近 100 条。
- 孩子只能看到自己的数据；家长能看自己孩子的总览和报告；管理员能看所有家庭和孩子的情况。

## 4. 教材数据模型：四层，各自独立、各自扩展

不同年级、学科、学校类型的孩子用的教材都不一样，还会不断增加，所以教材数据分成四层。
每一层只依赖它下面的层，每层都可以单独扩充。孩子自己的选择存在数据库里，不进教材文件。

```
孩子的选择（数据库）    年级 · 学校类型/模板 · 每科选哪套教材、哪个方向 · 学到哪 · 掌握情况
        │
学校模板 _meta/presets.json   上海公办小学/初中/高中、民办双语、国际学校剑桥路线……（预填，可逐科改）
        │
关联层   _links/*.json         concepts（同一概念跨教材互认）· links（uses / language / context）
        │
教材包   curricula/*.json      一套教材 = 板块 + 知识点（+ 方向 tracks）；包与包互不依赖
        │
学段     _meta/stages.json     所有学制放在同一根「学年」轴上（G1–G12、IGCSE、A-Level、IB MYP/DP、AP）
```

### 4.1 学段（`curricula/_meta/stages.json`）

每个学段有 `id`、`system`（cn / cambridge / alevel / ib / us / uni）、`label` 和 `year`。`year` 是「相当于中国几年级」，例如 IGCSE = 9.5，MYP3 = 8，DP1 = 11，大一 U1 = 13。

- 不同学制的知识点靠 `year` 比先后，诊断回溯和跨教材推断都用它。
- 学制（`systems`）带 `international` 和 `lang`：这个学制的课默认用什么语言授课和出题。代码不再按教材 id 猜。
- 没有统一学制的课程（少儿编程、某个技术栈、兴趣课）用 `course` 学制，级别在教材包里自己定义（见 4.2 的 `levels`）。
- 加学制或年级只改这个文件。孩子的「年级」从 `grades` 里选，`default_grade` 是新建孩子时的默认值。

学科表 `curricula/_meta/subjects.json`：学科 id、名字、图标、颜色、领域（language / math / science / humanities / social / computing），语言类学科还有 `lang`（它教的是哪种语言）。加学科只改这个文件，页面上的图标、语言课的判断都从这里来。

### 4.2 教材包（`curricula/<pack_id>.json`）

```json
{
  "pack": {"id": "eng-cambridge", "subject": "english", "subject_name": "英语", "edition": "剑桥英语（…）",
           "region": "国际学校", "system": "cambridge", "school_types": ["international", "private"],
           "tracks": [{"id": "0511", "name": "IGCSE ESL 0511（口语计入总分 25%）"}, {"id": "0510", "name": "…"}, {"id": "0500", "name": "…"}],
           "default_track": "0511", "stages": ["G3", "…", "IGCSE"], "version": 2, "verified": "2026-10-06",
           "sources": ["官方大纲 / 教学用书目录 URL"], "notes": "版本说明、学段对应、考试结构"},
  "strands": [{"id": "REA", "name": "阅读"}],
  "kps": [{"id": "ENG-REA-12", "strand": "REA", "stage": "IGCSE", "syllabus": "0510/0511 Paper 1 Ex3",
           "tracks": ["0510", "0511"], "name": "笔记补全", "name_en": "Note completion", "desc": "…",
           "prereqs": [{"id": "…", "strength": "必须"}], "hot": true, "method": "…", "probe": "…", "terms": ["…"],
           "source": "这个点的依据"}]
}
```

- **知识点 id 全局唯一，而且永不修改**，因为学生数据按 id 记录。内容变了就改字段；要删除先评估影响。
- **方向（tracks）**：同一套教材里不同考试或难度的分支，例如剑桥英语 0511 / 0510 / 0500、IGCSE Core / Extended。
  - 知识点带 `tracks` 字段，表示只属于这些方向；不带，表示所有方向都要学。
  - 孩子在每套教材上选一个方向（存在 `enrollments.track`），没选就用 `default_track`。
  - 诊断、计划、地图、进度、统计都只看所选方向的知识点：`catalog.ids_for(pack, track)`、`engine.my_ids(user, pack)`。
- **prereqs**：「必须」用于诊断回溯和补漏，「有帮助」只做展示。前置的学段不能晚于本点，否则自动降为「有帮助」。
- **school_types / system**：「编辑孩子」时把适合这类学校的教材排在前面。其它教材仍然可选，用于转学或提前学。
- **kind**：`textbook`（审定教材，如统编、沪教）/ `syllabus`（考试局大纲，如剑桥 IGCSE）/ `course`（没有统一教材的课程：少儿 Python、大学线性代数、某个技术栈）。不写时按学制推断：cn → textbook，国际学制 → syllabus，其它 → course。
- **teach_lang / item_lang**：授课语言、出题语言。不写时：语言课的题目用它教的语言（语文课讲解也用中文）；其他学科按学制（国际学制英文，否则中文）。题库按 `item_lang` 分语言，AI 出题和讲解的说明也按它生成。
- **levels**：`course` 没有年级时自己定义级别，例如 `[{"id": "PY-L1", "label": "入门", "year": 3}]`。级别挂到学段轴上，和年级比先后，知识点的 `stage` 引用它。大学课程直接用 U1–U4。
- **prompt_note**：给 AI 出题、讲解时的额外说明，比如「代码用 Python 3，不用第三方库」。不用为某门课改代码。
- 编程类题目用现有题型加 `code` 字段（一段代码，页面按代码块显示）：读代码写输出用填空，选哪段代码对用选择。
- **加一套教材**：往 `curricula/` 放一个 JSON 文件，跑 `python -m app.cli check-curricula` 通过即可。CI 也会跑这一步。
- 题库 `seed/items_*.json`、术语卡 `seed/vocab_*.json` 按知识点 id 挂靠。

### 4.3 关联层（`curricula/_links/*.json`）：学科独立，课上融合

教材包之间互不引用（基础前置点除外），跨学科的融合单独放在关联文件里。加关联不动教材，删掉一个关联文件也不影响教材。

现有关联文件按领域分：`core.json`（第一批）、`math.json`（沪教 ↔ 剑桥 ↔ 前置，理科用到的数学）、`science.json`（理科同一概念、理科互用、中英术语）、`language.json`（语文 ↔ IGCSE 中文、上海英语 ↔ 剑桥英语，英语和语文、地理的融合）、`history.json`（历史和语文、地理、英语、理科）、`economics.json`（经济和数学、地理）。同一个知识点只能属于一个概念，`check-curricula` 会检查。

- **concepts**：同一个概念在不同教材里的知识点。例如「密度」在沪科版物理、剑桥物理、Lower Secondary Science 里各有一个点。
  - 孩子学会其中一个，其它几个如果还没测过，就推断为「学习中」（`engine.infer_equivalents`）。
  - 这样转学、换教材、公办转国际，都不用从零开始。
- **links**：有方向的关联。
  - `uses`：from 用到 to。例如物理「速度」用到数学「速度、路程、时间的数量关系」和一次函数。
  - `language`：同一内容的另一种语言说法。例如物理术语和英语词汇。
  - `context`：背景知识。例如英语阅读话题和语文、历史、道法里学过的内容。
- 融合在上层应用里的落点：
  1. **学习页「🔗 和别的学科连起来」**（`engine.bridges`）：列出同一概念、要用到、会用在、相关背景，孩子已经会的排前面。
  2. **AI 讲解**：把孩子在别的学科已经学过的相关内容写进提示，让讲解从已知的东西引入，比如「你在数学里学过……」「英语里叫……」。
  3. **语言阅读选题**（`engine.cross_topics`）：英语阅读用最近在物理、科学、历史里学过的内容（用英语学内容）；中文阅读用历史、道法、科学的内容。
  4. **掌握度互认**：见上面的 concepts。

### 4.4 学校模板（`curricula/_meta/presets.json`）

模板是常见的「学校类型 → 各科教材 + 方向」组合，比如上海公办小学、上海公办初中、民办双语、国际学校剑桥路线。

- 家长在「编辑孩子」里选了学校类型，各科教材和方向会自动选好（孩子这个年级还没开的科目不预选），仍然可以逐科修改。
- 选择记在 `users.preset` 和 `users.school_type` 里。
- 新的学校类型加一条模板就行。模板引用的教材必须存在，由 `check-curricula` 校验。

### 4.5 校对与来源

2026-10 对照上海市教委教学用书目录、教育部目录、上海市教育考试院和剑桥官方大纲做过一次校对，报告和上海教材全景见 `docs/curricula-audit/`。

- 新教材包也按同样的要求建：每个知识点写 `source`，查不到依据的记进 unverified，不凭记忆编。
- 知识图谱依据课程标准、考纲和教材目录整理，**没有复制教材原文**。

## 5. 学习引擎

### 5.0 学习方式（教学理念）和扩展点

学习方法会不断研究、引入，所以「方法」和「记录」分开：

- **学习事件表 `events` 是唯一的原始记录**：做题、复习卡片、单词摸底、推断、自评、导入，每条证据一行（`target` = kp / word / card）。
- **一种学习方式 = 掌握模型 + 记忆模型 + 每日计划策略 + 参数**，写在 `app/methods/profiles.toml`。现在有三种：
  - 均衡（默认）：检索练习 + 间隔复习 + 交错练习 + 掌握学习。
  - 先学牢再往前：掌握学习，标准更严（90%、3 天），先补前置，不预习。
  - 考前冲刺：高频考点和薄弱点优先，复习更勤（保持率 90%），不预习、不摸底。
  家长在孩子资料页给每个孩子选，管理员在后台设全站默认。
- **掌握状态是算出来的**：`mastery.model` 记着算它的模型指纹（模型 + 版本 + 参数）。换方式、调参数、升级算法后指纹变了，就按事件重放（启动时自动做，换方式时立即做），新方法马上用上全部历史，旧记录一条不丢。
- **扩展的地方都只有一处**：
  - 调参数、加一种学习方式：写 `config/methods.toml`（同名覆盖，新名新增），不改代码。
  - 换一种算法：在 `app/methods/` 写一个实现同样接口的类（掌握模型：`step / judge / missing / needs_work / now_p`；记忆模型：`recall / interval / review`），登记到 `app/methods/__init__.py` 的注册表，在配置里用 `model = "名字"` 引用。
  - 加一类每日任务：在 `app/plan.py` 写一个来源函数，登记到 `SOURCES`，在学习方式的 `plan` 里排上。
  - 加一种题型：在 `app/itemtypes.py` 写一个子类（判分、显示、证据题型、蒙对概率、AI 题整理、前端控件）。
- 单元测试 `tests/test_units.py` 覆盖模型、配置、题型、教材元数据，改算法时先跑它。

### 5.1 掌握度

每个孩子 × 每个知识点一条记录：真懂的概率、记忆稳定性、做题数、正确数、证据、状态（未测 / 薄弱 / 学习中 / 已掌握）、模型指纹。下面是默认学习方式「均衡」的掌握模型（`app/methods/mastery.py` 的 BKT）；实时更新和按事件重放都走同一个纯函数 `step`。

- **真懂的概率**用贝叶斯知识追踪（BKT）估算：按题目的蒙对概率（四选一 25%，填空 / 计算约 5%）和粗心概率（10%）更新，所以选择题答对只加一点，粗心错一次也不会掉到底。题库里大家几乎都对的题，答对算的证据弱一些；大家都错的题，做错算的证据弱一些。点「还不会」是很可靠的证据。
- **遗忘模型**用 FSRS 的记忆公式：记忆稳定性 S（天），隔 t 天还记得的概率 R = (1 + t/9S)^-1。隔得久、R 低时答对，S 涨得多；当天反复答对几乎不涨。现在真懂的概率 = 上次的估计 × R。
- **掌握要交叉验证**：概率 ≥85%，答对过 ≥2 道不同的题，在 ≥2 天里答对过，并且 ≥2 种题型（只有一种题型时换 ≥3 道题）。诊断、摸底答对也只是一条证据，不会直接算掌握。
- **薄弱也要证据**：概率 <35%，并且不同的题错过 ≥2 次或自己点过「还不会」。
- 每日计划里会安排「确认一下」（昨天以前答对过、还差隔天 / 换题型证据的）和「该复查了」（记得的概率掉到 85% 以下的）。取题时优先没用过的题型。
- 推断出来的（同一概念、前置、自评、导入）只给一个概率，不算证据。学习页会显示概率、记得多少、已有的证据和还差什么。

### 5.2 诊断（向后回溯）

1. 取当前学段和上一学段的知识点，每个板块至少挑一个，优先高频点和有现成题的点，共约 8 个起点。
2. 每个点出 1 道题（有现成题用现成题，否则 AI 出题；AI 不可用时让孩子自评「会 / 不太会」）。
3. **做错 → 把它的「必须」前置插到队首继续测，最多追 3 层**；最多 18 题。
4. 报告里区分「断点」（做错、但前置都没问题的点——最该先补）和「需要加强」；答对的点，其前置推断为大概率已掌握。

### 5.3 每日任务清单

每天第一次打开时生成（可点「重新安排」；已经做完的任务即使新计划里没有了也保留打勾）。代码在 `app/plan.py`：每类任务一个来源函数，排哪些、什么顺序、每类几个由学习方式的 `plan` 决定（`fixed` / `flex` / `limits` / `prefer_hot`，`"weak+backfill"` 表示交替）。下面是默认「均衡」的排法，分两部分：

**固定项**（每天都有，不截断——坚持比做对更重要）

| 顺序 | 任务 | 来源 |
|---|---|---|
| 0 | 更新学校进度 | 有学科超过 14 天没更新进度时出现 |
| 1 | 单词 | 到期的生词/短语/术语卡片，含当天按词表加入的新词（`tracks.kind=words`） |
| 2 | 错题回顾 | 到期的错题卡片，最多 8 道 |
| 3 | 英语阅读 | 家长安排的英文读物（`read_en` track，今天读哪一段），否则 AI 短文 15 分钟 |
| 4 | 名著接着读 | 家长安排的中文书（`read_zh` track，按回目/章节接着读），否则中文阅读 15 分钟 |

**学习项**（按每天可用分钟截断，至少保留一项）

| 类型 | 来源 |
|---|---|
| 跟上学校 `sync` | 孩子/家长设置的「正在学」知识点，还没掌握就练（每天最多 2 个） |
| 试卷订正 `paper` | 导入了还没订正完的试卷 |
| 诊断 `diagnose` | 还没诊断过的学科，一次一科 |
| 补弱 `weak` / 补前置 `backfill` | 薄弱/低分学习中的知识点；它的必须前置没掌握就先补前置；两者交替 |
| 回顾小检查 `check` | 学校学过（勾选的 + 以前学段）但系统里还没检测过的知识点，每天轮换一个，限当前学段往前两段 |
| 预习 `preview` | 设置了进度：同一板块里「正在学」之后、前置已学过的下一个；没设置进度：前置已具备的当前/下一学段知识点 |
| 知识点回顾 `review` | 到期的知识点总结卡片 |

完成练习、复习、阅读、诊断、试卷订正时，对应的任务自动打勾并 +1 ⭐。

### 5.3.1 课程进度（个性化推进）

学校进度对不齐是每日计划最大的难点，系统不去猜，而是让孩子/家长自己维护（`/progress`，1 分钟）：

- 每个教材包：当前学段、「现在学校正在学」的知识点（`enrollments.progress_kp`）、本学段已经学过的知识点（`kp_taught`）。
- 「学过」= 以前学段的全部 + 本学段勾选的。系统据此：跟上「正在学」、在学过的范围里往回抽查、顺着前置关系补漏、在同一板块往前预习一步。
- 掌握度（`mastery`）和「学过」是两回事：学过但没检测的会被「回顾小检查」轮到；检测出薄弱的进入补弱和补前置。这样形成一张网：往回巩固、相互补漏、往前推进。

### 5.3.2 试卷

`/papers`：拍照（浏览器先压缩到长边 1800px）或粘贴文字 → `llm.parse_paper`（任务名 `paper`，需要能看图的模型）一次完成拆题、作答、讲解、从候选知识点（当前学段往前两段、往后一段）中选 `kp_id`、读出卷面答案和批改痕迹。

- 题目存入 `items`（`source='paper'`），卷子和每题的原卷对错、在线作答存 `papers` / `paper_items`。
- 原卷判错/扣分的题：记一次 `exam` 作答（计入掌握度）并进错题本。
- 在线重做：自动判分或自评，可点「还不会」；觉得 AI 答案不对可以标记，这题不计入诊断；知识点对得不准可以手动改。
- 诊断：按知识点汇总原卷丢分和重做结果；重做还错/还不会的是「要补的」，并列出没掌握的前置；原卷错但重做对的列为「可能粗心」。

### 5.3.3 划词查词插件

`extension/` 是 Chrome MV3 插件。孩子账号在「查词工具」页生成连接码（`api_tokens`，只存 sha256），插件用 `Authorization: Bearer` 调 `/ext/me`、`/ext/lookup`、`/ext/save`。加入的词成为 `word`/`phrase` 卡片，进入每天的「单词」任务。下载的 zip 会自动写好服务器地址。

### 5.4 一个知识点的学习步骤

看懂（说明 + 关键词 + 可选「AI 一步步讲」）→ 记方法 → 做 3 题（从易到难，每题有提示；连错两题提示退一步补前置）→ 一句话总结（变成复习卡片）。页面下方同时列出「往回：前置知识」和「往前：后续知识」。

### 5.5 间隔复习

卡片类型：生词、术语、错题（做错自动加入）、知识点总结。按学习方式的记忆模型排期（默认：下一次复习排在「记得的概率」降到 85% 的那天，「考前冲刺」是 90%）；「忘了」当天再来，稳定性回落。单词摸底四选一认出来的词，三天后会换成「看中文写英文」复查，写不出来就不算认识。

### 5.6 阅读

- 来源：AI 按年级写略高一点的短文（i+1），自动嵌入孩子最近要复习的生词，附 3 道理解题；或者粘贴自己的书/课文。
- 英文：每个单词可点；中文：选中字词查询，点句子可问「这句什么意思」。
- 查词结果贴合原句意思；可一键收藏（带原句进入复习）、用它造句（AI 先表扬再指出一个最重要的问题，给改正句和示范句）。
- 读完打卡记录时长和理解题结果。

### 5.8 自动发现问题（`app/insights.py`）

每次生成计划时检测一遍，结果存 `insights` 表（新出现的插入，还在的更新，消失的标记为已解决）：

| 类型 | 信号 | 变成的任务 |
|---|---|---|
| root 根源前置 | 两个以上没掌握 / 最近做错的知识点，共用同一个没掌握的必须前置（往回 3 层） | 补根源 |
| dont_know | 14 天内同一知识点点了 2 次以上「还不会」 | 再练练 |
| asked | 同一知识点问了小助手 2 次以上 | 再练练 |
| slow 做对但慢 | 做对的题平均用时超过 60 秒且超过孩子自己中位数的 2 倍（`attempts.ms`） | 再练练 |
| forget_words / forget_kp | 卡片复习「忘了」2 次以上 | 单词任务里重点复习 / 再练练 |
| lookup_repeat | 同一个词查了 2 次以上还没收藏 | 自动加入单词本 |
| decay 久未复习 | 已掌握但 30 天没练、在学过的范围内 | 回顾小检查 |
| careless | 试卷原卷错、在线重做对 | 提醒考试检查 |
| habit / reading_gap（只给家长） | 近 7 天学习天数 ≤ 4；某本书 4 天没读 | — |

计划里，最重要的一条排在「跟上学校」后面且不会被时间截掉；其余的排在补弱 / 补前置 / 回顾小检查各自的最前面，任务说明带 🔍 和发现的原因。孩子在「今天」页看到对自己有用的几条，家长页和学习报告里能看到全部。

### 5.9 摸底探索：解决冷启动（`app/explore.py`）

孩子不管几年级进来，过去几年的知识点掌握情况系统都不知道。不靠一次长考试，而是每天穿插少量「以前学过的」小题，让个性化快速收敛：

- **范围**：每个教材包里当前学段之前的知识点，加上本学段学校已经教过的（`past_range`）。
- **选题**（`candidates`）：在范围里的未测知识点中，按信息量打分：`2 × 未测的必须前置数 + 被范围内未测知识点依赖的次数 + 4（和学校正在学的有关）+ 2（高频）`。答对一题能推断一串前置，所以优先测「高处」的点；各学科轮流；一周内测过的不再抽。
- **作答**（`after_probe`，attempts.mode = `probe`）：答对记为掌握，2 层以内未测的必须前置记为「推断掌握」（source = inferred，score 0.65）；答错 / 还不会记为薄弱并进错题本，它没掌握的必须前置进入 `probes` 队列（最多往回 3 层），之后优先测。
- **投放**：每日清单最前面的「热身」（`/warmup`，3 道知识点题 + 2 个旧单词，约 4 分钟）；知识点练习的第 2 题穿插一道这个知识点没测过的前置（`/api/practice`）。
- **英语旧单词**：从孩子年级及以下的核心词表抽词四选一（干扰项来自同一词表），优先测得少、离当前年级近的词表；不认识的自动加入单词复习；按词表认识率（拉普拉斯平滑）估算词汇量，测满 10 个后显示。
- **可见**：「今天」页「我的学习地图」（每科摸清百分比、今天点亮的知识点、词汇量估计）；家长页同样显示。
- **前方**（`ahead`）：每科的下一站（进度之后的下一个，否则当前学段第一个未学的）、必须前置准备了几个、还差哪个、学会后能学什么。
- **点亮**（`lights` 表）：一个知识点第一次变成「已掌握」时记一笔，答题结果里返回 `lit`，前端放礼花。

### 5.10 网站内划词（`app/static/app.js` 的 `SelMenu` / `QuickLook`）

孩子账号在网站任何页面选中文字（输入框、阅读器除外，阅读器有自己的点词查询）弹出菜单：查词（短词）/ 翻译（句子，`/api/translate`）/ 加入复习（`/api/collect`，AI 查好意思再存）/ 问小助手。
自动记录规则（`_auto_collect`）：同一个词或句子查第二次，或在题目上划词查的，直接加入复习卡片，extra 里记 `why`。
「阅读 → 打开一篇网页文章」：服务器只抓公网 http/https（每次跳转都重新检查 IP，拒绝内网 / 本机 / 保留地址），限 3 MB、12 秒，只取正文段落（`app/webpage.py`）。

### 5.7 问一问小助手（引导式提问，默认名「小艾」，`.env` 里 `ASSISTANT_NAME` 可改）

孩子页面右下角常驻按钮（诊断页除外）。前端带上当前上下文：孩子最近点过 / 屏幕上的那道题（`renderItem` 给题目框标 `askable` 和题目 id）、是否已作答、选中的文字、页面标题、知识点。
服务器取出题目的正确答案和讲解，作为「只给小艾参考、绝不能说出」的内容放进提示词（`llm.ask_tutor`，任务名 `ask`）。
回复要求：苏格拉底式，一次只推进一小步、以问题结尾；连续卡住就退回更基础的知识；模型自报 `reveals_answer` 为真时重新生成一次。
对话存 `ask_threads` / `ask_messages`，同一道题接着问，换题自动开新对话；家长在学习报告里能看到。计入每个孩子每天的 AI 次数上限。

### 5.11 跟自己比（`app/records.py`，前端 `Run`）

目标是让孩子越学越想学，而不是堆功能：只跟自己比，没有排行榜、积分商城、抽奖。

- **一组（run）**：热身、单词复习、错题回顾、知识点回顾、知识点练习、阅读，每做完一组 `POST /api/run` 记一笔（`runs` 表：题数、答对、专注毫秒、总毫秒、最长连对、破了哪些纪录）。服务端会把数字收在合理范围内。
- **专注计时**：只在页面可见、而且最近 60 秒内有点击、打字或滚动时才计时。
- **个人最好（PB）**：每类任务比答对最多、最长连对、每道答对的题平均用时（只在热身和三种复习上比，因为这些是学过的内容）；最长专注跨所有任务比。正确率低于 80% 的一组不算答对和速度纪录。每类任务的第一组只立纪录，不算破纪录。
- **上周的我**：过去 7 天（不含今天）这类任务每道答对的题平均用时。进度条上的 👻 按这个速度前进，🏃 是答对的题数。
- **每周进步卡**：上周（周一到周日）和再上一周比，只列进步的地方（更快、正确率更高、点亮几个、破几次纪录、专注多少分钟），最后总是写学了几天、做了几道。上周没学就不出卡。周一在「今天」页默认展开，家长页一行显示。

### 5.12 乐园：按个人水平出题的游戏（`app/arena.py`、`app/quickgen.py`，前端 `arena.js` / `stickman.js`）

孩子底部导航的「🎮 乐园」。第一款游戏是「火柴人大战」（单机打电脑）。

**第一原则：PK 比的不是知识，也不是谁做同样难的题，而是当下学习的专注和投入。** 每个孩子拿到的题难度不同、答对的概率相同；在这个前提下谁更投入，谁赢的机会更大，学习效果也更好。积分、战报、胜负都围绕这一点设计。其次：游戏本身要好玩，学习是游戏的燃料。

- **专注指数**（战报里最显眼的数）：实际答对题数 ÷ 预期答对题数（每题出题时预测的答对概率之和）× 100。100 是正常发挥，高于 100 是比平时的自己更投入；3 秒内答错算「猜」，单独提醒。答题少于 3 道不算。

- **分层**：游戏只写玩法；出题、判分、经验值、冷冻、时长限制都在服务器（`arena.py`）；答题面板 `ArenaQuiz`（`arena.js`）所有游戏共用。以后加游戏只要写玩法、在 `GAMES` 里登记目标答对率，不碰积分和出题。
- **快题**（`quickgen.py`）：对战里每题要 20 秒内答完，题库里的题往往太长，所以按题族现场生成口算、短计算题，答案由程序算出。一个题族挂一个知识点（沪教版数学一到六年级的 24 个点），分 1–5 级。生成的题不进 `items` 表，题目 id 是 `gen-<题族>-<指纹>`。
- **公平的出题**（IRT / Elo 式）：孩子在每个知识点上有能力值 θ（`arena_ability`），每个（题族, 级别）有难度 b（`arena_calib`），答对概率 p = 1 / (1 + e^-(θ − b))。
  - θ 起点取自掌握度（BKT 的「现在还记得的概率」，没做过的按学段估），每答一题在线更新，新孩子步子大、很快定位；b 由全体孩子的作答在线校准，步子更小。
  - 选级别：在答对概率刚好高于、刚好低于目标的两级之间按比例混着出，平均下来正好是目标（火柴人 75%）。学得快的孩子拿到难题，学得慢的拿到适合他的题，大家答对的机会一样。
  - 选知识点（`kp_pool`）：不超过孩子当前学段；学习中、薄弱的多出；最合适的一级也离目标很远的知识点少出（太难或太简单就换别的点）。
  - `tests/test_smoke_arena.py` 用模拟验证：真实水平差很多的孩子，答对率都落在目标附近。
- **经济规则**（只在 `arena.py` 写一处）：答对得经验值 70–150（期望 100），8% 暴击翻倍；每连对 3 题攒一次必杀；答错冷冻 5 秒，3 秒内连续瞎答冷冻 8、12 秒；当天游戏经验值超过 5000 后减半。用时用服务器计时，关掉答题面板 90 秒内再打开还是同一道题（不能换掉难题）。经验值只在乐园里用，账本 `arena_ledger` 只追加。
- **学习记录**：游戏里每次作答照常进 `attempts` / `events`（mode = `game`），更新掌握度；不计入每天的学习打卡和学习分钟，做错的题不进错题本。
- **时长**：家长在「资料与密码」里设每天最多玩几分钟（0 / 10 / 20 / 30 / 45 / 60，默认 20，存在 `users.settings.game_minutes`），按每局开始到结束的时间算；家长页显示本周玩了多久、答了几道题。
- **公平看板**（管理后台「游戏公平」）：按孩子在数学上已掌握的比例分 4 组，对比各组的预测答对率、实际答对率、每分钟经验值、打赢电脑的比例；各组实际答对率都接近目标，说明出题是公平的。下面列出每个（题族, 级别）校准后的难度。
- **火柴人大战玩法**：走、跳、出拳耗能量（就是经验值），能量快没时答题按钮闪烁，没了就打不动、走得慢；答题时进入充能姿势，受到的伤害减半；用能量换木棍、护盾、剑、激光；电脑也会「答题」，答对率和孩子的目标一样（75%），领先太多时会收着打。

## 6. AI 抽象层与使用原则

- **配置和代码分离**：提供方、模型、密钥、每日上限、按任务路由都在 `config/llm.toml`（模板 `config/llm.example.toml`），改完重启服务生效，不用改代码。值可以写成 `"${环境变量}"`。
- **抽象**：业务代码只调用 `app.llm` 里的任务函数；任务函数把请求包装成 `ChatRequest` 交给 `service.ask_json`；`service` 按配置选出 `Provider` 调用。新增一个模型厂商 = 写一个 `Provider` 子类并 `@register("类型名")`，配置里写 `type = "类型名"`。
- **按任务路由**：`[tasks.lookup]` 这样的段落可以给某个任务单独指定提供方、模型、effort、max_tokens（比如查词用更便宜的模型，出题用更强的模型）。
- 所有调用在服务器端，查词、句子讲解按输入做缓存（同一个词在同一句里只查一次）。
- **题库沉淀**（`app/bank.py`）：AI 现场生成的东西全部存下来，以后先用库里的，不够才生成。
  - 题目存 `items`，用 `item_kps` 挂到一个或几个知识点上。同一概念在别的教材里、语言相同的知识点的题也能用。每道题记下语言、年级、出题目的、生成记录（模型和提示词版本，见 `tasks.PROMPT_VERSION`）、做题统计（次数、正确、还不会、用时），内容相同的题只存一份（`qhash`）。
  - 分步讲解、背景和用处、阅读短文存 `contents`（kind = teach / context / passage）。和孩子个人有关的部分不存，比如讲解前面的「你在数学里学过……」来自人工写的关联说明，用的时候再拼。阅读短文按语言、年级、话题复用，同一个孩子不会读到重复的。
  - 孩子和家长可以标记「这道题有问题」（`flags`）。标记的人自己不再看到这道题；家长标记一次，或两个不同的孩子标记，就暂停使用，管理员在后台「题库」页恢复或下架。后台也能看各教材的覆盖情况、正确率最低的题，并导出整个题库（不含作答记录和试卷原题）。
  - 试卷导入的原题只给这个孩子自己用。题目要求「答案正确且唯一」，人工核对过的题标为 seed。
- 每个孩子每天调用上限 `daily_limit_per_kid`。
- 题目和讲解用什么语言、要注意什么，按教材包的 `teach_lang` / `item_lang` / `prompt_note` 生成（国际学校的学科：题干英文 + 中文翻译，讲解用中文并标出英文术语）。出题格式里的题型来自题型注册表。
- Claude 默认启用服务端 fallback（`server_fallback = true`），模型过载时自动切换备用模型。
- `install.sh check --llm` 会真实调用一次，确认密钥和网络都通。

## 7. 数据表

`users`（家长/孩子；`settings.method` 是学习方式）· `enrollments`（孩子选的教材包和当前学段）· `events`（学习事件：所有学习证据，掌握度按它重放）· `mastery`（掌握度，带模型指纹）· `items` / `item_kps`（题库和题目考的知识点）· `contents`（讲解、背景、短文）· `flags`（标记有问题）· `attempts`（每次作答）· `cards`（复习卡片：生词/错题/术语/总结）· `diag_sessions`（诊断过程和结果）· `days`（每日计划、分钟数、打卡、反思）· `readings` · `lookups`（查词记录）· `tracks`（阅读/新词进度）· `reading_logs` · `kp_taught`（学校学过的知识点）· `papers` / `paper_items`（试卷）· `api_tokens`（插件连接码）· 乐园：`arena_ability` / `arena_calib` / `arena_matches` / `arena_answers` / `arena_ledger`· `ask_threads` / `ask_messages`（问小艾）· `sentences`（造句与点评）· `llm_cache` · `llm_usage` · 账号：`sessions` · `invites` · `password_resets` · `auth_events` · 迁移记录：`schema_migrations`。完整定义见 `migrations/`。

## 8. 后续路线

1. **作业拍照**：和试卷一样，但只挑错题。
2. **听说**：英文朗读（TTS）、跟读录音、听写。
3. **按课本单元走**：给知识点补全 `unit`，进度页按单元勾选更快。
4. **家长周报**：每周自动汇总发到邮箱或微信。
5. **奖励机制**：连续打卡、完成计划兑换积分。
6. **更多教材包**：人教版数学、新概念英语、IGCSE 数学/化学、A-Level 等，按第 4 节格式添加即可。
