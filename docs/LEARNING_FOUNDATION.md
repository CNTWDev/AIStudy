# 共通知识与个体学习（2026-10）

保持单体部署与现有关系数据库。Web、领域命令、教材数据和独立 worker 分开；无需微服务或消息中间件。

## 模型边界

- **概念**：`curricula/_links/` 的稳定 ID 表示经核对的等价知识。相关、前置、语言联系不是等价，不能共享掌握结论。暂未映射的点用 `kp:<id>` 隔离，不凭名称自动合并。
- **教材知识点**：保留原有 pack/KP ID，承载教学语境、难度、学段与前置；已有题目、选课和历史记录继续有效。
- **版本、册次与单元**：`curricula/_meta/textbooks.json` 定义 edition → book → unit/KP 显式映射，记录地区、学制、版本、来源、核实状态。旧教材标为 legacy，未核实版本不关联上线包；映射优先于旧章节推断。
- **个人证据**：`events` 是原始学习记录；`mastery` 是教材语境状态；`concept_mastery` 是共通知识投影。模型指纹和概念映射指纹变化时从历史重算。新事件冻结题目统计、猜测率和迁移先验，避免未来题库变化悄悄改变过去结论；旧记录缺少的统计只能兼容回退。

新教材的增加不要求复制孩子的掌握记录。已练过的同概念为新语境提供最高 0.65 的初始估计；新语境仍需实际作答。推断不会成为共通知识的掌握证据。共通知识反映相同概念，不保证不同语言、题型和复杂度的表现相同。

## 动态学习闭环

作答 → 更新证据 → 估计当前掌握和保持率 → 安排间隔回忆/换题验证/补前置 → 再作答。计划按概念去重，避免同一天把多个版本的同一内容重复塞给孩子；优先保留一项复查任务。仍保留学校进度、每日时长和课程目标。

掌握判定同时要求概率、不同日期、不同题目和题型证据。卡片和开放题自评权重最多 0.3，不能提供独立掌握证明；零权证据不改变记忆或掌握。答错、还不会和间隔成功回忆会影响后续间隔。

记忆模型是 **FSRS/DSR 思路的简化启发式**，不是完整 FSRS，也没有经过该孩子数据拟合。默认目标保持率 0.85，间隔上限 180 天，可按学习方式配置。没有宣称存在适合所有儿童、所有任务的“最佳曲线”。先提供可解释、可重算的保守规则，未来有足够历史后再做校准和离线评估。

研究背景：[间隔与提取练习](https://www.learningscientists.org/faq)、[FSRS 算法说明](https://github.com/open-spaced-repetition/fsrs4anki/wiki/The-Algorithm)。系统中的参数是工程默认值，不是这些资料给出的儿童个体最优参数。

## 一致性与模型边界

`learning.submit` 是练习作答命令；路由只负责请求/身份。作答、题库统计、事件、掌握、卡片和提交回执共用事务；PostgreSQL 按孩子锁定用户行，SQLite 写事务使用 BEGIN IMMEDIATE。相关诊断、错题、试卷、追根、游戏和冲刺命令也加事务边界。嵌套调用共用连接与 savepoint。

新客户端为每道题带 `request_id`；同一 ID 与同一内容重复提交返回原结果，不重复记账；同 ID 改答案返回 409。旧客户端仍可提交，因此旧客户端未提供 ID 的练习不保证去重。错题等原有流程沿用自身状态校验。不是分布式 exactly-once 协议。

AI 每日限额用数据库条件 upsert 原子领取；失败请求也消耗次数。任务契约在缓存前校验，坏题不会进入共享缓存。`llm_calls` 记录任务、模型、耗时、成败及提供方实际返回的 token；未返回的 token 保留未知，不编造价格或费用。日志不存提示词、孩子原文或密钥。部分非出题任务目前只有顶层契约，仍需要原有业务校验和人工题库核对。

## 代码与运维

`app/main.py` 负责组装；`app/routes/` 按账号、家庭、学习、阅读、记录、试卷、乐园、管理分组；`app/web.py` 共享渲染和 Web 辅助函数。领域模块保留现有职责，避免为拆文件引入一套框架。

`python -m app.worker` 独立运行题库维护和每日新闻；`--once` 跑一轮。Web 不再自动启动维护循环。数据库租约带 owner 和心跳续期，旧进程不能释放新持有者的锁；AI 调用前后检查租约，避免丢锁后继续接收生成结果。外部 API 无法取消的请求仍可能消耗费用，进程崩溃后由租约过期恢复。

管理后台增加“教材核实与覆盖”和“任务与 AI 运行”：分别看来源/缺口，以及租约、最近结果、连续失败和 AI 汇总。`python -m app.cli curricula-report` 导出机器可读的库存。
